# 主界面玩家外观同步失败报告

## 1. 问题目标

尝试让游戏主界面的玩家展示区域同步显示：

- 当前激活的战车皮肤；
- 当前选择的浮游战机尾焰颜色（`subCar_blue`、`subCar_red`、`subCar_yellow`）。

原版 11.3 的主界面展示逻辑存在以下限制：

- 浮游战机展示被固定为 `subCar_blue`；
- 战车展示只读取装备战车的 `baseLabel`，不读取 `CarItemsDataGroup.getActiveSkin()`；
- 实际战斗场景会读取上述外观状态，因此主界面与战斗画面可能不一致。

## 2. 本次修改内容

本次曾修改以下文件：

- `decompiled/gamefile/scripts/UI/top/HighPlayerBox.as`
- `decompiled/gamefile/scripts/gameAll/data/GameData.as`
- `decompiled/gamefile/scripts/gameAll/high/HighDps_ExtraData.as`

具体尝试如下：

1. 在 `HighDps_ExtraData` 中增加 `carImgLabel` 和 `subCarLabel` 字段。
2. 在 `GameData.getHighDps_ExtraData()` 中读取当前激活皮肤和浮游战机颜色，并传给主界面展示数据。
3. 修改 `HighPlayerBox`：
   - 优先使用传入的战车皮肤资源标签；
   - 使用传入的 `subCarLabel` 创建浮游战机；
   - 后续又增加了资源为空时回退基础战车或 `subCar_blue` 的保护。

## 3. 故障表现

修改后出现严重回归：

- 主界面中央的战车不再显示；
- 浮游战机不再显示；
- 后续测试中，左侧原有的返回主菜单按钮也不再显示；
- 主界面其他 UI 仍能显示，说明并非整个主界面 SWF 完全加载失败。

增加资源回退保护后，故障仍未解决。

## 4. 可能原因

以下均为尚未完全验证的可能原因：

### 4.1 主界面资源标签与战斗对象标签并不等价

战斗场景通过已经初始化的 `HeroCarBody.img.car` 和 `MoreImage` 结构切换 `imgLabel`。主界面的 `HighPlayerBox` 则直接调用：

```as
Game.swfLoaderManager.getResource("car", label)
```

因此，战斗代码中可用于 `showMC()` 的标签，不一定能直接作为 `getResource()` 的导出类名使用。

### 4.2 皮肤并非独立的主界面导出类

`getActiveSkin().getDefine().imgLabel` 可能只是战车 MovieClip 内部状态名称，而不是 `car1130.swf` ApplicationDomain 中可直接实例化的类。若把它传给 `getResource()`，可能返回 `null`。

### 4.3 `HighPlayerBox` 的数据对象兼容性被破坏

`HighPlayerBox.flesh_byData()` 同时处理本地玩家数据、竞技场数据和排行榜数据。给 `HighDps_ExtraData` 增加字段，或改变其数据读取方式，可能影响旧对象、动态对象或反序列化数据的兼容性。

### 4.4 主界面刷新调用发生在展示对象状态不完整时

购买和换装流程会调用 `Game.uiGroup.carShow.copyAll()`。该调用还会触发 `AllBack.fleshData()` 和 `HighPlayerBox.flesh_byGameData()`。如果调用时战车、皮肤资源或副武器资源尚未完成初始化，可能中断主界面局部刷新。

### 4.5 ActionScript 运行时异常中断了后续 UI 更新

最初版本中，资源加载返回 `null` 后仍会调用 `stop()`、`getPoint()` 或读取挂点，这可能抛出异常。虽然之后增加了空值回退，但按钮同时消失说明仍可能存在更上层的运行时异常或显示列表更新中断。

### 4.6 构建后的脚本导入可能存在非预期影响

项目通过 FFDec 将显式 ActionScript 补丁重新导入基线 SWF。代码能够成功构建不代表运行时显示列表、动态类字段和原 SWF 时间轴一定完全兼容。需要结合 Flash 运行时 trace/error 输出进一步验证。

## 5. 当前处理状态

由于故障影响主界面核心展示和导航，本次主界面外观同步修改已经全部撤销。

已恢复的文件：

- `HighPlayerBox.as` 已恢复到修改前逻辑；
- `HighDps_ExtraData.as` 已恢复到修改前逻辑；
- `GameData.getHighDps_ExtraData()` 中新增的外观字段已删除。

重新构建后的 `build/game.swf` SHA-256 为：

```text
69f48d059f001b33f2c347d8e4f76bc90db41a9c9970f0276482b37f8784ffd7
```

该哈希与“完成三种浮游战机商店商品修改、尚未修改主界面展示”时的构建结果一致。

商店中的蓝尾、红尾、金尾浮游战机及其 `1 G币` 价格修改仍然保留。

## 6. 尚未解决的问题

当前仍未实现：

- 主界面同步显示当前激活的战车皮肤；
- 主界面同步显示当前选择的浮游战机颜色。

该问题不能继续通过简单地向 `HighPlayerBox.getResource()` 传入战斗场景的 `imgLabel` 解决。

## 7. 后续调查建议

1. 开启 Flash Debug Player 或读取现有 trace/error 日志，取得首次运行时异常及调用栈。
2. 检查 `car1130.swf` 中皮肤究竟是独立 SymbolClass，还是基础战车 MovieClip 内部的状态标签。
3. 直接分析主界面原始展示对象的时间轴、挂点和资源实例化方式。
4. 优先考虑复制实际战斗对象生成位图，避免在 `HighPlayerBox` 中重新拼装皮肤资源。
5. 先制作仅同步 `subCarLabel` 的最小实验版本，确认浮游战机独立刷新无误后，再单独处理战车皮肤。
6. 每次只修改一条显示链路，并保留可快速回退的构建产物和运行截图。

## 8. 结论

本次修改确认了原版 11.3 主界面没有完整接入玩家外观状态，但所采用的“向 `HighPlayerBox` 传递皮肤和浮游战机资源标签”方案导致了主界面显示回归。

修改已撤销，游戏恢复到主界面展示修改前的构建状态。该外观同步缺陷目前仍未解决，后续需要从 SWF 导出类、MovieClip 内部状态以及 Flash 运行时异常三个方向继续调查。
