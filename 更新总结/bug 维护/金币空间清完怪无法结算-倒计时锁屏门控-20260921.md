# 金币空间"清完怪无法结算"（倒计时被场景锁门控）+ 非敌人掉落金币禁自动收取 · 排查与修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待实机确认**
> 现象（用户报告，端游玩家先报、手游实测同症状）：**金币空间**（关卡 `4-1-5`）把场上敌人**全部清完**后仍然**无法结算**，卡在关卡里。
> 归属：原版设计缺陷（两端同源逐行相同）；本次**手游与端游同时修复**（端游见 `metalwartale3-reborn.git\更新总结\bug 维护\3.0前瞻版本bug维护\` 同名记录）。
> 追加需求（用户 2026-09-21）：**本关"非敌人掉落"的金币不得被磁吸自动收取**（否则破坏该模式玩法）——已一并实施。

## 一、元素与数据链

| 层级 | 标识 |
|---|---|
| 关卡 | `4-1-5` **金币空间**，`specialClass = gameAll.level.extra.SpecialExtraLevel_6`，场景 `mothership_know`，出生点 2500,400 / 终点 4300,400 |
| 敌人 | 4 种 × 30 = 120 只（狂热者/圣堂战机/小型压路机/猎隼战机），生成窗口 `timeRange 0,1600`（远超关卡时长），无 portal/boss |

## 二、根因（行号=改前）

**倒计时被"场景锁 `oneSence.lockB`"门控，而清完怪恰好会解锁场景：**

1. `SpecialExtraLevel_6.as:99-113` `timeTimer()`：
   `if(now_t < 0){ now_t = 0; this.fail(); }` **`else { oneSence = Game.oneScene; if(oneSence.lockB){ now_t -= 1 / 6; } }`** ← 门控在此
2. 父类 `Level_2_5.as:40-56` 的同名方法：`else { now_t -= 1 / 6; }` —— **无条件倒计时**（说明 6 号关的门控是它自己多加的）
3. 同族对照 `SpecialExtraLevel_7.as:96-112`：用自己的 `holdB` 门控，并把 `unlockView()` **覆写成空方法**（禁止解锁）→ 7 号关不会卡
4. 解锁触发 `Levels.as:190-212` `fleshEventOrder()`：所有发兵命令 `enabled==false` 且 `!BG.getLiveEnemyB2()`（场上无活敌）→ `enemyOverB = true; this.unlockView(); this.enemyOverEvent("")`
5. `Levels.as:351` `unlockView()` → `Game.oneScene.unLockView()` → `OneSence.as:490-492` **`lockB = false`**
6. `Levels.enemyOverEvent()`（`Levels.as:237`）与 `Level_0.enemyOverEvent()`（`Level_0.as:476`）**都是空实现** —— 全项目没有任何关卡靠"清怪"结算

**死局链**：清光敌人 + 发兵命令耗尽 → `lockB = false` → 倒计时永久停摆 → `now_t` 永远到不了 0 → `fail()`（"通关"）永不触发 → **无法结算**；且不会再刷新敌人来重新锁屏，所以不可恢复。

**为什么平时看不出**：场上有敌人、或后续发兵会重新锁屏时，倒计时照走；只有"清空且发兵耗尽"才暴露——与玩家描述完全一致。

**附带影响**：金币球生成也挂在 `oneSence.lockB`（`lifeBallTimer:59-63`）→ 清完怪后**金币也停刷**，关卡成"没怪、没钱、不结算"的死场。另因倒计时只在锁屏期间走，该关实际耗时**长于 3 分钟**。

## 三、修复方案与决策点

| # | 改动 | 说明 |
|---|---|---|
| E1 | **去掉 `timeTimer()` 的 `oneSence.lockB` 门控**（改为无条件 `now_t -= 1 / 6;`），并删除随之无用的局部量 `var oneSence:OneSence = null;` | 恢复与父类一致的行为，兑现关卡自述的"坚持 03:00 通关"；清完怪也会按时结算 |
| E2 | `ItemsBody` 新增字段 `magnetForbidB:Boolean = false`（自动收取黑名单标记） | 与既有 `magnetB`/`hitB`/`hitFloorDisappearB` 命名风格一致 |
| E3 | `ItemsGroup.canAutoCollect()` 顶部加入黑名单判定 `if(items0.magnetForbidB) return false;` | 磁吸/自动收取的总闸门（`itemsGroupTimer → canAutoCollect → attractToHero`） |
| E4 | `SpecialExtraLevel_6.lifeBallTimer()` 中，本关自己刷出的金币球标记 `items0.magnetForbidB = true;` | **全项目唯一的"非敌人掉落金币"来源**；敌人死亡掉落走 `addAddBall2`（`b0` 为敌人本体），不受影响 |

**刻意保留（用户裁定）**：
- `lifeBallTimer` 的金币生成门控（`if(oneSence.lockB)`）**不动**——金币只在交战期间刷新（原有玩法节奏）；
- `modPurchaseIgnoreConditions` 等修改器语义不动；
- 不改用"清完怪即结算"的写法（那会与关卡文案和金币玩法冲突）。
