# 关卡星级"未通关也常亮" · 排查与修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待实机确认**
> 现象（用户报告）：关卡选择界面每关左上角的星星，手游**任何情况都显示为亮金色**；原版/端游里未通关应显示银灰色。
> 因低难度通关后高难度关卡自动解锁，解锁后几乎全部常亮，玩家无法分辨哪些关已通关。锁定态本身正常（有锁图标）。
> 归属：**F-8「gpu 模式运行时着色全量清扫」的同族残留**（第五刀甄别遗漏的第六处症状）。

## 二、根因

DefineSprite 1073 **帧1** 放置 characterId 1072 时挂 `surfaceFilterList`：

1. `GLOWFILTER` blur 3.0 / passes 1 / glowColor RGBA(**51,0,0**)
2. `GLOWFILTER` blur 8.0 / passes 3 / glowColor RGBA(**255,204,0**)
3. **`COLORMATRIXFILTER`** — 矩阵 `0.3086, 0.6094, 0.082, 0, 0`（三行），末行 `0,0,0,1,0`
   = **标准亮度灰化矩阵**（R×0.3086 + G×0.6094 + B×0.082，行和=1）

即"银灰星"= **金色位图底稿 + 放置级灰度滤镜**，并非另一张灰色素材。帧2 为同深度 `placeFlagMove=true` 的
**纯 MOVE**（只替换滤镜列表，去掉灰度矩阵）→ 恢复金色。

手游 `application.xml` 固化了 `renderMode=gpu`（F-4 真机 A/B 裁定），**AIR 的 GLES 路径忽略 symbol 时间轴
放置级滤镜** → 帧1 的灰度矩阵被静默丢弃 → 只剩金色底稿与金色辉光 → **永远常亮**。与 F-8 五刀同源
（第四刀礼包横幅 `noBuy_btn` 为同款放置级亮度矩阵）。

**旁证**：`metalwartale3-reborn.git\swf\ui1120.swf`（端游现行）与手游 F-8 之前的原件
**SHA-256 逐字节相同**（`0a33f2b2c9c0b558a366580231822f7a2655b5c082cd8281e1164110eff68106`）
→ 不是素材分叉，纯粹是渲染路径差异（端游 Flash Player 应用滤镜，手游 gpu 丢弃）。

## 三、修复方案与决策点

照 F-8 第三刀（研发灰卡，位图挂亮度矩阵）**同款烘焙流水线**，并保持桌面渲染等价：

1. 克隆位图 **1070 → 2300**：按同一亮度矩阵**逐像素灰化**（保持 alpha；矩阵行和=1 故按通道线性变换）；
2. 克隆 shape **1071 → 2301**：shapeId 改号 + `bitmapId` 指 2300（**克隆闭包必须纳入位图引用**——第二刀踩坑红线）；
3. 克隆 sprite **1072 → 2302**：内部放置改指 2301；
4. **帧1** 放置改指 2302，并从 `surfaceFilterList` 中**删除 COLORMATRIXFILTER**（两层辉光保留），
   同时把两层辉光色按同一矩阵**同步灰化**（51→16、255/204→203）；
   灰化是线性且保 alpha 的运算，与 alpha 合成可交换 → 与"对合成结果套矩阵"**等价**，故桌面观感不变；
5. **帧2** 必须一并改写：原为纯 MOVE（同深度只换滤镜、不换角色），帧1 改指灰色克隆后 MOVE 会让
   depth1 上仍是灰星 → 通关态错显灰。按引擎红线改为
   **`RemoveObject2 depth=1` + `PlaceObject3 characterId=1072`（金色原件）** 的 RO+放置写法
   （同深度**替换 replace 静默不渲染**，必须 RO 在前、放置在后；帧2 新放置由帧1 原标签派生，滤镜保持金色原值）。

三个克隆均无 SymbolClass 类绑定（已核），故无需补绑定条目。

### 顺带修复：出包脚本自动清旧误删本次校验件

`build-apk.ps1` 的"归集目录只留最新"清理条件为
`$_.FullName -ne $finalPath -and ($_.Extension -eq '.apk' -or $_.Name -like '*.apk.sha256.txt')`——
只排除了本次 apk 本身，**未排除本次刚生成的 `.sha256.txt`**（其 Name 同样匹配 `*.apk.sha256.txt`），
故每轮出包都会把校验件立刻删掉（本次实测：测试目录只剩 apk、无 `.sha256.txt`）。
修法：同时排除 `$finalPath + '.sha256.txt'`。本次已按手游侧既有格式补写校验件
（大写哈希 + 两空格 + 文件名 + CRLF，无 BOM，与冷备 3.0.3 件一致），PowerShell `Get-FileHash` 复核一致。

**未改 `decompiled` 源码、未改补丁清单**——本次为纯资源（SWF 二进制）改动，不涉及 AS 补丁两步走。
