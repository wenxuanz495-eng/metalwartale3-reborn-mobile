# BGM 场景切换时共享曲目不切回主界面歌单 · 排查与修复记录

> 记录日期：2026-09-15
> 状态：**已实施修复，待实机确认**
> 现象（用户报告）：进入战斗瞬间切到战斗歌单正常；从战斗退出关卡回到主界面时，有概率部分歌曲不切回主界面歌单。已确认必现曲目：`动漫向 | fripSide - only my railgun`（从进战斗到退出始终不切回）。用户疑问：是战斗歌单和主界面歌单都有这首歌导致，还是子文件夹结构问题？

---

## 一、复现链（代码级推演）

1. **进入关卡**：`Game.startLevel()`（`Game.as:985` 置 `gameState="gaming"`）→ `Levels.as:85-86` 播放关卡音乐 → `OneMusic.play`（`OneMusic.as:17`）→ `SoundGroup.playExternalMusic` → `playRecommendedPlaylist()`：`context="battle"`，发 `/api/bgm/playlist/start`（**不带 force**）。
2. **退出关卡回主界面**：`Game.closeLevel()`（`Game.as:1031` 置 `gameState="no"`）→ `eventGroup.gamingOver()`（`EventGroup.as:847`）重新播放主界面音乐 Decisions → 同一链路 `context="main"`，再发 `/api/bgm/playlist/start`（**不带 force**）。该链路每次退关必经，无漏发分支。
3. **服务端保留当前曲目**：`bgm_player.startPlaylist`（`bgm_player.go:589-600`）在 `!forceSwitch` 且当前曲目 ID 存在于新歌单且正在播放时，只把 `playlistIndex` 对齐到新歌单中的位置并 `return`，**保留当前曲目继续播放、不重启**。

## 二、根因结论

**是"战斗歌单与主界面歌单都有这首歌"导致的**，与子文件夹结构无关（`group` 分组字段仅用于 UI 显示，曲目按文件唯一 ID 索引）。这是此前刻意设计的"场景切换不重启目标歌单中仍存在的曲目"（原 `SoundGroup.as` 注释 `Scene changes must not restart a player track that is still present in the destination playlist`），本意是避免同一首歌跨场景被从头重放；副作用：退出战斗时若正在播共享曲目，该曲会续播到自然结束才回到主界面歌单顺序，玩家感知为"没切回歌单"。

**曲库证据**（`相关素材\歌单\曲库\developer-playlists.json`）：`fripSide - only my railgun` 的 `context="both"`、`default_main` 与 `default_battle` 同时为 true（主界面第 7 位、战斗第 3 位），两个歌单引用**同一曲目 ID** `ded7236ba211db79`。双挂曲目共 4 首：railgun、`DizzyAnchovy - The Rebel Path`、`王朝1982 - 成仙`、`程渤智 - 西安乱弹`。战斗歌单为随机模式，退出时正在播这 4 首之一即触发——"有概率"的来源；railgun 战斗顺位第 3，命中频率最高，故被确认为"必现"。

## 三、修复方案与决策点

用户拍板（2026-09-15）：**场景切换立即切歌**——主界面 ↔ 战斗上下文变化时立即强制切到目标歌单，即使当前曲目在目标歌单中也存在。

- 同一场景内的歌单编辑（`syncCurrentRecommendedPlaylist()`）保持既有恒 `force=1` 语义不变；
- 非上下文切换的启动（首次激活、同场景重入）保持不重启语义不变；
- 服务端不改（`force` 语义已存在）。

实现：`playRecommendedPlaylist()` 新增 `forceSwitch = context != activeRecommendedPlaylistContext` 判定，为 true 时 `playlist/start` 追加 `&force=1`。

## 七、追加特例：同歌单双场景续播（2026-09-15 第二轮，已实施）

用户提出特例：**同一张歌单同时勾选「主界面使用」与「战斗使用」**时，场景切换不应打断——当前曲目按顺序播到结束，然后接本歌单的下一首；同时勾选分配必须与场景严格对应。

### 结构核查结论

- 勾选与场景的对应已由结构保证：勾选框状态直接按 `mainPlaylistID` / `battlePlaylistID` 与编辑中歌单 ID 比对渲染（`AllBack.refreshPlaylistUseChecks`），勾选即分配，无第二份状态可漂移；`assignNamedPlaylist` 忽略失效 ID，`resolveNamedPlaylists` 对存量失效 ID 回退到第一张歌单；
- 双勾后 `mainPlaylistID == battlePlaylistID`，`resolveNamedPlaylists` 把同一份曲目+模式同时充作两个场景的歌单；服务端不带 force 的 `startPlaylist` 本就"保留当前曲目 + 对齐索引 + 更新上下文标记"，播完由 `monitorPlaylist` 按该单模式接下一首——特例行为服务端现成支持，零改动。

### 方案细化（用户拍板：按方案实施）

第一轮的 `forceSwitch = context != activeRecommendedPlaylistContext`（切场景就强制）细化为：

```actionscript
var forceSwitch:Boolean = playlistID != this.activeRecommendedPlaylistID;
```

语义从"切场景就强制"变为"**换了歌单才强制**"：各配各的歌单时切场景仍立即切歌（第一轮修复保持）；同歌单双勾时切场景不打断，播完接本单下一首；首次激活（活动 ID 为空）仍正常起播。
