# VIP 折扣价格显示反了（武器"原价"显示 0）· 端游同步修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待验证**（PC 本机可验：VIP 存档进商店即可看到）
> 现象（用户报告）：玩家获得 VIP 后商店出现折扣显示，但**武器的"原价"显示为 0**，实际（折后）价格是较高数值——看起来像"打折把价格打高了"。
> 归属：**原版缺陷**；本次**与手游同时修复**（`GoodsDefineGroup.as` 两端内容完全一致，1409 行 0 差异，同一套改动文本）。手游侧全周期记录见手游仓 `更新总结\bug 维护\VIP折扣价格显示-武器原价显示0-20260921.md`。

## 一、显示链

| 层级 | 标识 |
|---|---|
| 商品对象 | `GoodsDefineGroup.switchArms/switchCar/switchItems` 维持不变量 `d1.priceLevel = d0.Mprice`（未折扣原价） |
| 价格显示 | `UI/shop/ShopIcon.as:254 fleshPrice_byNow()`：`price_txt` 先填折后价（`fleshPrice_inData` 已按 `vipData.discount` 打折），随后在 M 币分支把 **`itemsData.priceLevel` 当"原价"** 追加显示（`:376`） |
| 实扣价 | `OneShopUI.yesBuy()` 用折后 `d0.Mprice` 扣费（VIP 折扣照常生效，**扣费无 bug**） |

## 二、根因：定制价/补漏价路径覆盖 `Mprice` 却未同步 `priceLevel`

`GoodsDefineGroup` 中 6 处覆盖点（行号=改前）：

| # | 位置 | 覆盖值 |
|---|---|---|
| VIP1/VIP2 | `addCustomGoods()` 定制主/副武器（`discount == -1000`） | 4000~9000 |
| VIP3 | 同上的战车（`getCarDisplayLevel > 7`） | 1000~2000 |
| VIP4 | `addLegacyArmsGoods()` 补漏武器 | 600 |
| VIP5 | `addLegacyCarGoods()` 补漏战车 | 1200 |
| VIP6 | `addSpecialMCoinCars()` 特殊 M 币车 | 50/50/50/150（另显式 `discount = 0`） |

**数据证据**：星座系列补漏武器（`conAries_lv1` 白羊座 / `conVirgo_lv1` 处女座 / `conTaurus_lv1` 金牛座 …）在 `2_EmbedXml_xmlClass3` 中**无 `<Mprice>`、无 `<priceLevel>`、无 `<discount>`** → `switchArms` 后 `Mprice = 0`/`priceLevel = 0`；补漏路径把 `Mprice` 覆盖为 600 而 `priceLevel` 仍为 0；`discount` 缺省 = `Number("")` = 0 → `ShopIcon` 里 `discount = 1-(1-0)*vip > 0` → **进入折扣显示分支** → 界面显示"现价 540 / 原价 0" → **"打折反而把价格打高了"** ✓

（对比：`discount == -1000` 的定制价武器走 `setSpecialState("show")` 不显示"原价"，那一支不暴露；但同属不变量破坏，一并修。）

## 三、修复方案

6 处覆盖点后各补 `goods0.priceLevel = goods0.Mprice;`，恢复"`priceLevel` = 未折扣 Mprice"不变量。
