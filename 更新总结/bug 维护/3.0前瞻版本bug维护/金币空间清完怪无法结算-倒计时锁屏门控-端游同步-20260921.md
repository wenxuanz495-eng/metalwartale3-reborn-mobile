# 金币空间"清完怪无法结算"（倒计时被场景锁门控）· 端游同步修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待验证**（端游为 PC 本机形态，可直接进关验证）
> 现象（用户报告，端游玩家先报、手游实测同症状）：**金币空间**（关卡 `4-1-5`）把场上敌人**全部清完**后仍然**无法结算**，卡在关卡里。
> 归属：原版设计缺陷。本次**与手游同时修复**（手游侧全周期记录见手游仓 `更新总结\bug 维护\金币空间清完怪无法结算-倒计时锁屏门控-20260921.md`；三个源文件两端**内容级 0 差异**，故改动文本完全相同）。
> 追加需求（用户 2026-09-21）：**本关"非敌人掉落"的金币不得被磁吸自动收取**——已一并实施（两端同款机制：`ItemsGroup.canAutoCollect → attractToHero`）。

## 一、元素与数据链

| 层级 | 标识 |
|---|---|
| 关卡 | `4-1-5` **金币空间**，`specialClass = gameAll.level.extra.SpecialExtraLevel_6`，场景 `mothership_know`，出生点 2500,400 / 终点 4300,400 |
| 敌人 | 4 种 × 30 = 120 只（狂热者/圣堂战机/小型压路机/猎隼战机），生成窗口 `timeRange 0,1600`，无 portal/boss |
| 结算入口 | 关卡内**只有倒计时**这一个自动结算入口：`now_t = 3 * 60`，`getTimeLimitText() = "坚持 03:00 通关"`，`failText = "通关"`（`now_t < 0` → `fail()`，本关把"失败"复用为"通关"结算） |

## 二、根因（行号=改前，两端一致）

1. `SpecialExtraLevel_6.as:99-113` `timeTimer()`：`else { oneSence = Game.oneScene; if(oneSence.lockB){ now_t -= 1 / 6; } }` ← **倒计时被场景锁门控**
2. 父类 `Level_2_5.as:40-56`：`else { now_t -= 1 / 6; }` —— **无条件倒计时**
3. 同族 `SpecialExtraLevel_7.as:96-112`：用自有 `holdB` 门控，且 `unlockView()` 覆写为空 → 不卡
4. `Levels.as:190-212` `fleshEventOrder()`：发兵命令耗尽 + 场上无活敌 → `unlockView()` → **`lockB = false`**（`OneSence.as:490-492`）
5. `Levels.enemyOverEvent()` / `Level_0.enemyOverEvent()` **均为空实现** → 全项目没有"清怪即结算"的关卡

**死局链**：清光敌人 + 发兵耗尽 → `lockB=false` → 倒计时永久停摆 → `now_t` 永不 <0 → `fail()`（"通关"）永不触发 → **无法结算**（且不会再有敌人来重新锁屏）。

**附带影响**：金币球生成同挂 `lockB`（`lifeBallTimer:59-63`）→ 清完怪后金币停刷，关卡成死场；另该关实际耗时**长于 3 分钟**（仅锁屏期间计时）。

## 三、修复方案（端游同步，4 处）

| # | 改动 |
|---|---|
| E1 | `timeTimer()` 去掉 `oneSence.lockB` 门控（改无条件 `now_t -= 1 / 6;`），删除无用局部量 `var oneSence:OneSence = null;` |
| E2 | `ItemsBody` 新增字段 `magnetForbidB:Boolean = false` |
| E3 | `ItemsGroup.canAutoCollect()` 顶部加 `if(items0.magnetForbidB) return false;` |
| E4 | `SpecialExtraLevel_6.lifeBallTimer()` 中本关刷出的金币球标记 `items0.magnetForbidB = true;`（全项目唯一的"非敌人掉落金币"来源；敌人死亡掉落走 `addAddBall2`，不受影响） |

**刻意保留**：`lifeBallTimer` 的 `lockB` 金币生成门控（用户裁定不动）；`exitEvent`（终点 4300）备选出口不动。
