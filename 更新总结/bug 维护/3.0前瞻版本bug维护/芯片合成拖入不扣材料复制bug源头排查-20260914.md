# 芯片合成"拖入不扣材料"无限复制 bug · 源头排查记录

> 记录日期：2026-09-14
> 状态：**已修复并实机验证通过，关闭**（2026-09-15 用户实机确认；方案见第六节，执行记录见第七节）
> 现象（用户报告）：从材料背包把芯片拖进芯片合成槽后，背包里的芯片不会少一个，可以通过"拖入→退回"循环无限复制芯片。

---

## 一、目标

只排查、不修改：找到芯片合成（ChipCubeUI）复制 bug 的代码源头，确认触发条件与完整复现链。

## 二、复现链（代码级推演）

**触发前提：修改器"免费制造"开启（`Game.gameData.modCraftFree == true`）。**
该标志由修改器 `modifier.html` 写入，并随存档持久化（`GameData.as:384` 读档恢复，`GameData.as:515` 读档后还会 `completeModCraftResearch()` 同步研发状态）。

1. **拖入（复制发生点）**：`ChipCubeUI.iconUp()` 背包→合成槽方向：
   - `ChipCubeUI.as:232`：`this.materialsItems.useItemsData(drag_d)` —— 本应从材料背包扣 1 个；
   - `GoodsItemsDataGroup.as:474-477`：`useItemsData()` 开头有豁免——`if(Game.gameData.modCraftFree && this == Game.gameData.materialsItems) return;` —— **免费制造开启时直接返回，背包不扣**；
   - `ChipCubeUI.as:233`：`this.chipItemsData.addItemsData(copy_d,1,false)` —— 无条件把副本加入合成槽。
   - 净效果：背包原芯片还在，槽里多出 1 个副本。
2. **退回（变现点）**：两条路都无条件把槽内芯片加回背包：
   - 拖回背包：`ChipCubeUI.bagBackUp()`（`ChipCubeUI.as:262-276`）`this.materialsItems.addItemsData(copy_d,1,false)`；
   - 关闭研究界面：`UIGroup.as:553` 调 `chipCubeUI.chipReturn()`（`ChipCubeUI.as:287-298`），把槽内所有芯片 `addItemsData` 回背包。
   - `GoodsItemsDataGroup.addItemsData()`（`GoodsItemsDataGroup.as:145-154`）对 `type == "chip"` 的物品**不走同名校融合并，每次都占新格**，所以副本以独立芯片实体落地。
3. **循环**：每轮"拖入→退回"净赚 1 个芯片，可无限重复。

**变体（合成变现）**：免费制造下拖 4 个同色芯片入槽（背包不扣）→ 点合成按钮（`btnClick`，`ChipCubeUI.as:311-325`，G币照扣，`addCoin` 无豁免）→ 槽清空、得 1 个高一级芯片，背包 4 个原芯片仍在。

## 三、根因结论

**免费制造豁免（本意：免除制造材料消耗）被芯片合成的"物品位置转移"路径继承**：进入合成槽时背包原件的移除被豁免跳过，而槽内副本照常生成、退回时照常落袋，豁免从"免成本"变成了"凭空复制"。

**为什么只有芯片合成有此问题**：2.1.6 公告的"印钞机"修复已把同类路径（洗炼槽、镶嵌槽）改为"费用豁免与位置转移分离"——`ChipBaptizeUI.as:208、229` 现用 `useItemsDataReal()`（`GoodsItemsDataGroup.as:494-505`，强制真实扣除 + 失败返回 false，调用侧带回滚）；芯片卸下复制也已单独修复（提交 `09bd37a`）。**`ChipCubeUI` 是当时漏掉的一处**，仍调用会被豁免的 `useItemsData()`。

## 七、详细修复方案（2026-09-14 设计，同日批准并实施）

**修复原则**（沿 2.1.6 印钞机修复既定原则）：费用豁免与物品位置转移分离——免费制造只豁免"制造消耗判定"，凡物品位置转移必须真实发生且原子（失败即整体不动、无复制无丢失）。实现完全镜像洗炼槽 `ChipBaptizeUI` 已验证范式。

**唯一改动文件**：`decompiled\gamefile\scripts\UI\research\ChipCubeUI.as`。不改 `GoodsItemsDataGroup`（`useItemsDataReal` 原语已存在）；不动配置与 SWF，无需三处同步和 manifest 更新。

### 改动 1｜iconUp 背包→槽·普通放入（现 230-235 行）
`this.materialsItems.useItemsData(drag_d)` 换为 `if(this.materialsItems.useItemsDataReal(drag_d))`，成功才 `chipItemsData.addItemsData(copy_d,1,false)` 并赋 `copy_d.site = iai.site`；失败整体不动（理论不触发的安全网）。

### 改动 2｜iconUp 背包→槽·目标位被占交换（现 235-240 行）
按洗炼槽次序重排：
1. `useItemsDataReal(drag_d)` 真实扣背包；
2. 占位芯片 `addItemsData(iai_d.copy(1))` 退回背包；若返回 null（背包满）→ `addItemsData(copy_d,1,false)` 把拖入芯片还原回背包后整体 return（放弃本次拖动，无复制无丢失）；
3. `chipItemsData.useItemsData(iai_d)` 移除槽内占位，`copy_d` 入槽并赋 `iai.site`。

### 改动 3｜iconUp 槽→背包（现 242-254 行，⚠️ 含第二个复制点）
现状两处问题：先删槽后进包（背包满则芯片蒸发）；占位换回背包用被豁免的 `materialsItems.useItemsData(iai_d)`（250 行——交换方向也能白复制一枚）。新次序：
1. `put = materialsItems.addItemsData(copy_d,1,false)` 先进背包；返回 null → tip「背包已满，无法取回芯片。」+ `failureItems` 音效，整体不动（芯片留在槽）；
2. 成功才 `chipItemsData.useItemsData(drag_d)` 删槽；
3. 背包目标格被占时：`useItemsDataReal(iai_d)` 真实移出占位 → `chipItemsData.addItemsData(iai_copy_d,1,false)`、`iai_copy_d.site = drag_d.site`；real 失败（理论不触发）则回滚 `delItemsData(put)`、占位不动。

### 改动 4｜bagBackUp 拖回背包背景（现 262-276 行）
同改动 3 前两步：先进包成功才删槽；失败 tip + 音效 + 芯片保留在槽。

### 改动 5｜chipReturn 关界面退回（现 287-298 行）
逐枚 `put = materialsItems.addItemsData(chip0,1,false)`，成功才从 `chipItemsData.arr` 移除该枚；失败保留槽内并一次性 tip「背包已满，剩余芯片保留在合成槽。」。遍历用副本数组避免迭代中修改。（满包遗留芯片若遇 `gameInit` 的 `newPlayerLogin` 清槽会丢失——该边界与洗炼槽现状完全一致，不在本次扩大范围。）

### 改动 6（建议项，可裁剪）｜btnClick 满包预检（现 311-325 行）
现状满包点合成会扣 G币、清 4 芯片、产物 `addItemsDefine` 返回 null 蒸发（原版既有缺陷，顺手补）。预检：产物芯片未命中自动出售规则（`!Game.gameData.shouldAutoSellChip(nextName)`，命中则自动转 G币不需格位）且 `materialsItems.arr.length >= materialsItems.bagMaxNum` 时 tip「背包已满」并 return，不扣不清。

### 决策点
- **D1**：免费制造下合成 G币是否也豁免？默认**维持照扣**（现状行为，超出本 bug 范围，不顺手动）。
- **D2**：改动 6 是否纳入？默认**纳入**；若要求最小 diff 可裁掉，不影响复制 bug 本身。

### 已核实的前置事实
- `chipItemsData` 为 `new GoodsItemsDataGroup()`，`bagMaxNum` 默认 36 ≥ 4，槽组侧 `addItemsData` 不会满（已核 `GoodsItemsDataGroup.as:12`）；
- `useItemsDataReal` 含 `indexOf` 与 `nowNum` 双校验，drag_d 必在背包数组中，失败分支仅作安全网；
- `addItemsData` 对 chip 不同名合并、每枚占新格（`GoodsItemsDataGroup.as:145-154`），交换/退回的 site 语义与原版一致；
- `addItemsDefine` 内含自动出售芯片转 G币分支（`GoodsItemsDataGroup.as:129-133`），改动 6 预检需排除该情形。
