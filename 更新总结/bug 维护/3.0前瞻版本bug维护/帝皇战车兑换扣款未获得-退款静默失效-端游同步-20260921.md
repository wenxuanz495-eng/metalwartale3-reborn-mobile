# 帝皇战车兑换"扣款成功、退款落空"（端游同步） · 排查与修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待验证**（PC 本机可验；端游为 PC 单机形态，验证成本低于真机）
> 现象（用户报告，手游侧先发现）：帝皇战车需集齐地虎/风鹰/黑犀/雪獒/炎龙 5 辆铠甲战车才能兑换；玩家"误触"后**荣誉勋章消失、帝皇战车没拿到**，界面只弹"该物品需要集齐…5辆战车才能兑换!"，玩家以为没扣钱。
> 归属：**原版/两端共有的历史缺陷**。本记录为**手游侧 2026-09-21 修复后的端游同步**（手游侧全周期记录见手游仓 `更新总结\bug 维护\帝皇战车兑换扣款未获得-退款静默失效-20260921.md`）。
> 端游与手游差异（内容级 diff 已核）：**端游无 `modPurchaseIgnoreConditions` 守卫**（扣款与退款无条件执行），其余同构。

## 二、根因（两段叠加，行号=改前）

**（1）扣款在前、前置校验在后** —— `UI/shop/OneExchangeUI.as`

- `onBuyClick()`（`:388`）**先扣款**：`switch(ed.EPayType)`（`:413`）中 `:427` 扣 `justice_badge` 150 枚；
- **之后**才校验前置：`:445` `if(gd.name == "帝皇战车" && !this.CheckCarHas("dihuang"))` → 未集齐 5 辆走失败分支；
- 失败分支（`:447-455`）弹提示、`_tempDT.flag = 0`，然后"退款" `:451 this.GD.propsItems.useItemsNum("justice_badge",-ed.EPayCount)`，`return`。

**（2）退款在"余额刚好花光"时静默失效** —— `gameAll/data/GoodsItemsDataGroup.as`（端游同构）

- 扣款侧 `useItemsData(id, 150)`（`:472-486`）：当 `id.nowNum == num0`（**恰好相等**）时执行 **`delItemsData(id)`，把整条物品记录删除**；
- 退款侧 `useItemsNum(..., -150)`（`:507-524`）：`num0 != -1` → `getItemsByBase("justice_badge")`（`:416-427`，**要求 `nowNum >= 1`**）→ 记录已删 → `null` → **`return false`，无 trace**。

### 触发条件（余额三档）

| 扣款前余额 | 结果 |
|---|---|
| > 150 | 记录保留 → 退款成功 → **无损**，仅看到提示 |
| **= 150** | 记录被删 → 退款落空 → **丢 150 荣誉勋章、无车、无异常提示** |
| < 150 | 按钮显示"荣誉勋章不足"且不可点（`setCanBuyBtn` `:315` 门槛）→ 走不到扣款 |

## 三、修复方案（端游同步版，7 处）

| # | 改动 |
|---|---|
| D1 | 新增字段 `_tempMaxI`（该行端游为裸 LF 行尾） |
| D2 | **前置校验前移**到扣款之前（`onBuyTips` 内、与 `gd.type == "sub"`"只能兑换一次"预检同处；文案逐字沿用）→ **永不扣款** |
| D3 | `onBuyTips` 记录抽中下标 `this._tempMaxI = maxI;` |
| D4 | `onBuyClick` **不再二次抽奖**（改用 `_tempMaxI`，缺失时回退抽一次）。原实现"`onBuyTips` 抽一次仅用于预检、`onBuyClick` 再抽一次决定发放"→ 确认依据与实际发放可不同、`sub` 拦截判据失真；D2 的正确性亦依赖 D4 |
| D5 | 失败路径退款改为 `this.refundPay(ed)`（端游形态：无 mod 守卫，直接替换） |
| D6 | 新增 `refundPay`/`refundItems`：按 `EPayType` 对称退款（金币/超合金X/Y/荣誉勋章）、**被扣空记录补建**（`addItems(...,newB=false)`）、materials 在 `modCraftFree` 下跳过（端游 `useItemsData` 同款守卫）、失败与补建均 `trace` 留痕 |
| D7 | 新增 `import gameAll.data.GoodsItemsDataGroup;` |

**与手游版的唯一差异**：手游在扣款/退款外有 `modPurchaseIgnoreConditions` 守卫，端游没有；故本同步版的插入文本**不加该守卫**，与端游既有风格一致。失败分支的前置校验按手游同款保留（D2+D4 后不可达，纵深防御）。
