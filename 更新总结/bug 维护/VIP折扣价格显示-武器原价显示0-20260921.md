# VIP 折扣价格显示反了（武器"原价"显示 0）· 排查与修复记录

> 记录日期：2026-09-21
> 状态：**已实施修复，待实机确认**
> 现象（用户报告）：玩家获得 VIP 后商店出现折扣显示，但**武器的"原价"显示为 0**，而实际（折后）价格是个较高的数值
> ——看起来像"打折把价格打高了"。
> 归属：**原版/两端共有的历史缺陷**（`GoodsDefineGroup.as` 两端内容完全一致，1409 行 0 差异）；本次**手游与端游同时修复**（端游见其 `更新总结\bug 维护\3.0前瞻版本bug维护\` 同名记录）。

---

## 一、显示链（谁在显示"原价"）

| 层级 | 标识 |
|---|---|
| 商店商品对象 | `GoodsDefineGroup.switchArms/switchCar/switchItems` 构造 `GoodsDefine`，**维持不变量 `d1.priceLevel = d0.Mprice`**（= 未折扣的原价） |
| 价格显示 | `UI/shop/ShopIcon.as:254 fleshPrice_byNow()`：`price_txt` 先填 `buyDefine0[币种]`（`fleshPrice_inData` 已按 `vipData.discount` 打折），随后**在 M 币商品分支把 `itemsData.priceLevel` 当"原价"追加显示**（`:376`） |
| 折扣叠加 | `:350-355`：物品自身 `discount`（0~1）与 VIP 折扣叠加 `discount = 1-(1-discount)*vipData.discount`；>0 时进入上面这段显示 |
| 实扣价 | `OneShopUI.yesBuy()` 用 `d0.Mprice / d0.num` 扣费（`d0` 为 `fleshPrice_inData` 后的对象，含 VIP 折扣） |

## 二、根因：5 条"定制价/补漏价"路径覆盖了 `Mprice`，却没同步 `priceLevel`

`GoodsDefineGroup` 里这些路径在 `switchArms/switchCar`（已设好 `priceLevel`）**之后**改写 `Mprice`，但**没有同步 `priceLevel`**：

| # | 位置 | 覆盖后的 Mprice（项目定制价） |
|---|---|---|
| VIP1 | `addCustomGoods()` 定制主武器（`discount == -1000` 的武器） | `getCustomWeaponPrice` = **4000~9000**（源码注释："custom weapons: 4000~9000 MB"） |
| VIP2 | 同上的副武器 | 同上 |
| VIP3 | 同上的战车（仅 `getCarDisplayLevel > 7`） | `getCustomCarPrice` = **1000~2000** |
| VIP4 | `addLegacyArmsGoods()` 补漏武器（星座等） | `defaultMPrice` = **600** |
| VIP5 | `addLegacyCarGoods()` 补漏战车 | **1200** |
| VIP6 | `addSpecialMCoinCars()` 特殊 M 币车（tank/electricSaw/charger/intercessor） | **50/50/50/150**（并显式 `discount = 0`） |

**数据证据**（`2_EmbedXml_xmlClass3` 主武器配置）：星座系列补漏武器（`conAries_lv1` 白羊座 / `conVirgo_lv1` 处女座 / `conTaurus_lv1` 金牛座 …）**既无 `<Mprice>` 也无 `<priceLevel>`**，且**无 `<discount>`** → 于是：

1. `switchArms` 后：`Mprice = 0`、`priceLevel = 0`；
2. 补漏路径把 `Mprice` 覆盖为 **600** → `priceLevel` **仍是 0**；
3. `discount` 缺省 → `Number("")` = **0** → `ShopIcon` 里 `discount = 1-(1-0)*vip` > 0 → **进入折扣显示分支**；
4. 于是界面显示：**现价 = ceil(600 × VIP折扣) = 540**，**"原价" = priceLevel = 0** → **"原价 0、折后 540，打折反而把价格打高了"** ✓ 与用户描述完全一致。

（对比：无折扣值（`discount == -1000`）的定制价武器走 `setSpecialState("show")`、不显示"原价"，所以那一支不暴露此问题——但同属"覆盖不同步"的不变量破坏，本次一并修。）

## 三、修复方案

6 处 `Mprice` 覆盖点之后各补一行，恢复"`priceLevel` = 未折扣的 Mprice"这一既定不变量：

```as
goods0.Mprice = <定制价/补漏价>;
goods0.priceLevel = goods0.Mprice;      // ← 新增
```

## 六、待实机确认项

1. **主验收**：VIP 账号打开商店 → 武器/战车的显示应为"**原价 = 定制价（如 600 / 4000~9000 / 战车 1200 等）+ 折后价 = ceil(原价 × VIP折扣)**"，原价不再显示 0；
2. 非 VIP（`vipData.discount == 1`）显示与修复前一致；
3. 实际扣费不变（仍按折后 `Mprice` 扣，VIP 折扣照常生效）；
4. 回归：`vipCard` 商品不参与折扣显示；特殊 M 币车（50/50/50/150）显示正常。

## 七、遗留（本次未动，待裁定）

1. **`discount == -1000` 的定制价武器**目前**不显示"原价/折后"对**（走 `setSpecialState("show")` 分支）——即那批 4000~9000M 币的武器只显示单一价格。是否要给它们也补上"原价/折后"显示，需另行裁定（涉及 `ShopIcon` 的 `-1000` 分支语义）。
2. `ShopIcon` 的价格显示把"原价"与"现价"拼进同一个 `price_txt`（`htmlText +=`，靠空格对齐）——排版观感由 SWF 符号决定，本次未改。
