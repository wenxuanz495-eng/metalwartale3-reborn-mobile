## 归档规则

1. **选位置**：新 bug 一律建在当前版本文件夹内；没有对应文件夹就按版本号新建（命名如 `3.0前瞻版本bug维护`）。
2. **命名**：`主题-YYYYMMDD.md`（日期用建档日）；一份 bug 一份记录，排查→方案→修复→验证全周期写在同一份内，用状态行跟踪（`已定位源头` → `已实施修复，待实机确认` → `已关闭`）。
3. **必备段落**：现象与复现链、根因（代码锚点到文件：行）、修复方案与决策点、实际修改文件、构建与验证证据（哈希/回读/自检）、待实机确认项。
4. **游戏逻辑改动两步走**：改 `decompiled` 源码后必须登记 `config\build\swf-script-patches.txt`（清单驱动补丁制，不登记不生效），并用 ABC 字符串回读验证进了 `build\game.swf`。
5. **提交**：bug 修复代码与记录同一次提交。
