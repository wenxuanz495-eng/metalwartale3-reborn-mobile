# 武器形态切换刷新功能总结

更新时间：2026-09-05  
适用版本：`metalwartale3-reborn.git` 当前正式源码

## 一、修改目的

解决战斗中打开武器菜单并切换武器形态后，数据已经改变，但战斗中的武器外观、攻击定义和相关显示没有立即刷新，必须先切换武器槽位才能间接刷新 的问题。

本次增加了独立的形态切换后刷新逻辑。切换形态后，当前正在使用的武器会立即重新载入；背包中未装备的武器只更新数据，不会错误地刷新到战斗场景中。


随后调用独立刷新函数：

```actionscript

```

刷新函数的判断规则：

| 场景 | 条件 | 处理 |
|---|---|---|
| 主武器 | 当前处于战斗状态、位于装备区，并且是当前使用槽位 | 调用 `Game.eventGroup.fleshArms()` |
| 副武器 | 当前处于战斗状态，并且位于装备区 | 调用 `Game.eventGroup.fleshSub()` |
| 背包武器 | 不属于装备区 | 只更新数据，不刷新战斗中的武器 |
| 非战斗状态 | `Game.gameState == "no"` | 不执行战斗刷新 |
| 非当前主武器 | 主武器槽位不是当前使用槽位 | 不刷新当前战斗武器 |

## 六、为什么原来必须切换武器槽位才能刷新

原来的 `switchArmsForm()` 只修改了 `ArmsItemsData` 和菜单显示数据：

```text
形态标签改变
  → 武器数据更新
  → 菜单更新
```

但它没有继续调用：

```text
Game.eventGroup.fleshArms()
```

因此战斗中的 `HeroCarBody.armsDefine` 和显示对象仍然保留旧形态。切换武器槽位时，槽位切换流程会调用 `changArms()`，所以看起来像是“换槽位后才刷新”。本次补丁把这个必要的刷新动作直接接到形态切换完成之后。

## 八、实机测试重点

建议分别验证：

1. 战斗中装备主武器时切换形态，当前主武器是否立即变为新形态。
2. 战斗中装备副武器时切换形态，所有副武器主体是否立即重建为新形态。
3. 切换背包中未装备的武器形态，是否只改变该武器数据，不影响当前战斗武器。
4. 退出并重新打开装备菜单后，形态、武器显示和菜单数据是否保持一致。
5. 切换形态后，武器特效、攻击定义、能量/芯片合并数据是否与新形态同步。

本次功能只增加“形态切换后的刷新”，没有修改武器特效资源、子弹大小、射速、备弹公式或芯片属性规则。
