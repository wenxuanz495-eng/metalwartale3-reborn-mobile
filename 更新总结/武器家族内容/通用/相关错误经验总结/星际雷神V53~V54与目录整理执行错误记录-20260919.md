## 一、SWF 手术类（V54 孤儿清理）

### 错误 1｜顶层定义删除 0 命中——FFDec XML 父级结构误判

- **现象**：`for it in list(root): root.remove(it)` 删除顶层 2902/2903 定义，命中 0 个（应 2 个）。
- **根因**：FFDec 导出的 XML 里，定义标签**不是根元素的直接子节点**（存在容器层级）；直接遍历根的子节点当然找不到。
- **修正**：构建父映射 `parent = {c: p for p in root.iter() for c in p}`，用 `parent[it].remove(it)` 删除。
- **预防**：对 FFDec XML 做结构操作前，先打印目标节点的实际层级路径，不要假设"定义在顶层"。

### 错误 2｜子树删除不适用"字符串流守恒"断言（差 50 项）

- **现象**：删除 10 个定义后，用"源元素流滤掉 10 个被删串 == 新元素流"做内容守恒断言，失败（差 50 项）。
- **根因**：**删除的是子树**——被删 shape/bitmap 的内部子元素（FILLSTYLE、边缘记录、EndShapeRecord 等）也随子树一起从新流中消失；逐元素比对把这些"合法消失"全算成了异常。Counter 差集诊断证实：51 项"源有新无"全部是被删子树内部件 + sprite100 容器的合法重序列化，无任何意外改动。
- **修正**：改用**语义指纹验证**——①全库 ID 库存差恰为 10 个被移除定义（含形状对位图的引用各 1）；②全部 sprite 的放置/RO/流声头事件逐一相等。
- **预防**：内容守恒断言要匹配操作类型——"纯新增/纯改值"可用流比对；**"删除/移动子树"必须用语义指纹**（库存差 + 事件等价），并在断言失败时先跑 Counter 差集定位，不猜。

### 错误 3｜指纹函数 spid=None 崩溃

- **现象**：`int(spid)` 对顶层 SoundStreamHead2Tag（无 spriteId）抛 TypeError。
- **根因**：事件归集时假设所有事件标签都在 sprite 内；**顶层也有流声头**。
- **修正**：无 spriteId 的事件不入 sprite 映射。
- **预防**：FFDec XML 中 main timeline 与 sprite 内部的同名标签结构不同，遍历时对所有 ID 类属性判空。

## 二、脚本与工具链类

### 错误 4｜heredoc 反斜杠塌缩

- **现象**：Bash heredoc 内的 python `'\\'` 到达解释器时变成 `'\'`，SyntaxError 两次。
- **修正**：一律用 `BS = chr(92)` 或 `chr(92)` 拼接，**不在 heredoc 里手写反斜杠字面量**（星际雷神系列脚本已有此惯例，本次新写临时代码时又踩）。
- **预防**：写入 `相关错误经验总结` 的通用规约——凡 bash heredoc + python，反斜杠一律 chr(92)。

### 错误 5｜git ls-files 中文路径静默跳过（1/23）

- **现象**：全库替换旧目录名，预期 23 个文件，第一轮只改了 1 个。
- **根因**：`git ls-files` 默认 `core.quotepath=true`，中文路径返回带引号的八进制转义名（如 `"\346\233\264..."`），按此名打开文件静默失败被 except 吞掉。
- **修正**：改 `os.walk` 遍历磁盘文件。
- **预防**：涉及中文路径的 git 枚举一律加 `-c core.quotepath=false`，或直接 os.walk；**批量操作后必须核对"处理数 vs 预期数"**（本次靠预期 23 对 1 才发现）。

### 错误 6｜ugrep 中文环境字符类报错

- **现象**：`grep -E "xxx[/\\]yyy"` 在本机 ugrep + 中文 codepage 下报 "invalid character class range"。
- **修正**：复杂匹配改用 python re。
- **预防**：本机 grep 是 ugrep 别名，含反斜杠/中文的模式不要用 grep -E，直接 python。

### 错误 7｜配置锚点双空格（雪花块两次 find 失败）

- **现象**：`find('<arms index="92" id="snow">')` 连续返回 -1。
- **根因**：原版配置里 `index="92"` 与 `id="snow"` 之间是**两个空格**。
- **修正**：锚点改用 `id="snow"` 单字段定位 + `rfind('<arms', 0, i)` 回找块头。
- **预防**：原版文件手写痕迹多（多空格/全角注释），锚点用**短且稳定的单一字段**，不用长串精确匹配。

## 三、流程类（V53/V54 提交与雪花盘点）

### 错误 8｜断言失败后后续命令仍执行（登记行漏入库）

- **现象**：README 索引登记脚本的锚点断言失败（分类整理后旧行文本已变），但同一条 bash 里的 `git add/commit/push` 继续跑完——新总结文件入了库，**登记行却没进 README**。
- **根因**：python 失败退出码没有阻断 bash 后续命令（`&&` 链只连了部分命令）。
- **修正**：补一个小提交把登记行加上（归位于 `武器特效重做/总结/` 并按新表格式登记）。
- **预防**：文档编辑与 git 提交分两步执行；编辑脚本失败立即停止，不带病提交。

### 错误 9｜抽查断言形同虚设（V54 回读 `or sid != 100`）

- **现象**：回读抽查 `assert found or sid != 100` —— 121/115 两个 sprite 的抽查被 `or` 短路成永远通过。
- **修正**：整段替换为语义指纹验证后删除该劣质断言。
- **预防**：写断言时自问"这个断言在目标出错时会不会仍然通过"；用具体输入在脑内跑一遍真/假两种分支。

### 错误 10｜雪花素材路径反斜杠 heredoc 崩溃（重演）

- **现象**：素材盘点脚本 `os.path.join(base, fn).replace('\','/')` 再次 SyntaxError。
- **说明**：与错误 4 同源，单列记录是因为它证明**chr(92) 规约必须覆盖临时代码**，不只是正式脚本。

## 五、沉淀规约（今后执行任务的标准动作）

1. FFDec XML 结构操作：先打印层级路径；删除/移动子树用**语义指纹**验证，不用字符串流比对。
2. 批量帧插入：**降序插入 + 索引只算一次**；同帧多元素按"后插者居前"安排次序。
3. heredoc 反斜杠一律 chr(92)；中文路径枚举用 os.walk 或 quotepath=false。
4. 每个批处理断言"处理数 == 预期数"。
5. 文档编辑与 git 提交分离执行；任何断言失败立即终止，不带病提交。
6. 配置锚点用短字段定位，警惕原版多空格。
7. 断言写完自问："目标出错时它会不会仍然通过？"
