## 二、玩家武器伤害：`get hurt()` 分岔口（最重要的一个结论）

`OneArmsDefine.get hurt()`（约 448 行）：

```actionscript
if(this.father == "arms" || this.father == "sub")
   return Number(this.baseHurt);        // 玩家主武器/副武器 → commonLevel 推导
return Number(this.hurtArr[0]);         // 其余（enemyArms 敌方武器） → XML 原值
```

结论：

1. **玩家武器 XML 里的 `<hurt>` 是死数据**（如小黄豆的 6.1/37/118/253 从不生效），仅敌方武器直接使用。
2. 面板显示的是 `getAllDps()`，与 XML hurt 无关。
3. `hurtArr = String(xml0.hurt).split(",")` 支持多值，但全代码库只读 `[0]`，多值设计从未启用。
4. 敌方武器没有 commonLevel→DPS 系统、没有主武器倍率，伤害就是 XML 直写值。

## 三、玩家武器实际伤害推导链（baseHurt）

`OneArmsDefine.fleshData()`（约 396~424 行）+ `dataMust\GameDefine.getDpsByLevel()`：

```text
① commonLevel = max(originalCommonLevel, 成长来源)
   成长来源三种（小黄豆都没有，等级固定）：
   - specialType 含 "Level_Growth_N"：等级 = 玩家等级 + N + 1（这才是"跟随玩家成长的特殊武器等级"）
   - 紫色芯片：getPurpleChipGrowthLevel() > 0 时取 getPurpleGrowthCalculatedLevel()
   - 副武器 con* 系列：加 itemsData.strengLevel（强化等级）
② baseDps = 10 × commonLevel^1.5 + 2
   主武器 ×4×1.2 = ×4.8；副武器 ×1.15×1.2
   ★ 2.5 的主武器倍率是 ×2（OneArmsDefine.fleshData, 2.5 代码库 341~349 行），没有 ×1.2 —— 这是 11.3 数值膨胀的主体
③ allDps = baseDps + itemsData.dpsHurt（芯片加成）
④ baseHurt = allDps × (attackGap+0.1) / (shootNum × bulletNum) × reduceRa
   （getHurtByDps；bulletType 非 bullet 时按 bulletLife×30 折算；lightning 分支另算）
```

"武器等级：X级"显示于 `UI\change\ArmsItemsTip.as`，就是 commonLevel。

## 四、连发与射速结构（纯配置驱动，无按等级缩放的代码）

`ArmsAttack.attackPan()` 状态机：start → delaying(attackDelay) → shoot → shootDelaying(shootGap) → overing(attackGap) → over → loop。

关键字段（全部来自 XML，缺省行为见括号）：

```text
shootNum     一个攻击周期内的射击次数（缺省→1）
shootGap     周期内相邻两发间隔（缺省/0→贴发连射）
bulletNum    一次发射的弹数，>1 时按 angleRange 扇形展开（缺省→1）
angleRange   扇形展开角度
tranArr      炮位偏移表，乒乓轮换（如 -5,5 / -10,0,10）
attackGap    周期间隔（面板射速 = 1/(attackGap+0.067)×shootNum×bulletNum）
```

运行时没有任何代码按等级修改 attackGap/shootNum——**连发与射速变化全部靠每级 XML 差异**。

### 副弹机制（secondBulletImg）

`ArmsAttack.shoot()`：一个周期内奇数发用 `bulletImgLabel`，偶数发用 `secondBulletImg`；
`BulletLink.getBulletByDefine()` 传 secondBulletImg 时**只换 imgLabel 视觉**，hurt/速度/碰撞宽度/受击特效全部沿用本等级定义——副弹不是低伤害弹。
（`n==1` 分支用于 bulletNum>1 时第二颗弹换图；`charged` 有专属随机分支。）

### 已确认的跨版本差异陷阱

- 2.5 小黄豆 LV2~4：`shootNum=2`（双连发）；3.4 和 11.3 **缺失 shootNum→1（单发）**。
- 2.5 / 3.4 小黄豆 LV5~6：`attackGap=0.05`；11.3 改为 0.1（原生 nerf，非团队改动，见初始提交 ba10543）。
- 当前 GitHub 配置已按 2.5 加回 `secondBulletImg`（LV2/LV3→lv1弹、LV4→lv2弹），但 shootNum=1 时偶数发分支永不触发，**该配置处于休眠状态**；要生效只需补 `<shootNum>2</shootNum>`。
- 2.5 小黄豆 LV2~6 实际射速 20 发/秒，11.3 全部 10 发/秒，**每秒输出差一倍**；单发伤害又因倍率差（×4.8 vs ×2）反向膨胀。迁移手感必须成对处理 shootNum/attackGap 与 commonLevel/倍率，只改一边会破坏平衡。

## 六、怪物等级系统（血量/伤害/经验/金币）

### 1. 等级来源

- 每个关卡 XML 的 `enemyLv`（`LevelsDefine.as:171`，解析时 −1）。
- `EventGroup`（约 1300~1340 行）刷怪取 trueLevel0：normal 关=`filter.getEnemyLvNow()`；3-13 Boss=77；extra=`extraData.getEnemyLevel()`；weekExtra=周常 define.level−1；specialExtra=玩家等级；union=关卡 enemyLv。→ `b0.setLevel(level)`。

### 2. 等级→基数（`gamefile\gameAll\GameDefine.as`）

```text
血量基数 test_getEnemyLife_byLevel(768行)：
  [(4×1.2) + (1.15×1.2×subRa)] × 10 × L^1.5 × 1.5 × (1+0.02L+chipRa) / 2 × 1.2 × 0.8
  本质 = 同等级玩家主武器DPS + 副武器DPS 之和的一半（与玩家公式同构）
  chipRa 分段 0.15→7（11级起每10级跳档）；subRa 1→8（91级封顶）

攻击基数 test_getEnemyHurt_byLevel(938行)：
  ceil( 2×(k0·L² + k1 + 玩家车生命期望×2) × (1+0.02L+chipRa) / 166 )
  chipRa 分段 0.2→11；★60级分水岭：k0 5→20、k1 100→1000（60级后攻击陡增）
  难度：difficult==2 → ×1.5；==3 → ×2

经验 test_getEnemyExp_byLevel / 金币 test_getEnemyCoin_byLevel：简单二次/线性式
```

### 3. 多乘区合成（`LifeBodyDefine.fleshAll_byLevel`，58~94 行）

```text
life_0 = 血量基数 × enemyLife_ra(关卡XML) × d_ra(难度系数；extra/weekExtra 用 nowDiff+1)
hurt_0 = 攻击基数 × enemyHurt_ra(关卡XML) × d_ra
maxLife = life_0 × baseLife(怪物自身XML倍率, inData_byXML 174行)
（maxLife 的 /57 是显示层魔数，存取对称）
```

### 4. 伤害最终合成（`EventGroup.hurt`，约 915 行）

```actionscript
value = b_hurt_0 * value;   // 攻击者等级基数 × 子弹hurt(敌方武器=XML原值)

```

- 敌方玩家车（罗杰等）不走本系统：`EnemyHeroCtrl.as` 有每武器专用 hurt_0 系数表（0.038~25）。

敌方武器 XML 的 `<levelGrow>`（2/3/10/40 等）在仓库及 2.5 代码库的 AS 代码中**零引用**，怪物等级成长不经过它。对比怪物强度应对比：关卡 enemyLv、公式常数（chipRa/subRa/k0/k1 档位）、怪物 baseLife、关卡 enemyLife_ra/enemyHurt_ra。

## 七、子弹碰撞与伤害结算链路（DPS 如何落地）

### 1. 核心语义：DPS 是预算，不是施加

DPS 公式从不直接作用于怪物，它只用来**反推每颗子弹应携带的伤害**。真正的伤害发生在每颗子弹与怪物受击框碰撞的那一帧，一次碰撞结算一次。没碰到就是零伤害——公式 DPS 是期望上限，实战 DPS 取决于命中率。

### 2. 伤害的携带（子弹出生时）

`BulletLink.getBulletByDefine()`：`bu0.hurt = d.hurt`（经 `get hurt()` 读取器 = baseHurt）。**主弹与副弹携带同一个值**——`secondBulletImg` 只换图片，hurt/速度/碰撞宽度/穿透/弹跳/受击特效全部沿用本等级定义。

### 3. 碰撞检测（`bodyGroup\BodyGroupHit.as`，每帧）

```text
每颗子弹 → 以自身位置为中心、边长 = bulletWidth×2 的矩形（约 296~337 行）
       → 与目标 AAHD.hurtRectArr（怪物受击矩形数组）做矩形相交判定（HitIO）
       → 扫掠判定：用下一帧位置 nextMot2 再测一次，防止高速子弹穿身隧道
       → 命中 → bulletHited()（462行）→ eventGroup.hurt(b0, bullet0.hurt, ...)（505行）
       → 穿透弹（penetrationB）穿过时在 453 行再结算一次，子弹继续飞行
```

- `bulletWidth` 是**判定尺寸**（碰撞矩形半宽），与 SWF 视觉大小是两回事。
- 子弹寿命 `bulletLife` 到期未命中则消失，零伤害。
- 激光类走 `hitRectArrLine2` 线判定（约 363~369 行）；`lightning` 类不靠碰撞，`OneBulletBody.lightningTimer()`（231 行）按周期直接对随机目标调 `eventGroup.hurt`。

### 4. 命中瞬间的完整合成（`EventGroup.hurt`，848 行起）

```text
子弹自带 hurt（baseHurt）
  × 攻击方系数：玩家 = getAllArmsAdd()；敌人 = 等级攻击基数 hurt_0
  + 暴击：HurtCount.getCritHurt(itemsData, hurt0)，每次命中独立掷骰
  × HurtCount.getHurt：attackType（mixed 等） vs defenceType 属性克制修正
  × (1 - defenceHurtRedu) 防御减免
  → 扣血 + 伤害数字 + hitImgLabel 受击特效
```

### 5. 连发（shootNum=2）的伤害语义

把同样的每秒伤害预算从"1 颗大弹 1 次判定"拆成"2 颗各带一半伤害的弹、2 次独立判定"：

| 变化 | 说明 |
|---|---|
| 期望 DPS 严格不变 | baseHurt 分母含 shootNum，预算自动重分配 |
| 方差变小 | 大暴击变成多次小暴击，期望暴击总量相同 |
| 过杀浪费减少 | 第一发打死残血怪后第二发不再浪费在它身上 |
| 判定次数翻倍 | 每颗弹独立碰撞测试，±5 炮位错开增加覆盖，对小/快目标实际命中更高 |
| 无额外收益的场景 | 高护甲/属性减免型敌人每次结算独立吃一次防御公式，两种结构完全等价 |
| 代价 | 同屏子弹数翻倍（性能可忽略） |

## 八、改射速的三种路径与 DPS 耦合规则（核心经验）

本节是实战得出的决策表，改任何武器的攻击节奏前先读这里。

### 1. 三个量的关系

```text
面板 DPS（预算）= 10×commonLevel^1.5 × 倍率 + 芯片加成   ← 只认等级/芯片/倍率，改射速永远不动它
单发伤害       = 面板DPS × (attackGap+0.1) ÷ (shootNum×bulletNum)  ← 推导值，随射速结构自动重算
实战 DPS       = 单发伤害 × 实际每秒发数 ≈ 面板DPS × (attackGap+0.1)/attackGap
```

### 2. 三种改法的行为对照

| 改法 | 每发伤害 | 实战 DPS | 结论 |
|---|---|---|---|
| 改 `shootNum`（连发数） | 精确 ÷shootNum | **严格不变** | 唯一的"手感变、强度不变"路径，恢复连发优先用它 |
| 改 `attackGap`（周期） | 按 (gap+0.1) 折算，非反比 | ∝ (gap+0.1)/gap，**必然变** | gap 变小 = 每发降一点、总量升更多（0.1→0.05 = 单发-25%、总量+50%） |
| 补 `reduceRa`（每武器 XML 字段，默认1） | 直接乘在最终单发上 | 同比放大 | 纯补偿开关：如 gap 0.1→0.05 后写 `reduceRa=1.3333` 可让单发精确回到改前值（总量变 +100%） |

### 3. 重要推论（血泪教训）

- **面板无变化 ≠ 实战无削弱**：attackGap 改动面板纹丝不动，但实战输出按 (gap+0.1)/gap 变化。
  11.3 把小黄豆 LV5/6 的 0.05 改成 0.1 就是一次面板隐形的实战削弱（-1/3）；反向改即是增强（+50%）。
- **同等级跨版本不可比**：两版主武器倍率不同（2.5=×2，11.3/GitHub=×4.8），同 commonLevel 下
  当前版预算是 2.5 的 2.4 倍。"等级一样=强度一样"不成立。
- **"伤害不动"的语义要事先和需求方对齐**：①不碰伤害字段（公式自动重算，单发会变）还是
  ②单发数字严格不变（必须用 reduceRa 补偿，总输出变化更大）。本次小黄豆 LV5/6 采用 ①。
- 单发伤害没有独立配置字段可改；XML `<hurt>` 对玩家主武器是死数据（见第二节），
  想动单发只能通过 commonLevel / reduceRa / 射速结构三条路。

## 九、迁移执行原则（本文结论的直接应用）

