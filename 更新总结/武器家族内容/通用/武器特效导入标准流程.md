# 武器特效导入标准流程

这是本项目当前验证过的最高效、准确率最高的武器 SWF 导入方法。以后导入主武器或副武器，默认按此流程执行。

## 1. 只在隔离目录操作

默认测试包：

```text
D:\superalloy\tmp-soya-family-test\game-test
```

每个系列单独建立：

```text
<family>-restore\input
<family>-restore\work
<family>-restore\output
<family>-restore\manifest
<family>-restore\logs
<family>-restore\report
```

正式 GitHub 工作区不作为实验目标。

## 2. 先确认真实运行入口

检查 `Game.as`、构建脚本和测试包，确认：

- `arms`、`sub`、`bullet` 分别实际加载哪个 SWF；
- 配置中的 `father/label` 是否能解析；
- 测试启动使用哪个 `game.swf`。

不能仅按文件名判断。旧版 `sub37.swf` 可能在当前项目中另存为 `sub25.swf`，但运行时的 `sub` 仍可能是 `sub1130.swf`。

## 3. 导出来源和目标 XML

使用 FFDec：

```text
ffdec-cli.exe -swf2xml source.swf source.xml
ffdec-cli.exe -swf2xml target.swf target.xml
```

两份 XML 只放在 `work`。同时记录输入 SHA-256。

## 4. 建立版本映射

先按名称、家族 ID、导出名和版本演进建立映射表：

```text
当前等级 | 名称 | 当前导出 | 2.5来源 | 3.4来源 | 是否保留当前本体
```

必须确认：等级是否后移、3.4是否新增初始形态、当前版本是否新增最高形态、MK2是否只是异色本体。不能默认 `lv1` 对 `lv1`。

## 5. 提取完整依赖闭包

从 SymbolClass 找到根 Character ID，递归收集所有：

- MovieClip / DefineSprite
- Shape
- Bitmap / DefineBits
- PlaceObject、RemoveObject、ShowFrame
- 矩阵、颜色变换、边界、注册点
- Sound、StartSound
- SymbolClass 映射

只复制 PNG 是错误做法，会丢失帧动画、矩阵、注册点和内部引用。

## 6. 全量 Character ID 重映射

找出目标 SWF 最大 Character ID，为来源闭包分配未占用的新 ID，并同步重写：

- Sprite 子标签引用；
- PlaceObject 引用；
- Shape 的 BitmapFill；
- 声音引用；
- 所有递归依赖；
- SymbolClass 导出 ID。

禁止猜测 ID，也不能只修改根 Symbol。

输出：

```text
manifest\dependency-closure.txt
manifest\dependency-remap.txt
manifest\changed-symbols.txt
```

## 7. 混合时间轴

新形态本体需要保留、但旧版蓄力或开火层被删除时，采用：

```text
当前本体层 + 旧版蓄力层 + 旧版开火层 + 当前注册点
```

逐帧检查：帧数、深度、`basePoint`、`shootPoint`、矩阵平移、缩放、RemoveObject 和特效清理。

不能遗漏第一个旧特效出现前的清理标签，也不能让旧特效占用注册点深度。必要时按 `shootPoint` 差值补偿矩阵。

## 8. 配置精确修改

只替换目标家族区块，核对：

```text
imgLabel
bulletImgLabel
hitImgLabel
attackType
bulletSpeed
bulletLife
bulletWidth
attackGap
recoilValue
bulletVra
tranArr
```

名称、家族 ID、武器 ID、升级关系和新增等级保持不变。速度、行为参数除非明确要求，不因视觉恢复自动改变。

输出：

```text
manifest\changed-config-fields.txt
```

## 9. 重建与验证

```text
ffdec-cli.exe -xml2swf merged.xml output.swf
ffdec-cli.exe -swf2xml output.swf verified.xml
ffdec-cli.exe -dumpSWF output.swf
```

必须确认：导出名、SymbolClass、Character ID、依赖、帧数、矩阵、边界、`basePoint`、`shootPoint`、配置引用和无关导出均正确。

## 10. 部署和回滚

部署前先备份测试包当前有效文件到 `input`，再仅替换测试包中的目标 SWF。不得复制回正式 GitHub 目录。

测试失败时，只用 `input` 中的测试包备份回滚，不使用 Git reset，不覆盖用户已有修改。

## 11. 标准执行链

```text
确认运行时入口
→ swf2xml
→ SymbolClass 定位
→ 递归依赖闭包
→ Character ID 全量重映射
→ 精确合并时间轴
→ 精确修改配置区块
→ xml2swf
→ swf2xml / dumpSWF 回读
→ 独立测试包部署
→ 游戏内验证
```

此流程已经用于电磁炮、小黄豆、响尾蛇、顽皮、无幻、深渊、深渊MK2、黄金深渊和星爆系列。以后如遇等级后移、异色 MK2、深度冲突或版本新增形态，必须先扩展版本映射和混合时间轴分析，不能直接覆盖整个 SWF。

## 12.1 鞭炮导入补丁：防止“内存已修改、写盘却丢失”

这次鞭炮/黄金鞭炮实验发现了一个重要错误模式：脚本已经在内存中完成 Character 导入、时间轴替换和 ID 重映射，但写出 `merged.xml` 时又重新读取了原始 `target.xml`，导致全部修改被丢弃。FFDec 仍然可以正常重建，因此仅看 `xml2swf` 成功并不能证明修改已经写入。

以后必须遵守：

1. 解析目标 XML 时保留同一个 `ElementTree` 对象。
2. 所有合并、替换和重映射都只操作这个对象。
3. 写盘时直接写入已修改的对象，不能重新 `parse(target.xml)`。
4. `xml2swf` 前先检查 `merged.xml` 中的目标导出、帧数和关键 Character ID。
5. `xml2swf` 后必须再次 `swf2xml`，从输出 SWF 回读验证实际内容。

最低回归检查：

```text
内存对象已修改
→ merged.xml 中确实出现修改
→ xml2swf 成功
→ verified.xml 仍出现修改
→ dumpSWF 成功
→ 才允许部署测试包
```

## 12.2 鞭炮/黄金鞭炮专项检查

2.5只有：

```text
banger_lv1
banger_lv1_bullet
```

没有独立的2.5黄金鞭炮本体。因此黄金鞭炮恢复时要明确区分：

- 黄金本体、颜色、名称和等级关系：保留当前版本；
- 黄金发射时间轴、蓄力、开火、消退和声音：可以使用2.5 `banger_lv1`；
- 黄金子弹：可以使用2.5 `banger_lv1_bullet`；
- 黄金受击特效：按用户指定，可继续沿用当前测试包鞭炮受击特效。

鞭炮本体和子弹不能只检查导出名。必须确认：

```text
banger_lv1～lv4：25帧完整本体时间轴
Goldbanger_lv1～lv2：25帧动态时间轴
banger_lv1_bullet：8帧子弹动画
```

如果回读后出现：

```text
banger_lv1_bullet = 1帧
蓄力层消失
只有简化开火层
```

优先检查“写盘时是否重新读取原始目标 XML”，不要先怀疑资源闭包或FFDec重建。

## 12.3 动画导入后的最小静态验证

对于完整发射动画，不能只验证根 Symbol 存在，还要逐项验证：

- 本体帧数；
- 子弹帧数；
- 蓄力阶段是否有多个 PlaceObject；
- 开火阶段是否有 StartSound；
- 发射后是否有清理/消退层；
- 黄金本体是否仍保留当前外观；
- 受击路径是否按要求保留当前或旧版；
- 所有 SymbolClass 和无关武器是否未改变。

## 12.4 挂点标记与美术本体的区分（2026-09-08 电磁炮家族教训）

武器本体 sprite（主武器 arms1100 与副武器 sub37/sub52/sub1130 同源）的时间轴里存在**挂点**——命名实例 `basePoint`/`shootPoint`/`armsPoint`/`rocketPoint`/`plasmaPoint`（2.5）/`laserPoint`（新版新增），名字包含即命中。实例内的**挂点标记**（方框加号或圆形加号，红/白/黑/透明任意配色，如 sub37 角色 110→形状 109 红色象限方块 13.5×13px）在 FFDec 静态导出中可见。**FFDec 静态导出/帧图里非常显眼，但实机 2.5/3.4/新版均被 `SWFLoaderManager.getSingleMovieclip()` 隐藏**——按名字 indexOf 扫描子对象（**与颜色、形状无关**：白/黑/透明、圆圈加号同样命中），读坐标后 `visible=false`＋`scaleX/Y=0.1`，三版代码一致（2026-09-09 双代码证实）。**检查比对时必须先把挂点标记从美术素材中区分出去，再下外观差异结论。**它们是射点/基点功能锚点（运行时读坐标出子弹，见 `SingleMovieclip.basePoint/shootPoint` → `SubImage.get shootPoint()` → `ArmsAttack.shoot()`），**不是美术本体**：

- 导出帧图里逐帧位置纹丝不动的红色几何块 = 挂点标记，不是炮体配色、不是待机动画；
- 比对 2.5/3.4 与当前版画面时，必须先把标记从美术中剥离再下"外观差异"结论（电磁炮 2.5 真美术=白银导轨炮体+逐帧 ADD 电弧层，红色是标记）；
- 回迁老版本本体时，标记不作为美术回迁对象；2.5 与当前版挂点矩阵逐字节相同（锚位无需重算），回迁前先在 XML 里核对挂点实例的 name 与 matrix；
- 需要定位挂点时用 FFDec swf2xml 搜 `name="basePoint"` / `name="shootPoint"`，不要靠像素猜。
