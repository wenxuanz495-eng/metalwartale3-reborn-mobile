# 原版武器文件资料地图与调查路径

> 定位：调查"某把武器的获取/购买/升级/数值"时**先查本地图定位文件，再下代码**，避免在目录间反复横跳（20260920 黄金黑绳调查实测：从报告到根因横跨 3 层配置文件与 6 个代码文件，本篇即其路径沉淀）。
> 案例全记录：`..\..\..\bug 维护\3.0前瞻版本bug维护\黄金黑绳可被直接研发绕过核心获取-20260920.md`；调研类错误记录见同文件夹《雪花2026调研错误记录与查证方法-20260919.md》。

## 一、文件地图（武器资料分三层，别混）

| 层 | 位置 | 内容 | 怎么查 |
|---|---|---|---|
| ① 武器定义本体 | `decompiled\embedded-xml-assets\6_EmbedXml_xmlClass7_EmbedXml_xmlClass7.bin` | 全部武器定义：`<arms index="N" id="导出名">` → `<armsLevel>`×N 级；字段含 name/type/price/Mprice/Xprice/Yprice/Zprice/Jprice/mustLevel/mustItems/priceLevel/commonLevel/specialType(`Level_Growth_N`)/hurt/bullet*/reduceRa/attackGap 等 | UTF-8 明文，`grep -a` 直接搜中文名或导出名；python 按 `<arms id="...">` 切块逐字段读 |
| ② 商店/兑换清单 | 同目录各 bin（特征：含 `<arms>a,b,c</arms>` 逗号标签清单，如 `21_EmbedXml_xmlClass13.bin`） | 各商店**卖什么**：G币/M币/兑换/正义徽章(Jxml) 等按货币分区的标签清单 | 判断"能不能买到"先查这里——**清单里没有 = 商店不卖**，与价格无关 |
| ③ 核心描述等周边 | 同目录其他 bin（如 `19_EmbedXml_xmlClass12.bin`＝开核心介绍/掉落文案） | 核心投放类武器的文案指向（"原版稀有武器：XXX"） | 核心获取类武器（黄金系）改 id 时三处必须同步 |

> 同目录还有别的 bin（语言、关卡、任务等），定位特征：先 `grep -rla "关键词" decompiled/embedded-xml-assets/` 全量扫一遍，看命中文件的特征再归类，不要凭文件名猜。

## 二、获取门控代码链路（谁决定"这武器怎么拿"）

| 环节 | 文件 | 职责与关键点 |
|---|---|---|
| 定义解析 | `body\define\DefineGroup.as` / `OneArmsDefine.as` | XML→对象；**`price = int(xml.price)`，空标签 = 0**；`index` 属性决定分组与区间（armsRange/subArmsRange） |
| 商品装配 | `goods\GoodsDefineGroup.as` `init()` | 四大货币区：`arms`(G币)/`Marms`(Mprice)/`Xarms`(Xprice)/`Jxml`(Jprice) 各自从清单 bin 装配；另有 addCustom/addLegacy 等追加段 |
| 渠道特判 | `goods\GoodsDefineGroup.as` `getBuySite()` | 返回渠道：`shop`/`exchange`/`pay`/`activity`/`star`/`grow`/`core`(20260920 新增)；空 = 无特殊渠道。**匹配串只锁 lv1 标签**（如 `cutter_gold_lv1`），匹配前缀会误伤升阶视图 |
| 研发列表准入 | `UI\research\ArmsDataFilter.as` `getOneList()` | 未拥有的武器定义 `index < 50` 就以"可研发定义"进研发列表——**新增"不可直接研发"的武器要在这里或 getBuySite 拦** |
| 研发/升级界面 | `UI\research\ArmsResearchUI.as` | `showArmsMust`：按 getBuySite 渲染提示（通过活动/星星奖励/成长计划/开启核心获得）或商店按钮；`upgradeClick`：扣 price+mustItems → `addItems`(研发出新) 或换 `baseLabel`(升级) |
| 助手与角标 | `UI\helper\HelperBuilder.as` / `UI\icon\ItemsArmsIcon.as` | getBuySite 为空且未拥有的武器会被助手条推荐"可研发新武器"、打新角标——**改渠道返回值会自动联动这两处**（返回非空即不再推荐） |
| 币与扣费 | `gameAll\data\GameData.as` 等 | `addCoin`(G币)、justice_badge 徽章兑换读 `Jprice` 等 |

## 三、关键语义（踩过坑的，改前必读）

1. **金线/核心投放武器的价格正确形态 = price/Mprice/Jprice 全空**（对照模板：goldflyBlade 六级全空）。price 空 → 解析为 0 → 研发扣费 0——**UI 不拦就等于免费送**；price 有值也只是"能扣得起就能研发"。配置生成脚本按"照抄本家"口径时，本家的商店价不能带进金线（黄金黑绳 lv1 残留 20000 即此事故）。
2. **"能买"由清单决定，"扣多少"由价格决定**，两处分开查；价格残留而清单没有时，价格经研发界面仍可达，不是死数据。
3. **阶间升级没有独立获得入口**：升级界面的等级条纯展示，`showArmsMust` 全文件只有"下一阶"和"lv0(未拥有)"两个调用点——封死 lv1 研发即封死整条线的非法入口。
4. **获得途径提示文本**由 getBuySite 返回值映射（activity→"通过活动获得"、core→"通过开启核心获得"…），返回空则整个 shop_mc 隐藏、什么都不显示。
5. **`specialType=Level_Growth_N`** 是成长型标记（N=成长档），与获取渠道无关，别拿它当门控用。
6. 未拥有/已拥有在列表里是两种对象：`OneArmsDefine`（定义，可研发）vs `ArmsItemsData`（持有的物品，可升级）——排查时先分清手头是哪个。

## 四、标准调查路径（可复用六步）

1. **中文名 → 导出名**：`grep -rla "中文名" decompiled/embedded-xml-assets/`，或先查 `更新总结\武器家族内容\` 对应家族文件夹（导入总结里必写导出名）；
2. **导出名 → 定义块**：python 定位 `xmlClass7` 的 `<arms id="...">` 块，逐字段读，并**对照同型模板家族**（金线对照 goldflyBlade，不对照本家）；
3. **导出名 → 代码链路**：`grep -rn "导出名" decompiled --include="*.as"`，重点 GoodsDefineGroup / ArmsResearchUI / ItemsController；
4. **能不能买**：全量扫商店清单 bin 有无该 id + `GoodsDefineGroup.init` 四货币区；
5. **怎么获得**：`getBuySite` 分支 + 清单命中情况 + 核心/活动/成长系统（xmlClass12 文案指向）；
6. **改动收尾**：改 `decompiled` 源码 → 登记 `config\build\swf-script-patches.txt`（新文件首改必须登记）→ `构建.bat` → ffdec 反导出回读 → `--check sa/sa_debug` 双自检 → 记录入 `更新总结`。
