# 雪花2026 调研错误记录与查证方法 - 20260919

> 背景：雪花 2026 新形态立项调研中，AI 连续产生 4 处错误结论，全部由用户以**实机面板截图与游戏常识**纠正。
> 本文档把每个错误的"错误结论 → 实际情况 → 根因 → 修正"完整存档，并沉淀为可复用的查证方法清单。
> 适用范围：任何涉及原版武器配置块（xmlClass3/7 等）字段调研与数值改动的任务。**后续同类调研开工前先通读本文。**

## 一、错误记录

### 错误 1｜固定字段白名单提取 → 误判"雪花没有成长字段、等级非动态"

- **错误结论**："snow 块根本没有 specialType 字段，『成长型』只是 specialProperty 描述文字，不触发动态等级。"
- **实际情况**：snow 块两级均有 `specialType`——lv1(2013)=`Level_Growth_5`、lv2(2014)=`Level_Growth_15`；成长公式（`OneArmsDefine.fleshData()`）对它生效：**有效武器等级 = max(配置commonLevel, 玩家等级 + 成长值 + 1)**。实机面板实证：玩家 150 级时 2014 显示"原生成长 人物等级+15、武器等级 165 级"。
- **根因**：第一轮字段提取用的是**固定字段名白名单**（name/attackGap/imgLabel 等 18 个），清单里没有 `specialType`——把"我的搜索没搜到"当成了"文件里不存在"。
- **修正**：全量标签普查（统计块内全部标签及出现次数）后再下"有没有"的结论。

### 错误 2｜内部名直译当实际名 → "正义勋章"乌龙

- **错误结论**：把升级材料 `justice_badge` 直译为"正义勋章"，并接受"游戏里没有正义勋章"的推论。
- **实际情况**：`justice_badge` = **荣誉勋章**的内部英文名（代码变量名即 `honorBadge`，GoodsDefineGroup:381；物品表 xmlClass12 有其条目）；`justice2_badge` = **公会奖章**。游戏内不存在叫"正义勋章"的第三种勋章。
- **根因**：内部英文名按字面直译，未到物品定义表反查显示名。
- **修正**：内部名 ↔ 显示名一律通过物品表（xmlClass12 等）反查映射；含 badge/medal/coin 等字样的内部名，先查定义再下结论。

### 错误 3｜升级材料张冠李戴 → 通用强化线冒充雪花材料线

- **错误结论**：雪花升级消耗 `ArmsUpgradeDefine.getConMust()` 返回的荣誉勋章（2/4/6…70 枚，35 级）。
- **实际情况**：主武器有**两条独立养成线**：
  1. **强化线**：`ConArmsUpgradeUI` + `getConMust(strengLevel+1)`，消耗**荣誉勋章**（justice_badge），强化等级上限 35；
  2. **形态线**（2013→2014→2026）：`ArmsResearchUI` 读各形态自己的 `mustItems`——升入 2014 消耗 **`xuehua_num450`（雪花×450）**，升入 2026 消耗 **`xuehua_num900`（雪花×900，2026-09-19 定稿并已导入）**。
- **根因**：只找到 getConMust 一条消费路径就当唯一路径，未按"UI → 消费函数 → 数据来源"追链到 `ArmsResearchUI:985`（`d0.mustItems`）。
- **修正**：材料消耗必须定位到具体 UI 与消费代码，区分"强化线"与"形态线"。

### 错误 4｜commonLevel 语义误解 → 提议 130 会让武器变强

- **错误结论**：为体现 2026 是升级版，提议 `commonLevel=130`。
- **实际情况**：配置 `commonLevel` 是**保底值（装备等级口径）**，不是终值；运行时有效等级 = max(配置值, 玩家等级+成长+1)，**DPS = getDpsByLevel(有效等级)** 查表——DPS 与武器实际等级绑定（用户记忆正确）。130 会让 2026 的 DPS 曲线整体高于 2014，违背"除贴图/开火帧外全部与 2014 相同"。
- **根因**：只看字段名与数值大小，未读 `fleshData()` 的运行时赋值逻辑，不知道字段是"终值"还是"公式输入"。
- **修正**：数值字段改动前，先读运行时赋值/重算代码，确认语义。

## 二、查证方法清单（正确做法，后续调研照此执行）

1. **全量普查优先**：解析配置块先统计**全部**标签及出现次数，再定向提取；"字段不存在"必须以全量普查为证。
2. **内部名反查**：SWF/配置的内部英文名，一律到物品表/符号表反查中文显示名；禁止直译命名。
3. **数值字段读语义**：改任何数值前，读该字段在代码中的运行时赋值与重算逻辑（如 `fleshData()`），确认它是终值、保底值还是公式输入，以及是否影响查表（DPS/伤害曲线）。
4. **材料追链**：升级/合成材料按"面板按钮 → UI 类 → 消费函数 → 数据字段"四步追链，区分并行养成线（强化线/形态线）。
5. **实机数据优先**：玩家面板截图（武器等级 165、原生成长+15 等）与代码推演冲突时，以实机为准，回查代码找差异原因，而不是坚持推演。
6. **结论分级表述**：向用户汇报时区分"已证实（附证据）/ 推断（附依据）/ 未查"，未查的明确说未查。
