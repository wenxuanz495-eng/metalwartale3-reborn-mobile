# 辉光碎屑层分离导出与画师素材交接规范

> 整理日期：2026-09-12
> 定位：当某武器需要**新做/重做蓄力辉光（闪屑）层**时——从"从 SWF 里把本体与辉光分离导出"到"给画师的素材包标准"到"成品回收入库"的完整规范。
> 实证案例：守望者家族（lightningBall）LV1~LV3 闪屑分离 + LV4/LV5 扩展尝试与撤销，全程记录见 `../..\副武器家族\守望者家族（球状闪电发射器）`。
> 相关方法论：`武器视觉效果构成元素键须知-20260908.md`（A1/A2 层归属）、`火神炮修改与武器导入经验总览-20260905.md`（导入管线）。

## 一、先懂机制：辉光层的真实身份（动手前必读）

1. **它不是独立的图片文件**，而是本体时间轴 depth2 上的一个精灵，内含**一张矢量碎屑形状**（DefineShape，非位图）。平时"看不到图"是因为它藏在 SWF 里、且只在开火动画期间以低透明度脉冲显示。
2. **它是每级专属美术**：闪屑形状的尺寸与亮点位逐级匹配该级枪体（守望者实证：LV1 32×14 / LV2 55×15 / LV3 65×21）。**跨级套用必然形状不贴合**——LV4/LV5 若要补，必须新捏专属形状（守望者撤销实证）。
3. **驱动方式**：放置于 f0（alpha=0 起始），f1~f11 逐帧 ColorTransform 改 alpha（典型脉冲：47%→80%→隐(ADD)→80%→47%→隐→…），无位移无旋转。alpha/blend 逐帧值可直接从旧层克隆。
4. **实机观感折损三件套**（对比图与实机感受不一致时的解释）：①播放仅 0.37s（playOnce 12 帧）；②挂载遮罩 `MaskArmsImage` ±30px 横带裁剪辉光超出轮廓的部分；③场景内武器尺寸小。FFDec 静态导出是无遮罩全尺寸渲染，**视觉上天然夸大**，给用户看图时必须注明。
5. **勿混淆**：闪屑层（A2 类，位于本体 depth2，随本体播放）≠ 子弹拖尾/命中特效（A3/A5，独立精灵）。命中特效另有 `motion_hit_effect` 类命名陷阱与随机后缀机制。

## 二、分离导出流程（程序侧，只读操作）

```text
① swf2xml 转储 → 定位本体时间轴（imgLabel 对应精灵）
② 逐帧放置明细：depth2 = 辉光层（LV1~3 型），depth4/2 = 蓄力火焰精灵，name= 的 = 挂点
③ 辉光独立导出：FFDec -format sprite:png -selectid <辉光精灵ID> → 透明 PNG
④ 本体待机导出：f1 帧 PNG（1:1 像素，无缩放）
⑤ 泛光位置实测：bbox( 峰值帧 − 待机帧 ) = 闪屑在本体画布上的落点（比读矩阵更可靠，
   因为矩阵 translate 是形状原点、还需叠加形状自身几何偏移）
⑥ 合成预览：峰值帧放大 + 红框标注落点
```

守望者实测落点示例（画布宽的 36%~47%，纵向居中偏上，覆盖枪体后段能量罐区域）：

| 级别 | 画布 | 落点左上角 | 闪屑尺寸 |
|---|---|---|---|
| LV1 | 108×42 | (5, 3) | 42×24 |
| LV2 | 139×48 | (1, 8) | 64×25 |
| LV3 | 159×54 | (1, 5) | 74×31 |

## 三、画师素材交接包标准（六件套）

1. **参考组**（已有辉光的级别，每级三件）：
   - `LV?_武器本体_待机.png`（落点基准）
   - `LV?_辉光碎屑层_单独.png`（辉光本体的样子，透明背景）
   - `LV?_合成定位预览_Nx.png`（合成态+红框落点）
2. **创作目标**：待补辉光的**枪体待机 PNG**（画布尺寸即交付画布尺寸）
3. **泛光位置坐标表**（如上示例；同时给出"占枪长百分比"的规律）
4. **风格规范**（以真实导出图取色+构成说明）：
   - 离散碎点，**不要柔光团/不要整枪剪影**；
   - 三类元素：青色高光对（对应枪体青色灯珠）、白色闪点（装甲反光位）、黄色斜纹 dither 补丁（对应黄色部件）；
   - 位置与枪体亮部部件一一对应。
5. **动画节奏说明**（画师可忽略，但写明"只需交付一张静态图，闪烁由程序实现"可大幅降低交付成本）
6. **交付要求**：每级一张透明 PNG，画布=枪体尺寸，碎屑绘制在落点上，**不合并枪体、不加半透明底板**

## 四、成品回收入库管线

```text
画师 PNG → 插入资源 SWF 为新位图+形状（或矢量形状，沿 plasma/聚能轰击炮先例）
→ 挂到目标本体时间轴 depth2（原蓄力精灵如在 depth2 则移 depth4 保持叠放：本体<辉光<蓄力）
→ f0 放置（alpha=0）+ f1~f11 逐帧 CT 克隆既有脉冲表
→ xml2swf → 回读断言（帧数/放置数/悬空引用/导出名）→ 逐帧渲染比对
→ 三处同步 + manifest + 构建 + 双自检 → 归档总结（含撤销/放弃也须记录）
```

## 五、关联测量经验（同族案例沉淀）

- **音效时序**：开火音效若为周期长音层（守望者实测 1.924s ≈ attackGap），则"音效先响"与"火光后现"的脱节是**时长不对等**而非起始帧错位；起始帧可整体平移对齐火焰首帧（StartSoundTag 挪帧，纯位置移动零风险）。
- **死帧感知**：无闪屑层的级别（f2~f4 差异 0px）会放大"音效响了画面没动静"的感受；有闪屑微光的级别感知较弱——评估"要不要补辉光"时应量化逐帧差异（峰值帧 − 待机帧的像素差）。
- **子弹遮挡火焰**：shootPoint 与火焰亮核重合是几何固有（三版一致）；解法优先移动 shootPoint（局部可逆），不动引擎 z 序。
- **每像素级证据优先**：凡"渲染图与实机感受不符"，先查 FFDec 渲染特性（无遮罩/全尺寸/调色板）与挂点标记等已知误导源，再下结论（电磁炮家族两次修订教训）。
