# 磁轨炮家族（magneticTrack，磁轨炮）工作总结——计划·任务·流程·具体经过

> 总入口日期：2026-09-12（主武器第十八家族）
> 当前状态：✅ **任务完成收口**——蓄力特效回迁＋射点三轮实机微调全部入库（arms1100=E108B33B），用户确认完成。
> 全流程：立项建档 → 引入 4.0 三版本对比 → 错位证实 → 口径决策 → 蓄力回迁 → 射点三轮微调 → 归档提交。

## 一、任务缘起与指令边界

2026-09-11 用户指认新主武器家族：LV1 形态名**恐惧镰刀**（口述"磁轨炮"，`arms id="magneticTrack"`，index=15）。指令边界：

1. 先定位、建档、建立初步认识，不做对比不做修改；
2. 随后引入关键情报：**存在原版 4.0 版本**（`原版\4.0（原版参考）\`），4.0 新增 3 个基础形态，且 **3.4 的两个基础形态实际上是 4.0 的第四、第五形态**——存在形态错位；
3. 对比三个版本（3.4 / 4.0 / 当前 GitHub），用户决策映射：**新版 LV1~LV3 ← 4.0 LV1~LV3；新版 LV4/LV5 ← 3.4 LV1/LV2**；
4. 特效口径：**开火枪口火焰留在新版；蓄力特效回老版**；
5. 数值口径：**战斗力相关数值、材料、价格、等级一律维持新版**（attackGap=0、recoilValue=4、reduceRa=0.7、hurt、材料/价格档位、commonLevel 90~140 等全部不动）。

## 二、定位与初步认识（2026-09-11）

- 三方配置定位：3.4＝`12_arms61_xml`（index=15，2 形态）；当前版＝`2_EmbedXml_xmlClass3`（5 形态）；素材在 `arms1100.swf`（当前）/`arms52.swf`（3.4）。
- 形态：3.4 仅恐惧镰刀（LV1）/恐惧先驱（LV2，共用 lv1_bullet）；当前版五形态（+炼狱使者/噬魂之指/灾变巨刃，LV2 起独立弹），commonLevel 90/110/120/130/140。
- 受击 `bullet/blue_motion`（两版一致）；无 smokeImgLabel、无 imgLoopTime；attackType=motion、specialProperty=穿透。
- 候选差异（后经穷尽补查证实）：attackGap 0.1→0、recoilValue 1→4。

## 三、三版本对比（2026-09-12，详见《磁轨炮家族3.4-4.0-当前版对比总结-20260912.md》）

- **4.0 参考**：`4.0游戏\embedded-xml\15_arms61_xml`（文件名哈希与 3.4 相同但**内容不同**，SHA16 2b05471b vs 2cb17554）；武器资源在 `arms400.swf`（4.0 改了分包命名）。
- **错位证实（像素级 0 误差）**：4.0 LV4/LV5 的挂点矩阵（basePoint 342,462／shootPoint 2219,457）、本体位图尺寸（101×43/103×43）与 3.4 LV1/LV2 完全一致；三方位图逐张比对 **0.000%**——"3.4 两基础形态＝4.0 的四五形态"成立。
- **本体位图结论**：当前版 lv1~lv5 全部帧位图与对应原版全等——**本体美术无需迁移**。
- **结构差异（真正要回迁的点）**：老版 5 帧"四辉光"编舞（f2 开火本体+flashA 蓄力大辉光 117×77+flashB 56×53+音 → f3 移A+flashC 炮口辉光 84×63 → f4 移B/C+回待机+flashD 尾段辉光 76×63 → f5 移D）；当前版被简化为 3 帧"单辉光"（仅 flashD，且与斯巴达 arc 共用同一张图，三方像素一致）。
- **异常发现**：4.0 lv5 的 f2 开火本体 shape38 误引 87×27 位图（bitmap37，lv2 尺寸）——4.0 打包错位；回迁/复刻时 lv5 f2 以 3.4/当前版 103×43 为准。
- **其他三版差异**：子弹（3.4=4.0 79×40 vs 当前 300×46 bitmap542 派生体系，5 颗弹三种裁剪/缩放）；受击音（4.0 #57 2288B ≠ 3.4/GH #55 1352B）；开火音三版全同（MD5 ca5c834ce10a）。

## 四、穷尽补查（响应"还有其他区别吗"）

逐级逐字段对撞三方配置，新增发现：`reduceRa` 0.4→0.7（能量需求系数）；`mustItems`/`price` 档位不同；`bulletImgLabel` LV2~5 共用→独立；类桩核查——当前版 10 类全齐（lv1~lv5＋五弹）、3.4 仅 3 类、4.0 仅 6 类，无迁移障碍。3.4 LV1/LV2 vs 4.0 LV4/LV5 除槽位元数据外视觉字段完全一致。除此之外无任何隐藏差异。

## 八、经验沉淀

1. **错位家族的标准处理**：先按"位图尺寸＋挂点矩阵＋位图像素"三重证据建立槽位映射，再按用户决策落位；名称不随美术移动时（4.0 惯性）尤其要警惕"同名不同形"。
2. **多原版版本（2.5/3.4/4.0）并存后，对比前先确认文件同名不同容**（4.0 的 arms61_xml 与 3.4 同名但内容不同）。
3. **"缺特效/盖住"类问题先测量再动手**：位图逐列 alpha 实测可见起点、挂点/弹体矩阵换算（twips÷20）、层级关系（bulletL＞heroL），三个数字定方案。
4. **弹体锚点常见陷阱**：美术矩形左缘 ≠ 可见起点（透明渐隐边距可达上百像素）；FFDec XML translateX 单位是 twips。
5. **时间轴插入用"元素身份"定位锚点**，禁止使用插入前缓存的索引（本任务首轮 bug 根因）。
6. **并行会话风险**：共享索引文档（两级/三级 README、变更档案）曾被并行会话以旧基线覆盖两次，重放登记后本次提交前再次核对——多会话并行期间，共享文档提交前务必以工作区现文为准重新校锚。
