## 三、资源层差异（依赖闭包逐 Character 比对）

十个导出（5 本体 + 5 子弹）**全部存在差异**，这是与 wave 家族（仅 3 处微差）最大的不同。

### 1. 本体（etcg_lv1~lv5，每级 16 个 Character）

- **时间轴帧数不同**：GitHub 本体 Sprite 为 **3 帧**，2.5 为 **4 帧**。逐帧放置结构：
  - 帧1：基体形状 + 枪口闪光 Sprite（双深度放置），两版一致；
  - 帧2：开火帧（更换炮体形状 + 三层开火特效 + StartSound），两版一致；
  - **差异在收尾**：2.5 的开火特效多停留一帧（帧3 空持有，帧4 才清除），GitHub 在帧3 即清除——**2.5 的开火特效画面停留时间约为 GitHub 的 2 倍**。
- **开火特效层形状内部坐标偏移**（char796 vs 351）：同一尺寸（560×580 twips）的特效形状，GitHub 的内容比 2.5 整体偏移约 (-127, -344) twips（即约 12.7、34.4 像素的上左偏移），放置矩阵两侧均为单位阵。
- **枪口闪光描边色**：与 wave 家族完全同款的共享差异——闪光形状（GitHub 19 / 2.5 3）描边 GitHub 白色不透明 `RGBA(255,255,255,255)`，2.5 半透明黑 `RGBA(0,0,0,128)`。
- **lv5（恒灭）开火帧放置差异为视觉无效项（2026-09-06 修正）**：GitHub 开火帧在深度1额外放置的形状 1245，经单 Character 归一化比对，**内容与基体 1243 完全相同**（也与 2.5 基体 355 相同）——即恒灭在两版中开火时炮体图形都**不发生变化**，该差异只是结构冗余（GitHub 重复放置了同一张图），非视觉差异。lv1~lv4 则两版行为一致：开火帧都换上同一张"开火形态"炮体图（GitHub 1260 与 2.5 的 370 内容相同，且不同于基体）。

### 2. 开火音效：零差异

五级共用一颗音效：GitHub `1240` vs 2.5 `352`，**字节级完全相同**（MP3，35142 采样，7074 字节）。StartSound 触发位置一致（开火帧）。GitHub 中该音效同时被 `induction_lv1~lv4`（感应炮）共享，2.5 中同样多级共用——共享关系两版对等，无回迁风险也无回迁价值。

### 3. 子弹：蓝红闪烁机制两版一致，仅图片尺寸不同

**闪烁动态（2026-09-06 补充，用户重点关注项）：两版完全一致。** 全部五级的子弹在两版中都是 **2 帧交替闪烁**：帧1 放置蓝 Halo 图、帧2 放置红 Halo 图，循环播放。像素采样确认两版同色同位：

| 帧 | 图 | 颜色（像素采样） |
|---|---|---|
| 帧1 | GitHub 1218 / 2.5 各级对应图 | 白芯 + **蓝色**辉光 `RGB(0,47~78,255)` |
| 帧2 | GitHub 1220 / 2.5 各级对应图 | 白芯 + **红色**辉光 `RGB(255,6~21,0)` |

2.5 的 lv4/lv5 位图（13/323）与 GitHub 统一用的位图（1218/1220）**同尺寸同色值**（即同一张图）。闪烁的节奏、颜色、帧序无任何差异。

差异仅在**图片尺寸**：GitHub lv1~lv5 统一用大图（82×45 + 86×48，即 2.5 lv4/lv5 的尺寸）；2.5 逐级增大：

| 等级 | 2.5 位图 | GitHub 位图 |
|---|---|---|
| lv1 毁灭 | 52×29 + 56×33 | 82×45 + 86×48 |
| lv2 湮灭 | 62×34 + 66×38 | 82×45 + 86×48 |
| lv3 绝灭 | 72×39 + 76×42 | 82×45 + 86×48 |
| lv4 幻灭 | 82×45 + 86×48 | 一致 |
| lv5 恒灭 | 82×45 + 86×48 | 一致 |

即：**2.5 的子弹随等级逐渐变大（lv1 只有 GitHub 的约 40% 面积），GitHub 从 lv1 起就是最大号**。另有细节：GitHub lv3 子弹根 Sprite 带 0.9 缩放矩阵（2.5 为单位阵，视觉约再缩小 10%）；2.5 lv5 子弹注册点偏移 (-920,-530)、形状外框明显更大（1907×1047 vs 860×450）。

### 4. 受击特效：两版完全不同的体系

- **GitHub**：`bullet/purple_motion`（bullet.swf Character 58，8 Character 闭包：3 张位图 59×58 / 70×43 / 99×55 + 3 形状 + 自带音效）。位图主色白芯 + **紫色辉光** `RGBA(255,69,255)`。
- **2.5**：`sub/motion_hit_effect`，运行时展开为 `_1`~`_4` 四个静态变体（sub37 Character 1697/1702/1707/1711），与小黄豆、火神炮共用同一组公共受击特效。
- **重要事实**：GitHub sub1130 里虽然也有 `motion_hit_effect_1~4`（Character 1466/1470/1474/1477），但**内容与 2.5 不一致**（每个变体 GitHub 4 个 Character vs 2.5 五个；Sprite 2 帧 vs 3 帧；内嵌音效数据不同）——不同于 energy_hit_effect（内容一致）。即若将来想把 etcg 改回 2.5 蓝白公共受击特效，**不能只改配置标签**，还需把 2.5 的四个变体导入 sub1130（会与现有 GitHub 版变体共存或替换，需另行设计）；且该特效同时关联小黄豆/火神炮家族的历史决定（soya 已改回 yellow_motion，fireFairy 保留 sub 调用）。
- `purple_motion` 在 2.5 的 arms_34 / sub37 中均不存在，是 3.4/11.3 一脉新增的资源。
