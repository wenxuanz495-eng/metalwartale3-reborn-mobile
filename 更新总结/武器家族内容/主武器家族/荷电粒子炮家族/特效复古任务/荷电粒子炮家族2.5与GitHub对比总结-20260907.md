### 4.4 开火瞬间的光效成分逐层解析（2026-09-07 补充详查）

以 LV4/LV5 本体时间轴帧 2（开火帧）为对象，逐放置项解析（ElementTree 展开 subTags + 滤镜参数）：

| 层 | 2.5 (arms_34) | GitHub (arms1100) | 内容 |
|---|---|---|---|
| 本体点亮版 | LV4=#262（83×29）；**LV5 无此层** | LV4=#1125、LV5=#1115（84×30） | 整支炮的"点亮"重绘版，帧 2 临时替换本体 |
| **细线菱形方框** | sprite #254 → 矢量形状 **#253**（11×11 空心方，StraightEdgeRecord 矢量线段） | sprite #1117 → **#1116**（同尺寸同画法） | 即游戏中"菱形细线方框"的生成项 |
| 炮口光斑 | #256（29×28 紫白光斑，位于 x74~103 炮口端） | #1119（像素级同源） | 炮口的紫色光晕 |
| 开火音效 | StartSound #257 | StartSound #1120 | 音频一致（见 4.5） |

**细线方框的完整生成方式**（两版逐位一致）：

```text
放置矩阵：scaleX=scaleY=6.1035156e-05（近零），rotateSkew0=0.9387，rotateSkew1=-0.9426
          → 把 11×11 方形旋转 90° 映射为 ~10×10 菱形，落点 translate(1150,190)twips=(57.5,9.5)px
混合模式：blendMode=8（ADD，加法发光）
滤镜栈：  BLUR(1,1,3passes)
          → GLOW 淡青白(230,255,255) blur8.2×14.6 strength2.35 innerGlow=true
          → GLOW 粉紫(255,153,255)   blur4.3     strength2.96 3passes
          → GLOW 品红(255,0,255)     blur6.8     strength2.03
```

紫色观感完全来自滤镜颜色链（形状本身是白色细线）；innerGlow 使框内微微充盈。**它不是代码生成的**——gamefile 代码中无任何生成该框的逻辑（`MultipleImage.showGlowEffect/hideGlowEffect` 虽存在 30×30 GlowFilter 接口但无调用者）。"素材库里找不到"的原因：它是藏在 body 精灵时间轴帧 2 里的 11×11 矢量形状，且经矩阵+滤镜变换后与原始素材外观完全不同。

### 4.5 "错位"现象的定量结论

细线方框的落点固定为 (52.5, 14.5)（四形态、两版本全部相同的矩阵）。本体烘焙的银灰菱形（"底层灰光"）实测中心：

| 本体 | 银灰菱形中心 | 与框的偏移 |
|---|---|---|
| 2.5 LV4 #260 | (52.2, 10.1) | dx=0.3 → **x 方向对齐** |
| GitHub LV4 #1123 | (52.2, 10.1) | dx=0.3 → 对齐（与 2.5 逐像素一致） |
| 2.5 LV5 #252 | (60.7, 12.0) | **dx=+8.2 → 错位** |
| GitHub LV5 #1113 | (61.6, 10.5) | **dx=+9.1 → 错位** |

结论（2026-09-07 二次修正，取代本节早前的 8~9px 结论）：改用**点亮版本体内嵌位图（patternTransform 恒等，PNG 像素=形状坐标 1:1）做银白连通域分析**后，早期"偏 8~9px"系炮体顶部银白饰条污染质心所致，作废。真实情况：

| 项 | 框中心 | 菱形簇中心 | 偏移 |
|---|---|---|---|
| 2.5 LV5 本体 #252 | (52.5, 14.5) | (53.2, 15.6) | ≈1.3px |
| GitHub LV5 待机 #1113 | (52.5, 14.5) | (53.2, 13.6) | ≈1.1px |
| GitHub LV5 点亮 #1115 | (52.5, 14.5) | (53.0, 14.0) | ≈0.7px |
| 2.5/GitHub LV4 点亮 #262/#1125 | (52.5, 14.5) | (51.4, 14.1) | ≈1.2px |

即：**错位确实存在但仅约 1px**（框略高于菱形中心，方向随形态略异），正常游玩不可见，逐帧+放大才可察觉——与玩家肉眼结论一致。两版本都在 1px 量级，无本质差异。另：每形态框坐标独立（2.5/GitHub 逐位一致：LV1(28.5,13.5)、LV2(36,13.5)、LV3(43.5,13.5)、LV4/LV5(52.5,14.5)），此前用 LV4/LV5 坐标套 LV1~LV3 得出的偏差结论一并作废。

### 4.6 开火音效（结论：无区别）

- 两版本体时间轴均在帧 2 触发 StartSound：2.5 五形态 → `#257`；GitHub 五形态 → `#1120`。
- 解码 PCM 比对：时长均 1.097s / 44100Hz / 立体声，Pearson 相关系数 **0.9992**，分段 RMS 一致——同一份录音，差异仅为编码级。
- **结论：开火音效两版一致，无需迁移。**

## 五、代码层

- **charged 专属开火分支两版一致**：`ArmsAttack.as` 中 `if(d.id == "charged")` —— 因 `secondBulletImg != ""`，charged 每次开火以 **60% 概率发射第二弹（secondBulletImg）、40% 发射主弹**（其他武器家族为奇偶交替规则）。GitHub `decompiled/gamefile/scripts/body/attack/ArmsAttack.as` 第 61~74 行与 2.5 代码完全相同。
- 配置 `secondBulletImg` 两版相同（lv1→bullet2、lv2→bullet3、lv3→bullet4、lv4→bullet5、lv5→bullet5），且第二弹资源三版像素一致——**开火弹幕的随机观感两版一致**。
- 无其他 charged 引用（`EnemyHeroCtrl` 的 charged_lv4 属敌方 AI 配装表，与回迁无关）。
