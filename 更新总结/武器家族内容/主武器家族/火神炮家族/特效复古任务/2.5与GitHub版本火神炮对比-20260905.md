# 2.5 与 GitHub 版本火神炮（fireFairy）对比报告

对比日期：2026-09-05
对比范围：仅 2.5 原版 ↔ GitHub 仓库当前版本，不含 3.4。
证据等级：配置差异为 A 级（文件直接取证）；资源结构差异为 B 级（结构 + 像素哈希取证，未实机验证）。

## 一、对比对象

| 侧 | 配置文件 | 资源文件 |
|---|---|---|
| 2.5 原版 | `原版\2.5（原版参考）\2.5版本素材库\raw\xml\arms_35.xml` 第 241–367 行 | `2.5版本素材库\raw\swf\arms_34.swf` |
| GitHub 版 | `decompiled\embedded-xml-assets\2_EmbedXml_xmlClass3_EmbedXml_xmlClass3.bin` 第 247–373 行 | `swf\arms1100.swf` |

两版的 fireFairy 都是 `arms index="1"`，都含 lv1–lv4 四个 `armsLevel`，主体结构完全同源。

## 二、配置层差异（逐字段）

两版完全一致的字段：

- `imgLabel`：fireFairy_lv1 / lv2 / lv3 / lv4
- `bulletSpeed`：四形态全部 30
- `shootNum`：全部 1
- `attackGap`：全部 0
- 能量、攻击属性等其余字段均未发现差异

存在差异的字段（按形态）：

| 字段 | 2.5 原版 | GitHub 版 | 说明 |
|---|---|---|---|
| lv4 名称 | 重型火神炮三连装 | 火神炮四连装 | 命名体系不同 |
| `recoilValue` | 全形态 1.1 | 2 / 2 / 2 / 3 | GitHub 后坐力更强，lv4 额外提升 |
| `angleRange` | 全形态 10 | 全形态 8 | GitHub 散布角更小 |
| `bulletImgLabel` | bullet / bullet2 / bullet3 / bullet3 | 四形态统一 fireFairy_bullet | GitHub 是此前已确认的刻意统一 |
| `hitImgLabel` | 全形态 sub/motion_hit_effect（公共受击特效） | 全形态 bullet/red_motion | 受击特效调用完全不同 |
| `commonLevel` | 5 / 8 / 16 / 27 | 8 / 11 / 19 / 30 | 获取等级整体后移 |
| `mustLevel`（lv1/lv2） | 3 / 8 | 1 / 1 | GitHub 解锁门槛更低；lv3/lv4 两版相同 |
| `mustItems` | (1,10,1) / (1,20,5) / (1,40,10) | (1,4,2) / (1,8,4) / (1,12,6) | 研发材料大幅降低 |
| `price` | 10000 / 80000 / 250000 | 5000 / 10000 / 20000 | 价格大幅降低 |

结论：数值/经济类差异是离线版刻意调整的结果；与"老特效回迁"直接相关的差异只有 `hitImgLabel`（受击特效）和子弹资源两条。

## 三、资源层对比（arms_34.swf ↔ arms1100.swf）

### 3.1 导出符号与 Character ID

两版导出相同的 7 个符号，但 ID 空间不同（迁移时必须全量重映射）：

| 导出名 | 2.5 ID | GitHub ID |
|---|---|---|
| fireFairy_lv1 | 586 | 1460 |
| fireFairy_lv2 | 576 | 1450 |
| fireFairy_lv3 | 565 | 1439 |
| fireFairy_lv4 | 554 | 1428 |
| fireFairy_bullet | 533 | 1630 |
| fireFairy_bullet2 | 539 | 1634 |
| fireFairy_bullet3 | 536 | 1632 |

### 3.2 武器本体（lv1–lv4）：高度一致，仅枪口点不同

四形态的时间轴结构逐层对齐、完全一致：

- 帧数：全部 7 帧
- 深度布局：d1 本体、d3 basePoint、d5 shootPoint、d2 开火/光效层
- basePoint 矩阵逐形态一致（lv1 330,300；lv2 310,280；lv3 230,260；lv4 220,230）
- 开火音效（StartSound）字节级一致（2.5 soundId=544 ↔ GitHub soundId=1418，soundData 相同）
- 全部 14 张位图（本体填充 + 光效）像素数据哈希逐一相同，即本体美术就是同一套图

唯一实质差异——shootPoint（枪口/出弹点）translateX：

| 形态 | 2.5 | GitHub | 偏移 |
|---|---:|---:|---:|
| lv1 | 1270 | 1490 | +220 |
| lv2 | 1080 | 1500 | +420 |
| lv3 | 1390 | 1770 | +380 |
| lv4 | 1670 | 2070 | +400 |

GitHub 的枪口点整体向炮口前方（右）移动。回迁本体特效时需要注意：若整体照搬 2.5 时间轴，会顺带把枪口点移回旧位置，影响出弹位置。

### 3.3 子弹：美术已换、不再分级、并刻意缩小

| 项目 | 2.5 原版 | GitHub 版 |
|---|---|---|
| 三个子弹导出引用的位图 | 各自独立：531(33×19)、537(35×20)、534(39×22)，Lossless2，随等级变大 | 三个导出共用同一张 1628，JPEG3 带 alpha，24×116 |
| 子弹形状边界 | 660×380 / 730×? / 780×? twips，横向圆润弹头 | 约 1601×251 twips，横向细长 |
| 放置矩阵 | 无缩放 | 统一 scaleX=scaleY=0.6666565（即此前已完成的 2/3 缩小） |

结论：GitHub 子弹美术与 2.5 完全不同源（11.3 系细长弹），且刻意统一成单一资源并缩小到 2/3。"恢复 2.5 子弹随等级增大的视觉"需要同时恢复三张独立位图和配置的分级调用，"只改大小"做不到。

### 3.4 受击特效

- 2.5：`sub/motion_hit_effect`（sub 公共资源组，运行时随机展开 `_1`–`_4` 四种静态变体）——此前已确认与小黄豆共用。
- GitHub：`bullet/red_motion`。
- 两者属于不同资源组、不同表现体系；回迁需改配置调用并确认 `sub1130.swf`/公共资源组的对应导出存在（参考 20260904 的共用关系文档）。

## 三.5 补充取证（2026-09-05 追问：枪身闪光是否被删除）

针对"2.5 开火时枪身本身有闪光、新版本是否删除"的复核结论：**未删除**。

- 本体 7 帧内 d2 层（枪身闪光/光效层，每帧一个变体）在两版均存在。
- 全部 28 个相关 Shape（本体 4 + 闪光层 24，lv1–lv4）做归一化逐字节对比（仅抹除 shapeId/bitmapId 编号差异），**28/28 完全一致**。
- 叠加此前的位图像素哈希一致、时间轴结构一致、开火音效字节一致，本体特效链路的静态证据已达 A 级：两版渲染结果必然相同（枪口点位移除外，属刻意修改）。
- 若实机感觉闪光变弱或消失，方向不在资源删除，应排查：细长弹道是否视觉遮盖闪光层、射速帧累积器是否改变动画重启节奏、以及运行时代码对动画播放的控制。

## 四、对"2.5 老特效回迁"的直接指导

1. 本体特效（枪口光效、开火帧动画）：美术与音效两版字节级同源，无需从 2.5 导入资源；GitHub 版已经是 2.5 的内容。唯一要决策的是 shootPoint 枪口点是否恢复 2.5 数值。
2. 子弹视觉：若要 2.5 效果，需从 2.5 `arms_34.swf` 导入 531/537/534 三张位图与三个子弹 Sprite，按标准流程做 Character ID 重映射，并把配置 `bulletImgLabel` 恢复为分级调用；同时决定是否保留当前 2/3 缩放。
3. 受击特效：恢复 `hitImgLabel = sub/motion_hit_effect` 只需改配置，但必须先验证当前 `sub` 资源组中 `motion_hit_effect_1–4` 导出存在且内容与 2.5 一致。
4. 迁移操作必须遵循《武器特效导入标准流程.md》：隔离目录 → 依赖闭包 → ID 全量重映射 → 回读 → 实机验证。

## 五、取证方式记录

- FFDec 26.2.1 CLI `-swf2xml` 导出两版 SWF XML。
- SymbolClass 双列表（tags/names 平行）解析导出名 → Character ID 映射。
- 时间轴按放置顺序做角色级配对，递归比较 frameCount、PlaceObject 矩阵、Shape 边界/记录数、位图引用、声音定义。
- 位图内容以 zlibBitmapData / imageData / bitmapAlphaData 属性串哈希比对；声音以 soundData 属性串直接比对。
- 注意：FFDec XML 中子标签在 `<subTags>` 下，位图尺寸属性仅 Lossless2 有 bitmapWidth/Height，JPEG3 需解析 JPEG SOF 段。
