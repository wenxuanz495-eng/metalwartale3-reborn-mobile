## 四、详细发现

### 1. 本体待机（证据等级 A）

`lightKnife_lv1` 时间轴两版均为 5 帧：第 1 帧放本体，第 2 帧进入开火表现，第 4 帧移除开火层。本体 Shape（2.5 char65 / GitHub char841）**85×23、md5 完全相同**——待机画面无差异。

枪体上及右侧的两个圆圈+十字图形为 2.5 char4 / GitHub char20 覆盖层，属坐标/作画辅助标记，不参与武器美术对比（用户已确认）。

### 2+3. 开火闪光与枪口火焰（证据等级 A 结构 / B 画面）

结构差异：

- **2.5**：第 2 帧在 depth2 放 sprite66（内部再次放置本体 char65，并带一个无音频数据块的 SoundStreamHead2，无可闻影响），在 depth4 放独立的 **32×32 圆形光球 Shape（char68）**叠加出枪口焰；第 4 帧移除这两层。
- **GitHub**：第 2 帧只放一个 **107×32 的整帧重绘 Shape（char844，"枪体+枪口焰"画在一张图里）**；第 4 帧移除。

画面对比：枪口焰位置、大小、亮度基本一致（6× 放大对比图见附件；炮口区域像素差 mean 7.69，差异仅为光球边缘的细微绘制差别）。**结论：视觉基本一致，不建议作为回迁目标**；但若日后做精细回迁，需按"独立光球叠加"结构重建。

### 4. 子弹（证据等级 A）

- 2.5 `lightKnife_lv1_bullet`（char62）：可见弹体 **114×18 px**，橙白火焰光弹，尾焰较柔。
- GitHub `lightKnife_lv1_bullet`（char838）：可见弹体 **157×23 px**，同风格但整体放大约 **1.38×宽 / 1.28×高**，白色炽心更明显。

与荷电粒子炮"主弹被重制放大 1.3 倍"属同一类 11.3 时代重制现象。`bulletSpeed` 两版均为 30，速度一致，仅子弹视觉变大。

### 5. 受击特效（证据等级 A）

- 2.5：`hitImgLabel = sub/energy_hit_effect`（sub37.swf char1692）——**蓝白色电光爆闪，6 帧**。
- GitHub：`hitImgLabel = bullet/orange_energy`（bullet.swf char120）——**橙黄色火焰溅射，4 帧**。

关键发现：**GitHub 的 `sub1130.swf` 内仍保留 `energy_hit_effect`（char1462），6 帧与 2.5 像素级完全一致（maxdiff=0）**。与荷电粒子炮家族的结论相同——若决定回迁 2.5 受击特效，只需改配置 `hitImgLabel`，零资源成本、零 SWF 修改。

### 6. 弹速/射速/后坐力

- **弹速**：`bulletSpeed` 30 = 30，一致（证据等级 A）。
- **射速**：`attackGap` 0.1 → 0.05 配置减半（证据等级 A）。但按 `ArmsAttack.as` 状态机（`gamefile\scripts\body\attack\ArmsAttack.as:326`），开火后需重新播放约 5 帧的攻击动画（INIT.FPS=30，动画约 0.167s），而两个版本的 attackGap（3 帧 / 1.5 帧）都**短于动画周期**，实际射速大概率由动画帧数卡住，两版实际射速可能并无差异。**需实机验证**（证据等级 C）。
- **后坐力**：`recoilValue` 1 → 0（证据等级 A）。代码在 `ArmsAttack.as:132` `attackBody.shake.startShake(1.5,0.2,ra-π,0,d.recoilValue)`——2.5 开火有反向震动，GitHub 完全没有。这是确认的体感差异。
