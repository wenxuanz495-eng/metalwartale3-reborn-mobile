## 五、实测反馈修正（第一轮实机测试，2026-09-08）

**实测反馈**：子弹出发点太靠后，弹体直接盖住枪体。

**根因**：`OneBulletBody` 将子弹贴图原点 (0,0) 直接钉在子弹逻辑坐标上（`img.x = mot.x0`），弹体视觉位置完全取决于 Shape 注册点。两版注册点几何差异（弹头前缘相对原点）：

| | 弹头前缘 | 弹尾后端 |
|---|---|---|
| 回迁前 GitHub 重制版（char838） | +46 px | −110 px |
| 2.5 原版（char62） | +20 px | −93 px |

2.5 美术的弹头比旧版靠后 26px，导致亮心压在枪体上。

**修正**：sprite839 的 PlaceObject2 放置矩阵加 `translateX = +520 twips（+26px）`，弹头前缘精确对齐回迁前旧版位置（+46px），且弹尾后端从旧版 −110px 收窄到 −67px，盖枪程度反而低于历史版本。仅动这一处矩阵，Shape、位图、配置均未再改。

**验证**：swf2xml 回读矩阵 `translateX=520` 已持久化；全量构建退出码 0；`build\swf\arms1100.swf` 与源文件哈希一致（`21B45EA6…`）；清单已同步；启动自检通过。

备份链：`backup\arms1100.swf.before-lightknife-bullet-20260908`（最初 1FDD 版）→ `backup\arms1100.swf.before-bullet-shift`（上轮 73B4 版）。

## 六、实测反馈修正第二轮（2026-09-08）：开火特效回 2.5 + 子弹再前移

**实测反馈**：要求开火特效回到 2.5 版本，同时子弹再往前挪、不得盖住开火特效。

**关键几何事实**（本轮实测确认的关键测量）：2.5 的开火光球（char68，32×32 径向光球）并非放在原点，其形状定义自带偏移——放置矩阵为 (0,0) 时球体落在**弹体坐标 +74.2 ~ +106.2px**（炮口前方）；2.5 原生子弹弹头在 +20px，与光球天然有 54px 间隙，互不遮挡。

**实际修改**（`swf\arms1100.swf`，合并脚本同轮执行）：

1. 2.5 开火光球 char68 以新 Character ID **1761** 导入（内容与 2.5 逐字节相同，归一化 ID 后序列化一致；此前哈希误报为行尾空白差异）。
2. sprite845 第 2 帧放置从贴图重绘版 char844 **改指 1761**，矩阵保持 (0,0)——光球精确落在 2.5 同一位置。GitHub 结构中第 2 帧本就只有一个放置对象（2.5 的 sprite66 只是重绘同一枪体+无音频块音轨，无视觉贡献），故无需复制该冗余层；帧数（5 帧）与移除时机（第 4 帧）两版本就一致。
3. 孤儿资源 char844（重绘"枪体+焰"图，改指后零引用）按家族惯例**移除**，移除前副本存于隔离区 `backup\`，git 历史亦可追溯。
4. 子弹 sprite839 放置矩阵 `translateX 520 → 800 twips`（26px → 40px）：弹头前缘 +60px，与光球左缘 +74px 保持 **14px 间隙**、与光球亮心（约 +90px 处）保持 30px 间隙——开火光球完全不被弹体覆盖；弹尾 -53px，盖枪程度继续低于历史任何版本。

**验证**：swf2xml 回读确认 frame2=char1761@(0,0)、char844 零残留、bullet tx=800、位图 1760/本体 841/845 结构未动；全量构建退出码 0；`build\swf\arms1100.swf` 与源哈希一致（`745B9BE3…`）；清单同步；启动自检通过。

## 七、开火特效"红方块"修复（第二轮实测反馈，2026-09-08）

**实测反馈**：开火特效渲染成纯红色方块。

**根因**：2.5 开火光球 char68 的两个 fillStyle 均为 `fillStyleType=65`（非平滑位图填充）——光球实际是**位图填充的 Shape**，引用 2.5 位图 char67（32×32 辉光图）。上一轮导入光球时只搬了 Shape、漏搬了它引用的位图，Flash Player 对缺失的位图填充正好渲染为纯色方块（红块）。这是"只复制 Shape 不复制位图"已知陷阱的又一次出现：**排查依赖闭包时，fillStyleType≥64 必须追查 bitmapId**。

**修复**：2.5 位图 char67 以新 Character ID **1762** 导入（32×32，数据哈希 `0cd23182e204…` 与源一致），光球 1761 的 fillStyle `bitmapId 67 → 1762`，位图定义插在光球定义之前。

**验证**：回读确认位图 1762 与源哈希一致、光球填充指向 1762；**光球 1761 独立渲染与 2.5 char68 渲染逐像素相同（32×32，max diff=0）**；全量构建退出码 0；`build\swf\arms1100.swf` 与源哈希一致（`FA0B2DDB…`）；清单同步；启动自检通过。

## 九、遗留决策

- **已定稿（2026-09-08）**：三轮实测通过（子弹位置/开火光球/红方块修复均确认），随本总结同批提交入库。
- 实测过程中确认的关键经验（供后续家族回迁复用）：
  1. 子弹/特效 Shape 若含 `fillStyleType>=64`（位图填充），依赖闭包**必须**追查 bitmapId 并一并导入，否则 Flash 缺图渲染为纯色方块；
  2. 弹体贴图的注册点原点即游戏内出生锚点（`OneBulletBody` 以 `img.x=mot.x0` 定位），跨版本搬美术时用放置矩阵 translateX 校准弹头位置最稳；
  3. 光球/特效在 Shape 定义里可自带坐标偏移（如本例 +74~106px），不能假设"放置在 (0,0) 就是贴着枪口"。
- 若后续想微调子弹出生位置：只改 sprite839 放置矩阵 translateX（每 px=20 twips），当前值 800 twips=40px。
