## 一、家族与版本背景

- **玄武 = 感应炮家族 LV4 形态**。四形态：青龙(LV1)/白虎(LV2)/朱雀(LV3)/玄武(LV4)，2.5/3.4/GitHub 三版一一对应，无 ID 错位。
- GitHub 版基于 11.3 原版基底；2.x.x（如 2.4.2）是离线版自己的版本号；2.5/3.4/11.3 均为原版。
- 双发结构（shootNum=2）+ bulletLink 子弹链接：配置恢复后每周期第 1 发为穿透激光（不可见伤害体），第 2 发为追踪爆能弹（绿色球体）。
- 双管炮：下主炮（大，shootPoint，发射爆能弹）+ 上管（小，激光出射点）。**上管口在原版从未有代码标记**，坐标需由火光位图矩阵法导出（见权威档案第三节）。

## 四、认知演进（一句话版，完整版见权威档案）

旧模型（已证伪）："激光视觉 = 本体动画里一条静态光束条（d2）；d4 是烟雾变形、也是尾焰。"
新模型（实证）："可视激光 = **生长光束（d4 变形，f2-f4，随 ratio 从 113px 长到 703px）+ 保持条（d2，f5-f6，静态全长）**两段无缝衔接；'烟雾/尾焰'均为历史误标；火光是独立的枪口焰，不是激光；伤害激光无图形，出射点由 laserPoint 决定。"
教训：**语义命名不可信，逐层展开形状实测 bounds 才算数**。

## 五、方法论沉淀（本次确立的标准流程）

1. **火光位图矩阵法**：枪口坐标 = 解析火光形状内独立火光位图（1302/412）的 FILLSTYLE 放置矩阵 + 位图亮核偏移；与 shootPoint 互验（0.7px）后可信。FFDec 矩阵 scale 20=1:1、10=半尺寸。
2. **单变量回滚实验**：视觉结构存疑时，只回滚单一资源（逐字节校验），配合慢放逐帧 A/B，一锤定音。
3. **F2 慢放逐帧分析**：30↔1fps 热键（Game.as 内联，诊断工具禁入玩家包）。
4. **三件套同动原则**：生长段/保持条/laserPoint 是一条激光的三个部件，移动必须同步，否则两段断裂。

## 六、事故与教训清单

1. 首版光束条迁移坐标错误（埋进枪体）+ 漏移生长段 → 双段断裂、接缝外露（本次最大事故，已由统一规则修复）；
2. #1069 刷屏：敌方 AAHD / 副武器 SubImage 缺 laserPoint 属性，sealed 类运行时抛错中断刷新循环（已双守卫修复）；
3. FFDec `-importScript` 不能新增类（DiagSlowMo 首版 VerifyError #1014）→ 逻辑必须内联进既有类；
4. UI 加载器修复漏登记补丁清单 → 只有 NormalAllIcon 生效的假成功（补登记 110→118）；
5. sub1130 首轮闭包漏 `bitmapId` 依赖 → 受击特效渲染红色实心块（重做补齐）；
6. 像素聚类估坐标不可靠 → 上管口偏差最多 23px，改用位图矩阵法。
