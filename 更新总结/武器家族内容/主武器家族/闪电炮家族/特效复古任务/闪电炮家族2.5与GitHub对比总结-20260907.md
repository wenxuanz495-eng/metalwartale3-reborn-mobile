## 二、形态映射

三个版本均为五形态、一一对应，**无 3.4 式 ID 错位**（不属于异端审判/普罗米修斯/星爆那类需要特殊映射的家族）：

```text
LV1 托尔   ↔ LV1 托尔   ↔ LV1 托尔
LV2 因陀罗 ↔ LV2 因陀罗 ↔ LV2 因陀罗
LV3 宙斯   ↔ LV3 宙斯   ↔ LV3 宙斯
LV4 皮卡丘 ↔ LV4 皮卡丘 ↔ LV4 皮卡丘
LV5 雷丘   ↔ LV5 雷丘   ↔ LV5 雷丘
```

注意区分：3.4 中紧随雷丘之后的「须佐」属于下一个家族 `charged`（荷电粒子炮），不是闪电炮第六形态。仓库里的 `arms id="arc"`（弧光贯通炮·斯巴达）和 sub 资源里的 `lightningBall_lv*`（xmlClass7 中敌方电球家族，含连锁闪电代码）都与玩家闪电炮无关。

### 4.2 开火音效（结论：无区别）

开火音效**嵌在本体时间轴里**，不在代码中（全部 gamefile 代码没有闪电炮开火 playSound 调用）。用 ElementTree 解析两版 arms SWF 全量 XML 的时间轴标签序列：

```text
2.5  LV1~LV5 本体（sprite 322/317/312/307/322…）：帧2 = 放置炮口焰形状(298/300) + StartSound(#301)
GitHub LV1~LV5 本体（sprite 1217/1212/1207/1202/1197）：帧2 = 放置炮口焰形状(1193/1195) + StartSound(#1196)
```

- 触发位置相同：两版都在帧 2（炮口焰出现的同一帧）触发音效。
- 音频内容相同：`arms_34.swf` Sound #301 与 `arms1100.swf` Sound #1196 经 FFDec 导出、ffmpeg 解码为 PCM 后逐样本比对，RMS 差 0.1（信号 RMS 4848.5，即零差异），时长均为 0.679 秒 / 44100Hz / 立体声。mp3 文件哈希不同只是编码元数据差异。
- **结论：开火音效两版一致，无需迁移。**

### 4.3 本体发射闪光 / 炮口火焰（结论：有区别，即本次回迁目标）

两版本体时间轴结构同构（帧1=本体静态，帧2=炮口焰+音效，其后为焰持续帧），差异全部在炮口焰的画面内容与循环长度：

| 项 | 2.5 | GitHub 当前 |
|---|---|---|
| 帧数（循环长度） | **4 帧** | **3 帧**（循环快 25%，焰消得更快） |
| 炮口焰峰值（帧 3） | 紫焰更大更亮，内容 bbox 达 (0,1,67,28)，焰体更高 | 辉光被削弱，bbox (3,4,67,25)，约 400~500px 像素差 |
| 帧 4 | 有（焰的延续帧） | **缺失** |
| 帧 1~2 | 与 GitHub 有约 170px 轻微像素差（2.5→3.4 期间本体小幅重绘；GitHub 帧 1~2 与 3.4 像素级一致） | =3.4 |

画面证据见《闪电炮本体开火帧与炮口焰_2.5与GitHub对比图-20260907.png》《闪电炮本体lv1帧3帧4_2.5与GitHub对比图-20260907.png》。

另：`recoilValue`（2.5=3，当前=6）按既有文档属于发射时武器本体的视觉后坐位移，属于纯表现层；若追求 2.5 开火观感可在执行时一并评估，本次范围决定默认不动数值。

### 4.4 受击特效（保持现状，不回迁）

| 项 | 2.5 实际调用 | GitHub 当前实际调用 |
|---|---|---|
| 配置 | `sub/boom_hit_effect` | `bullet/purple_boom` |

| 风格 | 爆炸火焰系 | 能量闪光系 |

关键事实（留存备查）：

1. GitHub `sub1130.swf` 中**已经存在** `boom_hit_effect`（#1454，7 帧）和 `boom_hit_effect2`（#1446，7 帧），但与 2.5 `sub37.swf` 同名资源**内容不同**：逐帧像素比对显示帧 1/3/5/7 相同或近似、帧 2/4/6 有内容位移与像素差异（boom_hit_effect2 的帧 2/4/6 位移尤其明显）。
2. `purple_boom` 属于 bullet.swf 的 8 色系受击组（yellow/red/orange/blue/green/blueness/pink/purple × motion/energy/boom），是 3.4/11.3 体系的产物。
3. 运行时后缀逻辑：`BulletBody.get hitImgLabel()` 只对包含 `motion_hit_effect` 的调用随机追加 `_1~_4`；`boom_hit_effect` 与 `purple_boom` 均整段直接播放（2.5 与 GitHub 代码一致）。

### 4.4 其他资源事实

- 本体/子弹 Sprite 内无 `StartSound`/声音引用，开火音效不在这些时间轴里（当前与 2.5 一致，不构成差异）。
- `lightningBall_lv1~5(+_bullet)` 位于 sub 组（sub1130 #1277~1327 / sub37 #1198~1261），供 xmlClass7 敌方电球家族使用，两边都有、与本次无关。
- 连锁闪电代码（`OneBulletBody.lightningTimer()`、`EffectGroup.lightning/lightning2/lightning3` BezierLightning）2.5 与 GitHub 均完整保留，同属电球体系。

## 五、代码层结论

- 当前版本**没有** lightning 专属代码分支（区别于 fireFairy 的帧累积射速特判），全部行为由配置驱动。
- `angleRange` 解析代码两版相同（`Number(xml0.angleRange)`），差异纯在配置。
- 迁移特效只需动：①配置 `hitImgLabel`（5 处）；②`arms1100.swf` 本体/子弹资源闭包；③如需 2.5 原版受击，`sub1130.swf` 的 `boom_hit_effect` 闭包需替换或重映射导入。若同时要还原 2.5 手感，还需评估 `recoilValue 6→3`、`angleRange 4→缺省`（是否属于"特效还原"范围需另行确认）。

## 七、回迁清单（按范围决定修订，本次未实施）

按 2026-09-07 范围决定（子弹不变、受击不变、不动数值），实际需要动的只有**本体资源一组**：

1. 从 `arms_34.swf` 导入 `lightning_lv1~5` 四帧本体闭包（含帧 3 强辉光、帧 4 延续帧、炮口焰形状 298/300），全量重映射 Character ID 后替换 arms1100 中对应资源。
2. 开火音效随闭包带上（2.5 Sound #301 与当前 #1196 音频相同，带哪个都行，建议保留当前 #1196 引用、只迁视觉层，改动最小）。
3. 配置文件（`2_EmbedXml_xmlClass3_...bin`）**无需改动**——imgLabel/子弹/受击/数值全部保持现状。
4. 资源双写：改 `swf\arms1100.swf` 后必须同步 `build\swf\arms1100.swf`，并重建 `game.swf`。
5. 全程遵循《火神炮修改与武器导入经验总览》标准链：隔离目录 → swf2xml → 依赖闭包 → ID 全量重映射 → xml2swf → 回读 → dumpSWF → 测试包独立运行 → 实机验证 → 同步正式源文件。
