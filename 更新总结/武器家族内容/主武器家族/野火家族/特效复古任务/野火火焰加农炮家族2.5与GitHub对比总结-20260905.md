# 野火（火焰加农炮）家族 2.5 与 GitHub 版对比总结

> 核查日期：2026-09-05
> 用途：记录火焰加农炮家族（初始形态"野火"）在 2.5 原版与当前 GitHub 版之间的全部差异，作为后续老特效迁移的依据。
> 证据等级：本文所有结论均达到 A 级（配置调用、实际 SWF、帧图、哈希互相印证）；尚未实机验证的项目单独标注。

## 二、配置字段对比

### 完全一致的字段

```text
name / type / attackType(boom) / hurt(40/95/123/173)
bulletNum / bulletTranslation / bulletLife(1.5) / bulletType(bullet)
bulletSpeed(25) / attackGap(0.15) / attackDelay(0)
imgLabel(cannon_lv1~4) / bulletImgLabel(arms/cannon_bullet)
```

### 存在差异的字段

| 字段 | 2.5 | GitHub | 性质 |
|---|---|---|---|
| `hitImgLabel` | `sub/boom_hit_effect` | `bullet/red_boom` | 视觉（受击特效） |
| `bulletWidth` | 6 | 10 | 配置层尺寸参数 |
| `recoilValue` | 4 | 7 | 数值/视觉（后坐力） |
| `angleRange` | 0 | 2 | 数值（射击抖动角） |
| `commonLevel` | 5/9/17/28 | 10/14/21/35 | 数值（解锁等级） |
| `mustItems` / `price` | 2.5 体系 | 1,4,2 等 / 价格不同 | 数值（合成/售价） |

迁移注意：按项目规矩，除用户明确要求外，**只还原视觉，不改伤害、速度、能量、射速、解锁等数值**。`bulletWidth`/`recoilValue`/`angleRange` 属于数值字段，还原与否需要单独确认。

## 三、弹道速度结论

- 两版本 `bulletSpeed` 均为 **25**，且 `ArmsAttack.as`、`OneArmsDefine.as` 中对 `cannon` **没有任何运行时特判**（不像火神炮有帧累积器分支）。
- 结论：**当前 GitHub 版的弹道速度就是 2.5 的速度，无需改动**（A 级）。

## 四、运行时解析机制（BulletBody）

```text
D:\superalloy\metalwartale3-reborn.git\decompiled\gamefile\scripts\body\bullet\BulletBody.as  （get hitImgLabel，约 94~101 行）
```

- 随机后缀 `_1~_4` 逻辑**只**作用于包含 `motion_hit_effect` 的调用；
- `boom_hit_effect` 与 `red_boom` 均按原名原样解析，画面变化依赖 sprite 自身时间轴轮播变体；
- 因此切回 `sub/boom_hit_effect` 不会触发后缀机制，配置层可直接生效。

## 六、开火特效与武器本体（无需迁移）

对两版 `arms` 包做了全量比对，结论：**开火表现链完全等价**。

| 比对项 | 结果 |
|---|---|
| 时间轴结构（lv1 五帧，lv2~4 各四帧；放置顺序、深度、RemoveObject 时机） | 完全一致 |
| 放置矩阵（位置/缩放/注册点） | 逐帧哈希一致 |
| 武器本体形状（四形态 body） | 像素级零差异（diffbbox None） |
| 开火火焰/闪光（每形态 fire → flash2 → 余烬 三张图，共 12 张） | 像素级零差异 |
| 开火音效（2.5 sound 504 ↔ GH sound 1387） | 字节级相同（88814 字节，44100Hz，1.01s） |

11.3 改版没有触碰火焰加农炮的开火表现，Character ID 不同（如 525↔1408）只是两文件的编号体系，内容等价。

## 七、需要迁移的差异项

### 1. 受击特效（核心差异）

```text
2.5     sub/boom_hit_effect  → sub37.swf Character 1678：7 帧、6 个变体位图（JPEG3）+ 命中音效，完整爆炸演进（亮核→炸开→火星→余烬消散）
GitHub  bullet/red_boom      → bullet.swf Character 110：4 帧、3 变体位图 + 音效（与旧版小黄豆 yellow_motion 同体系）
GitHub  sub1130 残留 boom_hit_effect → Character 1454：7 帧、仅 3 变体位图 + 音效，约对应 2.5 的第 1/2/5 阶段
```

对比图：`D:\superalloy\tmp-cannon-restore\work\hit-variants-compare.png`（上排 2.5 六段，下排 GitHub 三段）。

关键结论：sub1130 里残留的 `boom_hit_effect` 是**被精简的同源动画**，仅改配置回 `sub/boom_hit_effect` 只能得到 3 变体效果；要 100% 还原 2.5 画面，必须按标准流程从 sub37 导入 6 变体位图闭包（JPEG3 位图 + shape + 音效，Character ID 全量重映射）。

### 2. 子弹本体图（次要差异，可选）

```text
2.5     cannon_bullet → shape 497：90×32 短焰弹
GitHub  cannon_bullet → shape 1380：198×37 长条拉丝弹（11.3 的改动）
```

对比图：`D:\superalloy\tmp-cannon-restore\work\fire-effects-compare.png` 最底行。

### 3. 配置改动（随资源迁移一并执行）

- 四个等级的 `hitImgLabel`：`bullet/red_boom` → `sub/boom_hit_effect`；
- `bulletImgLabel` 保持 `arms/cannon_bullet` 不变（资源在 arms 包内替换/新增）。
