## 三、具体经过

### 1. 只读对比（详见《斯巴达3.4与当前版对比总结-20260911.md》）

- **配置**：三个视觉字段（imgLabel/bulletImgLabel/hitImgLabel）两版一致；数值仅 `recoilValue`（3.4=1 → 当前=10）与当前独有 `penetrationB=1` 两处差异。
- **时间轴**：`arc_lv1` 两版均为 5 帧结构（f1 待机+挂点 → f2 换开火本体＋ADD 光斑层 blend=8 @(1629,300)＋StartSound → f3 保持 → f4 移除光斑 → f5 收尾），逐操作一致。
- **美术**：待机/开火本体位图、枪口光斑位图 **0.000% 像素差**；受击 `bullet/blue_energy` 两版同为 CharacterID 93（bullet.swf 整文件虽因历次死名改绑分叉，本资产完好），三帧形状与位图逐项一致；开火音（3.4 #13＝当前 #532）与受击音（#55）MD5 相同。
- **代码链**：`ArmsAttack → NewHeroCarAAHD → MoreImage.playOnce` 一致，`imgLoopTime` 两版均未设（playOnce 单闪路径）。
- **结论（证据等级 A）**：特效资产链零差异，"缺焰"静态不成立；唯一美术差异是子弹（3.4 矢量 129×44 vs 当前 225×50 大弹体，按指令保留新版）。
- 排除项：2.4.2 发行包的 arc 块同样完整（排除旧包缺资源）；arms1100 三处副本哈希一致（9B02AAF0）。

### 2. 缺焰原因定位

用户提供 3.4/当前版双实机 GIF：3.4 可见枪口焰斑，当前版只见大弹体。据此几何量化：

- **层级**：子弹加入 `gameSprite.bulletL`，战车/武器（含枪口焰）在 `heroL`，堆叠序 bulletL 恒在 heroL 之上（两版代码一致）。
- **几何**：光斑区 x 43.4~119.4（亮核中心 81.45）；子弹在射点 x=111.2 生成；弹速 30px/帧；attackGap 0.1s≈3 帧/发；光斑可见期约 2~3 帧。
- **判定**：新版弹体矩形虽后延 167px（3.4 仅 69px），生成后 3 帧内持续覆盖光斑区——**遮挡，而非资产丢失**。

### 3. 三轮矩阵调参（全部只改 sprite536 内 shape535 的 PlaceObject MATRIX，每轮 1 行 XML 差异）

| 轮次 | 参数 | 弹体 | 用户实机反馈 |
|---|---|---|---|
| v1 | scale 0.9 + translateX 3300（165px） | 202×45 | 光斑露出了，但"弹尾离枪口太远、子弹还是太大" |
| v2 | scale 0.75 + translateX 2280（114px） | 169×38 | 矩形弹尾起点对准了枪口，但实机复测"亮斑距枪口仍差 ~41px" |
| **v3（定稿）** | **scale 0.65 + translateX 1180（59px）** | **146×33** | —（待实机） |

### 4. v3 的关键转折：位图像素实测

v2 后的空隙根因：**弹体位图（bitmap534）左侧有 54 列全透明边距**——可见亮斑起点在局部 x=−108（第 59 列起 ≥3px 不透明），而非矩形左缘 −167。v2 按"矩形左缘"定位，可见亮斑被推到世界 ≈141，距枪口 41px。v3 改按**像素实测的可见起点**锚定：111.2 − 108×0.65 + 59 = **100.0，正对枪口**；实心部分 107 起（射点附近）。

> ⚠️ 勘误沉淀：过程文档曾两处误判——①把弹体矩形左缘当"弹尾起点"；②一度以为弹体带"拖尾细线"（实为亮斑渐隐透明边，用户据实纠正"该武器的子弹没有任何拖尾细线"）。**判定弹体可见边界必须做位图逐列 alpha 实测，不能拿矩形范围或语义想象代替。**

### 5. 每轮标准验证链（未省略任何一轮）

```text

→ swf2xml 回读核对矩阵值 → XML diff 确认仅 1 行变化（其余 7.4 万行零变化；对最初版的

→ 三处同步（swf\ = build\swf\ = runtime\swf\，哈希逐一核对）
→ config\build\current-resource-manifest.sha256 更新
→ scripts\launch_game.bat --check sa 通过
```

产物哈希：最初 `9B02AAF0…`（已备份）→ v1 `6CC13184…` → v2 `702A052B…` → **v3 `D1184767…`（当前）**。arms1100 的 `arc_lv1`/`arc_lv1_bullet` 导出与 ABC 类桩全程未动；碰撞判定（`bulletWidth=10`）不受矩阵影响。

## 四、本任务沉淀的经验

1. **"缺特效"先判三型**：资产缺失（查 SWF+三处副本+发行包）／驱动缺失（查 playOnce 链路）／**显示遮挡（查层级+几何）**——本例为第三型，静态资源审计"零差异"与实机"看不见"可以同时成立。
2. **遮挡量化三要素**：子弹美术相对锚点的前后延（位图 alpha 实测，不是矩形边距）× 弹速与光斑可见帧数 × bulletL/heroL 层级。
3. **矩阵级微调是观感调参的最低成本手段**：不动美术、不动碰撞、每轮 1 行差异可秒级回滚；配合"实机反馈→参数修正"闭环，三轮收敛。
4. **AI 与用户对画面的描述要互验**：AI 看导出素材，用户看实机动态；本例"弹尾对准枪口"（矩形语义）与"亮斑对准枪口"（可见像素语义）相差 41px，最终以用户实机观感为准。

## 五、遗留与待办

- **待实机确认**：v3 效果（亮斑正对枪口、光斑全程可见、弹体 146×33 观感）。
- **待用户决策**：①`recoilValue`（3.4=1 / 当前=10）是否保留；②`penetrationB=1`（当前独有穿透）是否保留；③开火音挂 f2 两版实机均不触发（挂载帧位铁律，共性非差异），是否修复（若修按铁律挪 f4 并全域核查）。
- 若观感再需微调：改 sprite536 矩阵两个数值即可（scale / translateX），成本极低。
