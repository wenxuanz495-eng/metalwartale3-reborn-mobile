## 二、实际修改（`swf\arms1100.swf`，单文件）

按金色琉璃定稿的原位替换方案：

- **来源**：2.5 `arms_34.swf` char87（DefineShape，雪花光弹轮廓）+ char86（**DefineBitsJPEG3Tag**，JPEG+alpha 位图填充，数据哈希 `1020C6D0B0FE…`）。GitHub 包内经 JPEG3 专用哈希全量比对**无同内容位图**，随 Shape 一并导入。
- **替换**：GitHub char876（DefineShape，仅被 sprite877 引用一次）内容原位替换为 2.5 char87，保留 Character ID 876 与 tag 顺序；sprite877（`SoundStreamHead2 + Place 876 + ShowFrame`）未动。
- **位图重映射**：2.5 位图 char86 以新 Character ID **1763**（原最大 ID 1762 + 1）导入，Shape 内 fillStyle `bitmapId 86 → 1763`；bitmapId 65535 为占位保持原样。位图定义插在 Shape 定义之前。
- 本体 snow_lv1（878）、snow_lv2（874）、金色琉璃新增资源（1760/1761/1762）及全部其他符号未动。

**经验应用**：本次在合并前逐个 fillStyle 检查，发现 fillStyleType=67（位图填充）并追踪到 JPEG3 位图依赖——直接规避了金色琉璃第二轮"红方块"问题。另外 DefineBitsJPEG3Tag 的数据在 `imageData`+`bitmapAlphaData` 属性（非 `zlibBitmapData`），查重脚本已按类型区分。

**影响范围提示**：`bulletImgLabel` 为 `arms/snow_lv1_bullet`，为 **2013 与 2014 两个形态共用**——本次替换后 2014 的子弹外观同步恢复为 2.5 美术（2014 无老版本参照，属预期连带效果）。

## 五、【追加】2014/2013 弹药区分（2026-09-08 第二轮）

**问题**：`bulletImgLabel = arms/snow_lv1_bullet` 为 2013/2014 共用，第一轮回迁后 2014 也变成了 2.5 小弹。用户要求：**2013 保持 2.5 老弹，2014 恢复新版大弹**。

**方案选型**：给 2014 新增导出名不可行——本项目已验证 AS3 SWF 追加 SymbolClass 名字无 ABC 类桩会被 Flash 丢弃（相转移炮家族教训），必须**死名改绑**。经全域扫描（全部配置 bins + 全部脚本 + 存档 + `_bullet` 动态拼接规则）：

- `arms1100.swf`：340 个导出名**全部被引用**，无死名（第一轮扫描的 3 个"死名"系漏查 xmlClass9 敌人武器数据的假阴性：coinSpace_bullet、Charger_bullet_1/2 均被大量引用）；
- `sub1130.swf`：motion_hit_effect_1~4 是运行时随机后缀变体（正被小黄豆/火神炮使用）、`positron_hit_effect`/`laser_lv1_bullet0`/`goldflyBlade_bullet2` 等存在动态拼接风险——均排除；
- **`bullet.swf` 的 `orange_motion`（sprite 121）**：全域零引用（bullet.swf 为纯资源包无代码，消费方仅主配置/主脚本），且 `bullet/orange_motion`（20 字符）与 `arms/snow_lv1_bullet`（20 字符）**等长**——选定。

**实际修改**：

1. `swf\bullet.swf`：把改前版本（`FA0B2DDB` 版 arms1100 的 char876 + 位图 875，即用户提供的 `超合金素材汇总\主武器11.0\images\875.png` 对应素材，包内原件未失）复制进来——位图 875→新 ID **122**（DefineBitsLossless2，154×43，哈希 `5D63CCAB…` 一致）、放大 Shape→新 ID **123**（fill 875→122）、新 sprite ID **124**（Place 123 @0,0）；SymbolClass 将 `orange_motion` 从 121 **改绑到 124**（类桩现成）。原 sprite 121 与其余资源未动。
2. 配置 bin（`xmlClass3`，等长替换，417816 字节不变）：**仅 2014 形态**的 `bulletImgLabel`：`arms/snow_lv1_bullet` → `bullet/orange_motion`（行 5299）；2013 保持 `arms/snow_lv1_bullet`（行 5256）。
3. `current-resource-manifest.sha256`：bullet.swf 哈希更新为 `6E4FF760…`。

**跨组子弹先例**：`bulletImgLabel` 使用非 arms/ 前缀已有大量先例（`sub/flyBlade_bullet`、`sub/banger_lv1_bullet`、`car/jump_bullet` 等）；`getResource` 按 label 前缀 `split("/")[0]` 解析资源组（`SWFLoaderManager.as:184-188`），`bullet/` 组已被 hitImgLabel（如 blue_boom）稳定使用。

**验证**：回读确认 orange_motion→124、链路 124→123→122 完整、位图 122 与 arms1100 位图 875 哈希一致、bullet.swf 自有 snow_lv1_bullet(43) 未动；**orange_motion 渲染与改前大弹 154×43 逐像素相同（max diff=0）**；全量构建退出码 0；`build\swf\bullet.swf` 与源一致；game.swf 内嵌配置确认 2013→arms 小弹 / 2014→bullet/orange_motion；启动自检通过。
