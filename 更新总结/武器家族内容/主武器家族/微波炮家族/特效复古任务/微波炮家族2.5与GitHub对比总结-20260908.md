> 指定武器：微波炮家族（`arms index="13" id="microwave"`）。按用户指定对比 2.5、离线版 2.4.2、GitHub 当前版（3.4 未在本轮范围）。

## ⭐ 最终结论（2026-09-08 定稿，用户确认）

**该武器不需要任何修改，本身已经极为优秀。**

- 核心行为两版一致：激光与精灵弹交替、均穿透（激光打一排）、伤害公式一致、无散射、弹速一致。
- 用户决策：受击特效、子弹保持现状不回迁；激光打一排特性经复核本就存在（`penetrationB=1` 三处复核通过）。
- 与 2.5 的差异（后坐力 2→3、能耗 0.5→0.7、开火态表现现代化、动画变长）属新版整体演化结果，不构成回迁必要项。
- **本轮零代码改动**；全部回迁候选项关闭。

## 四、视觉对比（证据等级 A，除注明外）

### 1. 本体待机与开火时间轴

- 2.5 三形态统一 **4 帧**：F1 待机体+basePoint+shootPoint → F2 开火体+枪口焰A+双开火音效 → F3 枪口焰B → F4 回待机/清理。
- GitHub lv1/2/3/5 为 **6 帧**、lv4 为 **7 帧**：在"回待机"之后多出 **3 帧枪口余光衰减**（焰C/D/E 依次变短变淡），lv4 另有清理帧。
- 待机体美术：对应形态同源（见第二节像素差）；lv4/lv5 与 2.5 逐像素相同。
- **开火时武器本体表现（追问补查，2026-09-08）**：
  - 2.5 lv1/lv2：开火帧换**矢量重绘的加长开火体**（Shape2，_bounds 更长更高，炮口延伸）；lv3：开火体=待机体原样（1 帧 sprite 包裹）+ 位移 @-60,20。
  - GitHub lv1/lv2/lv3/lv4：开火帧换**同尺寸高亮位图变体**（986↔988、971↔973、966↔968、951↔953，整体泛白如火光照亮）；lv5：与 2.5 lv3 同款——开火体=待机体 + 位移 @-60,20。
  - **结论：对应形态的开火态"不一致"**——2.5 用矢量加长炮体表达开火，当今用高亮变体（lv1-4）或纯位移（lv5），机制与画风都不同；仅 lv5 保留了 2.5 lv3 的位移式。
- 枪口火光（光带）：两版均为长条光带形态（微波束风格，即"激光线"的可视部分）。2.5 焰A/B 为 992×43（品红/粉紫主调、蓝紫变体，lv3 另有 44×36 橙红短焰）；GitHub 为 1248~1252×41~74（金橙+粉紫双色，约 1.26 倍更长）并带 **3 帧余焰衰减拖尾**（2.5 无）；GitHub lv3/lv4 共用同一组焰层（P956/P958）。
- shootPoint：2.5 lv1 (2269,260)、lv2/lv3 (2209,260)；GitHub lv1 (1589,280)、lv2 (1780,210)、lv3 (2209,260)、lv4 (2209,300)、lv5 (2209,340)——对应形态 lv3 射点与 2.5 lv1 相同，lv4/lv5 射点下移。

### 1b. 激光线机制（追问补查，2026-09-08）

微波炮每攻击周期两发交替（`shootNum=2`、`bulletLink.index=1`）：第 1 发**精灵弹**（橙色环，bullet 型，有贴图有伤害），第 2 发**激光**（`microwave_1` 定义，`bulletType=laser`）。

- **激光线本体**：`microwave_1` 无 `imgLabel` → `LaserBody(false)`，**无贴图**；屏幕上那条激光线**就是武器开火帧里的长条光带 Shape**（2.5 992px / GitHub ~1250px，位图填充的 Shape，非纯矢量绘制）。
- **激光是否有伤害**：两版**都有伤害**（`microwave_1.hurt=33`，两版同值），由 `BodyGroupHit.as` 判定：
  - 两版 `microwave_1` 均为 `penetrationB=1`（2026-09-08 更正：此前误报当今已移除，系首轮 grep 模式漏字段；源 bin、2.4.2 bin、build/game.swf 三处已逐一复核）→ 走"线-矩形求交"分支，`hitRectLine2/hitRectArrLine2`，**命中线上所有敌人**，每个交点各结算一次伤害并各自播放受击特效；
  - 非穿透分支（`penetrationB=0` 时的"射线首中"逻辑）两版代码都在，但微波炮两版都未走到该分支。
  - 即：**两版激光都是穿透打一排，行为一致**（伤害公式本身也一致）。
- 代码对照：2.5 与 GitHub 的 `BodyGroupHit.as` 激光两分支结构完全一致，GitHub 仅在穿透分支新增等离子护盾特判（`hitCircleLine`）。
- 附注：非穿透激光分支还会把武器 `img.arms.length` 设为 1000（光带拉长逻辑），说明光带长度由代码与时间轴共同决定。

### 2. 子弹（第 1 发精灵弹）

- 2.5：**每形态独立子弹**——lv1 为位图环（48×74，橙红色调），lv2/lv3 为矢量 Shape2。
- GitHub：五个 `microwave_lvX_bullet` 导出**共用同一张位图**（char926，45×81，金黄色调）。
- 视觉：同为竖向能量环/椭圆风格，2.5 偏橙红、当今偏金黄；尺寸接近（未出现其他家族 1.3~1.5 倍放大重制现象，宽略窄、高略高）。

### 3. 受击特效

- 2.5：`sub/energy_hit_effect`——**青蓝色能量电光爆炸，6 帧**（爆炸光球→电光飞溅→拖尾消散），带受击音效。
- GitHub 第 1 发弹命中：`bullet/orange_energy`——**橙红火焰型，4 帧**；激光命中：`bullet/yellow_energy`——**黄白电光型，4 帧**（两者结构相同仅配色不同，共用音效 Snd55）。
- **GitHub `sub1130.swf` 内的 energy_hit_effect 与 2.5 六帧全部逐字节相同**（49×49→90×59）——老受击特效在当前版资源库完整存在，回迁仅需改配置调用（零资源成本，与光刃炮家族先例一致）。

### 4. 音效

- 开火音效：两版各 2 条，数据长度相同（3124/5828 字节）但内容不同——疑似同段音效再封装或改版重录，**需试听确认**（证据 C）。
- 受击音效：2.5 energy_hit_effect 帧2 挂 Snd1683；GitHub sub1130 对应帧挂 Snd1522；orange/yellow_energy 共用 Snd55。

## 五、数值行为备注

1. **射速**：两版 `attackGap=0`、`shootNum=2` 一致，实际射速由本体动画帧数门控（同 2013 家族结论）。按帧数推算（30FPS）：**2.5 每周期 4 帧 ≈ 15 发/秒；GitHub lv1/2/3/5 每周期 6 帧 ≈ 10 发/秒、lv4 7 帧 ≈ 8.6 发/秒**——当今版因动画变长实际射速约降至 2.5 的 2/3~4/7。**需实机计时验证**（证据 C）。
2. **分散程度**：`bulletNum=1`、`angleRange=0`，两版均无散射，一致。
3. **弹速**：精灵弹 `bulletSpeed=35` 一致；激光为即时判定（`bulletLife=0.001`）两版一致。
4. **穿透**：武器级精灵弹与 `microwave_1` 激光**两版均穿透**（`penetrationB=1`，激光打一排行为一致——2026-09-08 更正，详见 1b 节）。
5. **后坐力**：2→3，当今开火震动更强（代码路径 `ArmsAttack.as` startShake）。
6. **能耗**：`reduceRa` 0.5→0.7，每发能耗 +40%。
