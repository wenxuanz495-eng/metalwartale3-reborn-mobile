# 守望者家族回迁工作流程总结

> 日期：2026-09-09
> 定位：以守望者家族（lightningBall，球状闪电发射器）为完整案例，沉淀副武器家族从立项到提交的**标准工作流程**。后续副武器家族（乃至主武器新家族）可按此模板复用。
> 本家族各步骤的详细产物见本文件夹其他 MD 与 `tmp-soya-family-test\lightningball-3ver-audit\`。

## 一、流程总览（九步）

```text
① 立项建档 → ② 引擎与素材预检 → ③ 三版本只读对比审计 → ④ 用户逐项决策
→ ⑤ 配置回迁（块内替换） → ⑥ SWF 闭包导入（ID 重映射） → ⑦ 回读+像素+回归三重验证
→ ⑧ 三处同步+manifest+构建+双自检 → ⑨ 归档+备份+提交
```

## 二、各步要点（本家族实测有效的做法）

### ① 立项建档
- 在 `副武器家族\` 新建 `<家族名>（<武器别名>）\` 文件夹 + 家族档案 README（arms id、形态表、imgLabel/hitImgLabel 五级清单、参考版本入口、对比协议）。
- 同步在 `..\..\..\副武器家族\README.md` 家族清单表登记一行。

### ② 引擎与素材预检（先证明"能迁"再动手）
- **配置层**：三版配置块（2.5 `subArms37.xml` / 3.4 `9_subArms52_xml` / GH `6_EmbedXml_xmlClass7`）全字段 diff，锁定差异项。
- **行为字段必须查消费点**，不能想当然：
  - `specialProperty`（锁敌/跟踪）→ 全库 grep 证明仅 `ArmsItemsTip` 提示文本使用，零行为风险；
  - `attackType`（energy/boom）→ 查到 `HurtCount` 伤害克制表（真实平衡变化）+ `getArmsMustItems` 研发材料风味连锁（boom→buncher），在总结中向用户明示。
- **资源层**：确认 `sub/` 前缀解析到哪个 SWF（本家族：本体/子弹在 sub1130；**受击音、电弧音却在别处**——sound 资源组按导出名由代码播放，SWF 时间轴里翻不到，这是本家族最大的排查弯路）。
- **音频对账法**：ffdec 全量导出 DefineSound 按哈希对账 + 引用反查（StartSound 归属精灵），快速证明"哪些声音真缺、哪些是代码播放不缺"。

### ③ 三版本只读对比审计（对比期严禁修改）
- 配置 → SWF 结构（Character ID/帧数/放置数/StartSound）→ 逐帧渲染像素 diff → 音频哈希，四层证据对齐，按 A~D 分级。
- **形态映射先过表再比**：本家族五级一一对应（干净）；异端审判/微波炮等家族存在 ID 错位，不可机械 lv 对 lv。
- 产出对比图 + 审计 MD，**差异逐项列决策点交用户**，绝不代拍板。

### ④ 用户决策
- 本家族决策："全部复原 2.5，追踪也要改成锁敌"；经济字段按长期禁令不动（price/mustItems/commonLevel）。

### ⑤ 配置回迁
- 只在 `<arms id="lightningBall">` 块内替换，块外逐字节不变；替换前后 SHA-256 + 字节差记录（+15B 逐项可解释）。
- 修改前原件备份进 `备份-被替换的旧资源-<日期>\`。

### ⑥ SWF 闭包导入（沿 cutter/调皮范式，脚本 `lightningball_restore_merge.py`）
- 整段时间轴替换：GH 精灵（1327/1323/1313）← 2.5 模板（1261/1256/1244）。
- 闭包收集（后序遍历、id_map 去重、根模板精灵不导入防孤儿、过滤 characterId/bitmapId 0 与 65535）。
- 特例映射：挂点 `110→104`（basePoint/shootPoint 矩阵强制当前值）；开火音 `1225→946`（GH 有等音直接重绑，不克隆）。
- 新 ID 从目标最大 ID+1 起连续分配（本家族 1993-2029，共 35 项）。
- **铁律：全程持有同一棵 ElementTree，禁止重读原始 XML（鞭炮教训）。**

### ⑦ 三重验证
1. **回读结构**：xml2swf → swf2xml，断言导出名不变、帧数/放置数/挂点/StartSound 符合预期、悬空引用 0、未涉及精灵（LV4/LV5）未动。
2. **逐帧像素**：重渲染 LV1~3 全 12 帧 vs 2.5 → 全 0 差异。
3. **回归复核**：抽查前序家族（elastic/laser/cutter/missile/elecGun）29 个符号结构逐一比对 → 零回归。

### ⑧ 同步与构建
- `swf\` = `build\swf\` = `runtime\swf\` 三处 sub1130.swf 哈希一致。
- `config\build\current-resource-manifest.sha256` 更新 sub1130 行（C89B9C80 → 4C9CF7BF）。
- `build_swf.bat`（121 脚本补丁 + 7 BinaryData）→ `build\game.swf=26DDE359…`。
- 从产物反编译断言配置四项 ×5 全 PASS；`launch_game.bat --check sa` / `sa_debug` 双自检通过。

### ⑨ 归档与提交
- 本文件夹：执行总结（四段式）+ 工作流程总结（本文件）+ 对比/证据图 + 迁移脚本两枚 + 备份文件夹。
- 两级索引 README（`武器家族内容\README.md` 变更清单、`..\..\..\副武器家族\README.md` 家族表）与家族档案同步更新。
- 代码与总结同一次提交，保证"代码到了 GitHub、总结也到了"。

## 三、本家族沉淀的新经验

1. **"音效缺失"三段排查法**：sub 包时间轴/嵌套闭包 → 全文件声音哈希对账+引用反查 → 代码 playSound 链路（资源组/注册清单/音量）。本家族结论：电弧音在 sound 资源组、三版字节相同、代码链路完整——**"听不到"≠"资源缺失"**，还有"源响度低"（实测 -26.7dB）与"触发频率"两种解释。
2. **音量提升实验**：`getSound(label).play(1,倍数)` 定点放大，不影响其他音效；ffmpeg volumedetect 先测源响度再定倍数。
3. **光晕层真身识别**：FFDec 放置明细逐帧 diff + 放大渲染，把"整枪发白"落到 depth2 精灵（1260）+ 逐帧 ColorTransform + blend=8 的具体结构，导入才有精确目标。
4. **specialProperty 是展示字段**——两版引擎皆然，后续家族遇到"锁敌/跟踪"类字样先查消费点再下结论。
