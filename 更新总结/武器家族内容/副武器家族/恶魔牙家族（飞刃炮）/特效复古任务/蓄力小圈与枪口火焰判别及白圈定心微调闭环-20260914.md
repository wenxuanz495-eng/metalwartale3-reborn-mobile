# 蓄力小圈与枪口火焰判别 · 白圈定心 · 取色微调闭环

> 整理日期：2026-09-14
> 来源：黄金恶魔牙（goldflyBlade_lv1，char 391）圈链位置修正全程实战（一天内 7 个部署版本的完整错误链与收口过程）。
> 定位：**跨家族方法论**——任何带"蓄力指示 + 枪口火焰"双元素的原版武器（大部分主/副武器蓄力枪）都适用。

## 一、至关重要的判别错误（本日两次踩坑）

### 错误还原

| 版本 | 动作 | 错在哪 |
|---|---|---|
| EC19F872 | 把整条大圈链（含爆闪/消散）随小白圈一起对心到剑柄 | **枪口火焰被错误搬离枪头** |
| ED117A18 | 只归还后半段 2670/2675/2680/2683，2650~2665 生长蓝圈继续留柄 | **同一错误犯了第二次**（半次修正） |
| BBB776C3 | 大圈链 8 处全部归位 2.5 枪口位 | ✅ 最终正确口径 |

### 判别标准（升级后，按元素语义，不按出现早晚/大小）

```text
小白圈脉冲系列（subtle 白色 pulse，如 flyBlade 2652~2677）
  = 蓄力指示 → 贴合剑柄/圆饰中心（伴随蓄力全程微弱存在）
蓝圈→光球→爆闪→消散的生长链（如 flyBlade 2650~2683）
  = 枪口火焰 → 全程在枪头/枪口段（2.5 原设计即"沿枪口段生长"）
```

⚠️ **蓄力小圆圈极其容易被忽略**：它不显眼（低透明度、小尺寸），排查时目光容易被大圈链吸引；移动大圈链时它常被"顺带"移动或漏判归属。**动手前必须先把该武器蓄力段的每个元素逐一定性：这是蓄力指示还是枪口火焰？列清单再动矩阵。**

## 二、圆形特效定心方法论（本日第三次踩坑）

### 错误还原

用"形状包围盒中心 + 目视估读宝石中心"定心 → 白圈偏宝石左上约 1.5px，用户放大截图可见。

### 根因

1. 软光晕圈的**视觉中心 ≠ 包围盒中心**：白圈 alpha 集中在核心 8px，包围盒含大片淡光晕 → 视觉中心 (19.42, 9.60) vs 包围盒中心 (21.9, 11.6)，差 2.5px；
2. 目视估读宝石中心 (24, 38.5) vs 实测 (23.31, 36.20)，差 ~2px。

### 正确方法

```text
特效视觉中心 = 渲染像素 alpha 加权质心（逐形状实测，勿用 bbox 中心）
目标圆饰中心 = 本体形状上"圆饰颜色×alpha"加权质心（限定区域防装饰条纹污染）
新矩阵 = 目标中心 − 视觉中心（twips = px × 20）
最后以用户实机取色微调闭环收口（1px 级偏差静态测量到头了）
```

黄金恶魔牙实测锚点（当前部署态）：白圈形状视觉中心 (19.42, 9.60)；宝石加权重心 (23.31, 36.20)；白圈最终矩阵 **(98, 552)**；对照参照：恶魔牙青毂 (22.5, 37.0) 与其白圈 (24.4, 37.6)。

## 三、取色微调闭环（收口手段）

静态渲染（FFDec）只能保证到"肉眼大偏差消除"；1px 级收口必须靠**用户实机取色反馈**：

```text
部署 → 用户取色器点测（坐标+色值截图）→ 判定差几格哪个方向 → 矩阵 ±20tw/格
→ 重部署 → 再取色 → 直至"完美"
本次闭环：78,532 → 右移1格(98,532) → 下移1格(98,552) → 用户确认完美
```

每格 = 1 sprite 像素 = 20 twips。方向以用户截图十字线为准，不靠猜。

## 四、其他教训（同日实战）

1. **"部署了但游戏没变化"排查序**：①游戏会话是否重启（sub1130 进游戏时一次性加载）→ ②启动器来源是否仓库（发行包目录的启动器读的是另一套文件）→ ③三处部署文件哈希是否一致 → ④manifest 是否同步。
2. **manifest 哈希必须完整复制**：手打/截断哈希会造成自检失败（本日曾写入不完整哈希与含空格哈希，均已即时发现修正）。
3. **git 暂存必须精确到文件**：文件夹级 `git add` 两次误带无关任务的 7z 包，两次移除补救（磁盘文件不受影响）。
4. 版本哈希链（黄金恶魔牙 391 本日全程）：2E303889 → 354DCBA6（红弹删除+回枪线）→ EC19F872（初版对心·错）→ ED117A18（半次修正·错）→ BBB776C3（大圈链全归位）→ C770D1CA（白圈精确定心）→ 226ABC70（右移1格）→ **4AB12D99（定稿）**。
