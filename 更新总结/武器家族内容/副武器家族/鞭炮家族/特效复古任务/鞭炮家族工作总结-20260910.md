## 一、任务背景与命名界定

- **鞭炮**（arms id=`banger`，subArms index=91）：转移炮型副武器，当前版 4 级（鞭炮/鞭炮II/鞭炮2016/鞭炮2017），2.5/3.4 均只有单形态，lv2~lv4 为 11.3 基底后续新增。
- **黄金鞭炮**（arms id=`Goldbanger`，index=4）：黄金转移炮（穿透），当前版独有 2 级，2.5/3.4 无任何对应资源。
- ⚠️ 命名陷阱（本次全程反复强调）：`type=转移炮/黄金转移炮` 与主武器**相转移炮家族**（phaseTransfer）名字相近但分属两套体系；且 2.5 文案即写明鞭炮是"根据相位转移炮的特点制造"的致敬产物。config 中 `sub/cutter_hit_effect` 被全文件 25 处引用（8 个家族），任何受击改动必须块级精准操作。
- 历史包袱：本家族的测试包实验（`banger-gold-restore`）曾暴露"写盘重读原始 XML 致修改全部丢失"的严重事故，教训已入通用第九节 4 条；本次执行全程只保留同一个 ElementTree 对象。

## 三、任务与用户决策记录

用户在对比完成后下达的批准范围（原意逐条）：

1. **受击特效**：鞭炮与黄金鞭炮都使用**新版鞭炮的受击特效**（`bullet/green_boom`）——黄金鞭炮由 `sub/cutter_hit_effect` 改绑。
2. **待机及开火特效、枪口火焰**：使用 **2.5 版本**（黄金鞭炮无 2.5 对应本体，按测试包先例保留金色本体＋2.5 火力轨道）。
3. **子弹**：鞭炮和黄金鞭炮均使用 **2.5 版本**（8 帧绿色鞭炮火花弹）。
4. **覆盖范围补充**：是**整个鞭炮和黄金鞭炮家族**（6 个形态），不是只有 LV1。

## 五、过程中遇到的问题与处置（具体经过）

| 问题 | 处置 | 沉淀 |
|---|---|---|
| FFDec 21.1.1 `-export frame` 逐帧导出失效（只出 1 帧） | 换归档开发资料的 **26.2.1**，并确认正确语法：`-export sprite` 全量导出或 `-select <charId>:<N>` 单帧循环 | 逐帧渲染基准包同款方法 |
| 首版帧对比把挂点标记算进差异（f1 虚高 82.6%） | 改为 **DefineShape 直接比对**（排除 basePoint/shootPoint 标记），得真实 34.21% | 呼应通用教训"挂点标记非美术" |
| FFDec XML 深度平衡解析把自闭合 `<item .../>` 误计为开标签，sprite 提取返回 None | 正则改为 `<item\b(?![^>]*/>)` | 合并脚本已内置 |
| 合并脚本断言"GH sound 125 missing"误报 | 断言里字符串 '125' 与整数列表比较的类型错误；修正为 `int()` 后通过 | — |
| `build_all.bat` 首跑失败：残留 server.exe 锁定 build\server.exe（拒绝访问） | taskkill server.exe / FlashPlayer.exe 后重跑通过 | 残留进程清理应先于构建 |
| 构建后 `runtime\swf\sub1130.swf` 未随构建更新（仍是旧 B9C46C9D） | 确认构建只同步 `build\swf`，**runtime 为第三处需手动补齐**；已手动同步并复核三处哈希一致 | "三处同步"中 runtime 不能依赖构建脚本 |
| Git Bash 反斜杠转义吞路径（`work\xml` → `workxml`） | 统一改用正斜杠/绝对路径 | — |
