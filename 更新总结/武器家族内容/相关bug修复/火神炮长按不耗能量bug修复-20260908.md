# 火神炮开火（长按/连点）不消耗能量的 bug 修复

日期：2026-09-08
适用版本：`metalwartale3-reborn.git` 当前正式源码

## 一、bug 现象（实测记录）

1. 四连装：连点会消耗能量，但射速降低；长按完全不消耗能量。
2. 一连装、二连装：连点也不消耗能量。

## 二、根因

全游戏唯一的能量扣减点在 `HeroCarBody.energyUse()`（`bodyTimer` 每帧调用），只在其攻击状态机处于 `state == "start"` 的那一帧扣 1 点能量。

火神炮四形态配置全部为 `shootNum=1, attackGap=0, attackDelay=0`，因此全部走 `ArmsAttack.attackPanFireFairy()` 专用状态机，其循环为：

```text
start → shoot（首发）→ fireFairyLooping（长按期间持续停留，按帧累积器连发）→ overing → over → stop
```

长按期间状态机停留在 `fireFairyLooping`，永远不再回到 `start`，通用扣能通道被整体绕过——这就是"长按不耗能"。

连点时的偶尔扣能来自另一条残留路径：`attackGap=0` 使 `overing` 只持续 1 帧，快速点按若恰好落在该帧会设置 `preinputB`，随后 `"over"→"start"` 的转换帧被 `energyUse()` 看到而扣 1 点。该命中与形态无关、纯随机，所以四连装"连点扣能"只是测试噪声，连点时的"射速降低"则是点按节奏低于长按累积器连发节奏的固有现象。

## 三、修改内容

1. `decompiled\gamefile\scripts\body\hero\HeroCarBody.as`：新增 `consumeFairyShotEnergy()`。语义与 `energyUse()` 的 start 分支完全一致：`nowEnergy >= 1` 时 `setEnergy(-1)` 并放行；不足时按现有逻辑从 `equArr` 随机选一把已装备武器调用 `changArms` 自动换枪，并返回 false。`modInfiniteEnergy` 无限能量修改器由 `setEnergy` 内部原有逻辑兼容（扣血变回满），修改器开启时不会看见消耗。顺带修正了 `energyUse()` 中声明 `arr` 却使用 `arr0` 的反编译残留（未声明变量引用）。
2. `decompiled\gamefile\scripts\body\attack\ArmsAttack.as`：`attackPanFireFairy()` 的两个实弹发射点（`shoot` 状态首发、`fireFairyLooping` 累积器循环内每一发）在发射前调用 `consumeFairyShotEnergy()`。返回 false 时立即 return，不再发射该发：此时自动换枪（若成功）已经通过 `resetForArmsChange` 重置状态机，若继续执行会用旧 define 覆盖新状态，复现"新武器继承火神炮节奏"一类问题。

## 四、修复后的能量语义

- 每发实弹固定扣 1 点能量，与通用武器"每攻击周期扣 1 点"对齐；高形态射速快（2/3/3.5 倍），消耗同比加快。
- 能量耗尽：优先自动换枪（与所有武器现有的"能量耗尽自动换枪"行为一致）；若火神炮是唯一已装备武器，则停止射击等待能量回复（`energyRate` 0.025/秒 × 能量上限）后自动恢复开火。
- 无限能量修改器开启时不消耗（`setEnergy` 原有兼容）。
- 小黄豆 `hasInfiniteEnergy()` 的内置无限能量不受影响。

## 五、能量回复机制原版一致性审计（2026-09-08 补充）

结论：本次修复未触及任何回复代码；回复机制与原版逐层一致，未改动武器的回复速率（占能量上限的百分比/秒）与原版完全相同。

逐层对照（当前 GitHub 版 vs 2.5 原版代码库 vs 3.4 原版代码库）：

| 层级 | 当前版 | 2.5 / 3.4 原版 | 结论 |
|---|---|---|---|
| 回复入口 `GameData.dataTimer()` | 遍历 `equArr` 全部已装备武器，`addEnergy(maxEnergyRate / 6)` | 逐字一致 | 一致 |
| 调用频率 | `timer5 = new XTimer(5)`，每 5 帧 1 tick（30帧制 ≈ 每秒 6 次） | 相同注册方式 | 一致 |
| `ArmsItemsData.addEnergy()` | `nowEnergy += value * maxEnergy` + 上下限钳制 | 逐字一致（当前版仅在顶部多无限能量修改器守卫） | 一致 |
| 回复率 `maxEnergyRate` | `baseEnergyRate * (1 + add.energy_rate)` | 一致 | 一致 |

即回复速度 = 每秒回复 `energyRate` 配置值 × 能量上限（火神炮为 0.025/0.05，即每秒回复上限的 2.5%/5%）。

需要区分的两个**既有**绝对值差异（均属离线版既有设计，非本次修复引入，也不属于回复机制改动）：

1. 全武器通用：当前版 `maxEnergy = 2 * baseEnergy * (energy_max + 1)`，2.5 与 3.4 原版均无前缀 `2 *`（已记录于 `武器数值公式审计总结.md` 的 98→196 问题）。回复量按上限的比例计算，上限翻倍使绝对回复速度同比翻倍，但"每秒回复上限的百分之几"不变。
2. 火神炮专有（此前按要求实装的槽位能量制）：上限走槽位公式、芯片不再提供 `energy_max/energy_rate` 加成，回复保持基础配置比例（2.5%/5% 上限每秒），绝对值随槽位上限放大。

本次每发扣 1 点的消耗与原版速率回复组合后的经济性参考（4 解锁格 1 把装备，上限 400，回复 10/秒）：一连装 7.5 发/秒可近似续航；四连装 26.25 发/秒净耗约 16/秒，满能量可持续射击约 25 秒后进入回复-脉冲射击循环。
