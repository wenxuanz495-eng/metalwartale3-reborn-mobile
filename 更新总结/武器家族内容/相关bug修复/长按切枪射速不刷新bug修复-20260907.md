# 长按开火切枪后新武器继承上一把射速的 bug 修复

日期：2026-09-07
适用版本：`metalwartale3-reborn.git` 当前正式源码

## 一、bug 现象

战斗中长按开火不松手，通过键盘数字键（1-8）或鼠标滚轮切换另一把武器后，新武器会按上一把武器的射速开火，射速状态不刷新。

## 二、根因

键盘路径 `HeroCarKey.attackKey → Game.eventGroup.changArms`，滚轮路径 `Game.GamingMWheel → eventGroup.changArms`，最终都进入 `HeroCarBody.changeArms()`。该方法只调用 `armsDefine.inData(...)` 换武器定义，从不重置攻击状态机 `ArmsAttack`。

`ArmsAttack` 的 `state / now_t / shootNum / fireFairyFrameAccumulator / preinputB` 因此跨武器残留。其中最严重的持久性泄漏是 `attackPan()` 的路由条件：

```actionscript
if((d.id == "fireFairy" && d.shootNum == 1 && this.baba is HeroCarBody) || this.state == "fireFairyLooping")
```

上一把武器是长按中的火神炮一连装时 `state == "fireFairyLooping"`，切枪后新武器仍被路由进 `attackPanFireFairy()`，按火神炮的帧累积器节奏（倍率/4帧）开火，而不是自己的 `attackGap` 节奏。非火神炮之间切换时，残留的 `now_t / shootNum` 也会污染新武器第一轮的射击时机。

## 三、修改内容

1. `decompiled\gamefile\scripts\body\attack\ArmsAttack.as`：新增 `resetForArmsChange()`。清空 `now_t / shootNum / fireFairyFrameAccumulator / preinputB`；保留 `loopB`，若仍处于长按状态则直接置 `state = "start"`，新武器以自身节奏无缝继续开火；否则置 `state = "stoping"`。与 `stopAttack()` 的区别是不清 `loopB`，保持"按住即持续开火"的手感。
2. `decompiled\gamefile\scripts\body\hero\HeroCarBody.as`：`changeArms()` 在 `armsDefine.inData(...)` 之前调用 `this.attack.resetForArmsChange()`。该入口同时覆盖键盘、滚轮、UI、能量耗尽自动换枪（AI 同样受益）。
3. `HeroCarBody.changeState("fly")`：变身飞行形态直接换 `flyLaser` 定义也存在同一根因（不重置状态机），在 `inData` 之前同样调用重置。

## 四、明确未修改的内容

- 未修改任何武器的 `attackGap / attackDelay / shootNum / shootGap` 配置；
- 未修改火神炮帧累积器本身的射速逻辑；
- 未修改 `stopAttack()` 原有语义（死亡、`setNoAttack`、落地等路径不受影响）；
- 副武器（SubBody）各自的攻击实例不在本次范围内。

## 五、构建与静态验证

- `scripts\build_all.bat` 退出码 0，175 个运行时资源校验通过；
- `scripts\launch_game.bat --check sa` 退出码 0；
- 解压 `build\game.swf` 后在 ABC 常量池中确认 `resetForArmsChange` 出现 3 次（1 处定义 + 2 处调用），修改已进入正式构建产物。

## 六、待实机确认

1. 长按火神炮一连装开火，数字键或滚轮切到任意武器：新武器应立即按自身面板射速开火，不再继承火神炮节奏。
2. 长按任意武器开火切到火神炮一连装：火神炮应以自身倍率节奏开火。
3. 长按切枪过程中不应出现需要重新点击才能继续开火的情况（`loopB` 保留的验证）。
4. 能量耗尽自动换枪、变身飞行（fly 激光）时按住开火：节奏应立即切换为对应武器的自身节奏。
5. 非长按状态下切枪、战斗开始加载、死亡复活：行为与修复前一致。
