## 一、FFDec CLI 用法陷阱

### 1.1 预选项必须放在命令前面

> 场景：阳电子炮对比·导出 2.5 本体逐帧图时

- **现象**：`ffdec-cli.exe -export frame outdir -selectid 409 file.swf` 打印帮助文本，导出 0 个文件。
- **根因**：FFDec 用法是 `<executable> [PRE-OPTIONS] [COMMAND]`，`-selectid`/`-format` 等是**预选项**，必须写在 `-export` 命令**之前**。
- **正确**：`ffdec-cli.exe -selectid 409,406 -format sprite:png -export sprite outdir file.swf`

### 1.2 导出逐帧动画用 `-export sprite`，不是 `-export frame`

> 场景：阳电子炮对比·同 1.1（修正参数顺序后仍只得到 1 张 `1.png`）

- **根因**：`frame` 类型导出**主时间轴**帧；分包 SWF 的角色是库符号，不在主时间轴上。
- **正确**：**`-export sprite`**——每角色一个目录（`DefineSprite_<id>_<导出名>`）、每帧一张 PNG，帧数一目了然。副产：`-export symbolClass` 直接得 `symbols.csv`（`ID;"导出名"`），是三版符号对照最快入口。

### 1.3 中文/全角路径导致 "Input SWF file does not exist!"

> 场景：阳电子炮对比·把 `原版\2.5（原版参考）\...sub37.swf` 直接喂给 FFDec 时

- **根因**：Java 进程对全角括号等非 ASCII 路径处理不稳（`ls` 能看到文件，FFDec 说不存在）。
- **正确**：SWF **复制到隔离工作区纯 ASCII 路径**（`workdir\input\sub37.swf`）再处理；复制后 `sha256sum` 留证。

### 1.4 `swf2xml` 只认绝对路径

> 场景：阳电子炮回迁·把当前 sub1130/bullet.swf 转全量 XML 时

- **现象**：相对路径报 "File not found."（而 `-export` 用相对路径正常——行为不一致）。
- **正确**：`swf2xml` 的**输入输出都给绝对路径**。

### 1.5 `-dumpSWF` 不展开 DefineSprite 内部

> 场景：阳电子炮对比·查本体时间轴里有没有内嵌 StartSound 时

- **现象**：只看到 `DefineSprite (chid: 409) len=412` 加原始字节预览，看不到内部标签。
- **正确**：dumpSWF 只适合看**顶层标签流**（数 DefineSound、找 SymbolClass）；sprite 内部必须 `swf2xml` 后解析。

### 1.6 输出目录参数的路径拼接坑

> 场景：阳电子炮回迁·回读验证导出新包 SymbolClass 时

- **现象**：`-export symbolClass symnew\sub1130 ...` 实际生成目录 `symnewsub1130`，按预期路径找 CSV 落空。
- **正确**：输出目录用正斜杠或预先 mkdir 的纯名字；导出后 `find` 确认实际落点再用。

## 二、FFDec XML 解析陷阱（Python 文本手术）

> 场景（本节总）：阳电子炮回迁·编写合并脚本（positron_restore.py）提取 3.4/2.5 依赖闭包并重映射时。FFDec 2.2 版 XML 是**泛化元素风格**：所有标签都是 `<item type="XxxTag" 属性=...>`，没有 `<DefineSprite>` 专有元素，解析必须按"type 属性＋各自 ID 属性名"做。

### 2.1 嵌套 `<item>` 让非贪婪正则截断块体

> 场景：分析本体时间轴结构时（23 帧被读成 `frames=0 places=1`）

- **根因**：sprite 体里嵌着 PlaceObject 的 `<item>`，`(.*?)</item>` 在**第一个** `</item>`（PlaceObject 自己的闭合）就停了。
- **正确**：**平衡扫描**——`<item...>` 开 / `</item>` 闭配对，深度归零才是真块尾。

### 2.2 自闭合标签破坏深度计数

> 场景：同上（修完 2.1 后解析结果只剩 25 个 DefineSoundTag）

- **根因**：开标签计数把 `<item ... />` 也 +1，而它没有闭合标签，深度永不归零。
- **正确**：token 正则区分 `<item[^>]*?(/?)>|</item>`，**以 `/>` 结尾的不加深度**；且注意初始化——从开标签**之后**扫则 depth=1，从开标签**本身**扫则 depth=0，两处不一致就是"永远不闭合"。

### 2.3 定义 ID 属性名不统一（本批最大坑）

> 场景：闭包导入时 `KeyError: 109`（形状漏索引）

- **根因**：ID 属性名按 kind 各不相同，统一用 `characterId` 会漏掉 shape 和位图：

| kind | ID 属性名 |
|---|---|
| DefineSpriteTag | `spriteId` |
| DefineShapeTag / 2 / 3 / 4 | `shapeId` |
| DefineBitsLossless2Tag / DefineBitsJPEG3Tag | `characterID`（**大写 ID**） |
| DefineSoundTag | `soundId` |
| 其余 Define*Tag | `characterId` |

- **连带**：`DefineSoundTag` 是自闭合且 `soundData` 属性在前、`soundId` 在后——正则别假设属性顺序。

### 2.4 引用属性重映射要覆盖全部携带 ID 的属性名

> 场景：同 2.3（闭包重映射阶段）

- **正确集合**：`characterId | characterID | spriteId | shapeId | soundId | bitmapId | fontId`（PlaceObject 引用走 characterId、StartSound 走 soundId、形状填充走 bitmapId；定义自身属性同命名空间，需一并重映射）。

### 2.5 `bitmapId="65535"` 是哨兵值

> 场景：重映射时 `KeyError: 65535`

- **根因**：FFDec 对**非位图填充**（渐变/纯色）的 FILLSTYLE 写 `bitmapId="65535"` 占位。
- **正确**：重映射回调对 65535（及任何不在映射表的值）**原样保留**，不当作引用。

### 2.6 ID 属性正则漏等号

> 场景：首次运行解析函数时（解析结果恒为 0 条）

- **根因**：`re.search(id_attr + r'"(\d+)"', attrs)` 漏了 `=`。
- **正确**：`id_attr + r'="(\d+)"'`；解析后先打印计数再继续。

### 2.7 SymbolClassTag 的 XML 形态

> 场景：bullet.swf 受击死名 orange_boom 改绑时

- **结构**：`<item type="SymbolClassTag"><tags><item>ID</item>…</tags><names><item>名字</item>…</names></item>`——**平行列表按下标对齐**；改绑＝names 找下标、改 tags 同下标 ID。
- **注意**：导出名还会出现在 **ABC 常量池**（`<constant_string>`）里，那只是类名字符串，与映射无关，别改错地方。

### 2.8 新导入块在 XML 里的插入位置

> 场景：设计合并脚本时

- **原则**：SWF"先定义后引用"。导入闭包按 donor 文件序保持内部先后，整块**插在第一个被替换目标之前**最稳；纯导出资源（如受击精灵）可插在 SymbolClassTag 之前。

### 2.9 星爆执行期三连：手工 XML 手术的结构性错误（2026-09-11 追加）

> 场景：星爆家族回迁·lv6/lv7 分层手术（保留红机体＋插入 2.5 lv3 特效层）时，连续踩了三个相关错误，前两个都会产出**结构非法的 XML**。

- **2.9a subTags 外壳错配**：组装新时间轴时，把自有机体的 f1 放置插在了导入时间轴的 `<subTags>` **外面**，而导入片段又自带 `<subTags>` 壳——形成"DefineSpriteTag 直接子元素是 `<item>`＋游离 `<subTags>`"的非法结构。FFDec 报 `NoSuchFieldException: item`。
  - **正确**：先剥掉导入片段的 subTags 外壳（正则取 `<subTags>`…`</subTags>` 之间内容），自有机体放置与特效内容**放在同一个 subTags 内**。
- **2.9b 丢弃带子元素的标签只删了开标签**：手术要丢弃 body/锚点的 PlaceObject（带 `<matrix/>` 子元素），用 `m.start()/m.end()` 只删了**开标签**，留下孤儿 `<matrix/>` 和游离 `</item>`。FFDec 报 `NoSuchFieldException: matrix`。
  - **正确**：对非自闭合标签计算**完整元素跨度**（平衡扫描到配对 `</item>`），按完整跨度删除或保留。**且别忘了在非自闭合分支里给起点变量赋值**——本次就漏了 `s_i = m.start()` 导致 `UnboundLocalError`。
- **2.9c 验证手段**：三个错误叠加时，`ET.parse` 报 `mismatched tag` 给出行号，FFDec 导入报 `SEVERE: NoSuchFieldException`——**两者都要看**：ET 抓标签配对，FFDec 抓语义层非法子元素。
- **预防**：涉及"保留部分＋插入部分"的手术，组装完成后先用 ElementTree 解析验证，再交 xml2swf。

### 2.10 xml2swf 对非法 XML 静默产出半截 SWF（2026-09-11 追加）

> 场景：2.9 的非法 XML 喂给 xml2swf 时——**不中断、不报错退出**，仍写出 1.8MB 的 SWF（正常应为 4.87MB），SEVERE 日志被 `| tail -1` 吞掉，险些把坏包当成品部署。

- **正确**：
  1. xml2swf 后**统计 SEVERE/Error 计数**（`| grep -c "SEVERE\|Error"` 应为 0）；
  2. **产物大小合理性检查**——与上一版产物对比，暴涨暴跌都是信号；
  3. 别用 `tail -1` 吞日志。
- **推广**：任何"工具报错仍可能产出产物"的场景（FFDec 全家、编译器降级模式），产物必须配合校验链使用，不能只看退出码。

### 2.11 PlaceObject 矩阵与位图填充矩阵的 scale 口径相差 20 倍（20260917 追加）

> 场景：黄金深渊五级·子弹缩放矩阵（实机子弹满屏巨型，用户报告"子弹实在太大"）

- **现象**：FFDec 渲染抽检全部正常，实机子弹却是 9.23×（lv4 20×）巨型。
- **根因**：FFDec XML 里两处 matrix 的 scaleX/scaleY 口径不同——**PlaceObject 放置矩阵=原始因子（1.0=1.0）**；**位图填充 bitmapMatrix=20 twips/px（20.0=1.0）**。按填充口径给放置矩阵写 20×倍率（9.2308），FFDec 原样编码为因子 9.2308。
- **抽检为何失效**：FFDec 自家渲染器与 XML 导出同口径（把 9.2308 再 /20 解释），渲染图看起来正确——**渲染验证对矩阵口径错误系统性失明**。
- **破案手段**：手工解码 SWF 二进制 PlaceObject 矩阵比特（NScaleBits=21，原始值≈605032=9.2308×65536），与 XML 值互证。
- **预防**：凡手写矩阵，验证顺序="二进制解码 ＞ 1:1 实测尺寸 ＞ FFDec 渲染"；渲染通过不构成矩阵正确性证据（已沉淀为新建线红线 R9）。

## 三、名字资源管理（死名/占用）

### 3.1 死名是消耗性资源，用一个少一个

> 场景：受击回 2.5·给 2.5 受击美术选导出名时（`positron_hit_effect` 已被响尾蛇×4＋调皮×4 占用，幸有多米诺档案"命名区隔"条目预警）

- **规则**：每次死名改绑必须在执行总结＋变更档案登记"谁占用了什么名"；下次选名先翻档案再全域扫描。

### 3.2 全域扫描的正确姿势与已知例外

> 场景：同 3.1（全域扫描全部配置 bins＋反编译脚本选死名）

- ⚠️ **文本零引用 ≠ 真死名**：`motion_hit_effect_1~4` 文本层零引用，但 `BulletBody` 会对 `motion_hit_effect` 运行时随机补 `_1~_4` 后缀——凡与运行时拼接模式同构的名字一律排除。
- 时点参考（2026-09-11）：sub1130 真死名剩 `goldflyBlade_bullet2`、`protonImpact_lv3/lv4_bullet`、`protonImpact_lv3/lv4_smoke`、`laser_lv1_bullet0`；bullet.swf 死名池剩 `pink_boom`、`pink_motion`、`blueness_boom`、`blueness_motion`、`yellow_boom`（`orange_boom` 已被本次阳电子炮受击占用）。
- ⚠️ **星爆回迁执行期实证（2026-09-11）**：曾误判 `chipped_hit_effect` 可作星爆受击的改名回收——立项时只统计了 xmlClass7（subArms 配置，0 引用），漏扫 **xmlClass3（主武器配置，等离子家族 ×10 引用）**。SymbolClass 改绑后才会连带改变等离子受击。全域扫描必须覆盖**全部**配置 bins（xmlClass3+xmlClass7+其他），不能只查本家族所在的那份。修正：星爆受击改绑 bullet.swf 真死名 `pink_boom`(65→185)。同日 bullet.swf 分配起点也需动态计算（阳电子炮已占 141~170，固定 141 起会撞号）。

### 3.3 新增导出名必须有 ABC 类桩

> 场景：通则（相转移炮 v1 先例：追加 SymbolClass 无类桩被 Flash 丢弃）

- **正路永远是改绑零引用死名**，不走新增名字路线。

## 四、部署与构建陷阱

### 4.1 manifest 更新的静默失败

> 场景：回迁部署·更新 current-resource-manifest 后首次构建，校验器报 `hash mismatch: swf\bullet.swf`（sub1130 行却成功）

- **根因**：`str.replace` 匹配不上不报错——两行间不可见字符差异导致"部分成功"，最难察觉。
- **正确**：改完**逐行 repr 校验**实际字节，或按行扫描重写；能断言替换次数就断言。

### 4.2 传输/脚本环境的反斜杠折叠（本批最隐蔽）

> 场景：修复 4.1 按行重写 manifest 后，构建改报 `Illegal characters in path`；字节级检查发现行内是 `*swf\x08ullet.swf`（退格符）

- **根因**：heredoc/传输层把脚本里 `\\b` 折叠成 `\b`，Python 把 `\b` 解释为退格写入了文件。
- **信号**：**SyntaxWarning（如 "\d is an invalid escape"）出现＝脚本源码已被改写**，此时应停手检查。
- **正确**：①复杂脚本**写成 .py 文件再执行**（不用超长 heredoc）；②必须在 heredoc 写反斜杠时用 `chr(92)` 或 `b"\x5c"` 构造；③任何含转义的写入，写完 `repr` 回读验证。
- ⚠️ **复发记录（2026-09-11 星爆执行期）**：给 starburst_restore.py 打"受击改走 bullet.swf"的方案补丁时，heredoc 补丁再次因转义折叠断言失败（`rebind block not found`），且同一段 heredoc 里 `\d` 折叠触发 SyntaxWarning——随后用 **Edit 工具**逐段修改才成功。结论：**heredoc 打补丁在本环境不可靠，凡含反斜杠/正则的补丁一律用 Edit 工具或落盘脚本**。

### 4.2b 跨任务 ID 分配撞号：分配起点必须对当前包动态计算（2026-09-11 追加）

> 场景：星爆受击导入 bullet.swf 时，脚本硬编码新 ID 从 141 起——但阳电子炮回迁已占用 bullet.swf 的 141~170（含受击根 170）

- **根因**：分配起点写死，没有对**当前包**重新计算全局最大 ID。阳电子炮执行后 bullet.swf 的空口已经变了。
- **正确**：每次合并前对**当前**包重扫 `(?:characterId|spriteId|soundId)="(\d+)"` 取最大值 +1 起分配（本例修正后从 171 起，受击根 185）。
- **推广**：同一边字典（如 `nid = 141`）在包被前序任务更新后就是错的；**写死任何"下一个可用 ID"都是定时炸弹**。

### 4.3 game.swf 是压缩 SWF，直接 grep 字符串恒为 0

> 场景：构建通过后验证内嵌配置，对 build\game.swf 二进制 grep `orange_boom` 得 0，险些误判配置没嵌入

- **正确**：FFDec `-export binaryData` 解出 BinaryData（如 `6_EmbedXml_xmlClass7_...bin`）再统计；预期值先算好（本次 orange_boom=6、red_energy=3）。

### 4.4 残留进程锁

> 场景：本次构建前 taskkill 掉残留的 server.exe 与 FlashPlayer.exe 各一个（鞭炮档案已有同类先例）

- **规则**：构建失败先看是否文件锁；构建/启动前清理后台残留。

### 4.5 构建校验器是最后一道网

> 场景：同 4.1/4.2（两处错误都是校验器率先暴露）

- `hash mismatch`→对照 manifest 行哈希；`Illegal characters in path`→八成行内混入不可见字符，字节级 repr 检查。

## 六、回迁执行预检清单（浓缩版）

```text
[工具] FFDec 预选项在命令前；逐帧用 -export sprite；swf2xml 用绝对路径；SWF 复制到 ASCII 路径
[解析] 平衡扫描 + 自闭合分支；ID 属性名按 kind 映射表；引用重映射七属性全覆盖；65535 跳过
[手术] 完整元素跨度（开标签+子元素+闭合）后再删改；剥壳再组装；ET.parse 验证 well-formed 后才交 xml2swf
[名字] 先翻占用档案 → 全域扫描（全部配置 bins，不只本家族那份）→ 排除动态构造模式 → 选定后登记
[分配] 新 ID 起点对当前包动态计算（max+1，含 sound 命名空间）——严禁写死；声音按内容哈希去重
[脚本] 复杂脚本落盘执行；反斜杠用 chr(92)/\x5c；见 SyntaxWarning 即停；写入后 repr 验证
[验证] SymbolClass 逐条对比；逐帧像素对比（预期 0%；跨版本对比先做包围盒/全局平移对齐防假差异）；音效挂接回读；game.swf 内嵌配置 FFDec 导出回读
[构建] xml2swf/构建后检查 SEVERE 计数与产物大小合理性（tail -1 会吞警告）；三处同步（swf\=build\swf\=runtime\swf\）+ manifest 逐行 repr 校验 + 构建前清理残留进程
[收尾] 旧资源备份 + 总结四段 + 档案登记死名占用
```
