# 离线化联网功能机制总结（登录 / 存档 / 商店等联网问题的解决方式）

> 调研日期：2026-09-11
> 性质：**只读调研**，本文撰写过程未修改任何代码或资源；结论均直接摘自当前仓库源码并附文件与行号锚点。
> 覆盖范围：Flash 侧 `decompiled/gamefile/scripts/`（ActionScript）+ 服务端 `server/`（Go）+ 启动链（`launcher/`、`scripts/`）。

---

## 一、总机制链（先记这一条）

原版是 4399 网页游戏，登录、存档、支付（M币）、排行榜、公会全部依赖 4399 页面注入的服务对象和远程接口。离线版的解决思路不是"模拟服务器"，而是**釜底抽薪 + 就地降级 + 本地接管**三层：

```text
① 釜底抽薪：Game.setHold() 硬编码 serviceHold = null
   —— 4399 网页服务对象永远缺失，一切在线调用自动进入"无服务"分支
② 就地降级：SaveAPI.isLocal() 硬编码 return true
   —— 全游戏所有"在线/本地"分叉永远走本地分支，4399 分支成死代码
③ 本地接管：Go 服务器提供同名 HTTP 接口 + mock4399 兜底
   —— 存档走权威接口 api/game-save；漏网的 4399 式请求拿到合法假响应，不会卡死
```

三层配合的结果：登录直接跳过、存档落本地权威文件、商店扣的是存档里的 M币余额。

## 二、登录问题：不再有登录

**代码锚点**：`decompiled/gamefile/scripts/gameAll/api/save/SaveAPI.as`

原版流程：`game_init()` → 请求服务器时间 → `showLogPanel()` 弹 4399 登录框 → 登录成功回调 `login(obj)` 写入 `username/uid` → 进存档选择页。

离线流程（`SaveAPI.game_init()`，第 42~53 行）：

```actionscript
if(this.isLocal())
{
   var localTime:String = Game.getNowLocalTime();     // 用本机时间冒充服务器时间
   Game.timeDate.getSaveDate.inData_byStr(localTime);
   Game.severTime.nowTime.inData_byStr(localTime);
   Game.gameData.username = "本地玩家";                // 写死用户名
   Game.gameData.uid = 1;                             // 写死 uid
   this.loadUI.hide();
   Game.uiGroup.serverUI.show(this.readlist,this.read); // 直接进 8 槽存档选择页
}
```

- 登录面板（`s4399.showLogPanel()`）在本地分支**永远不会被调用**；`Save4399.as` 整个类仍保留但已是死代码。
- 判定开关本身是写死的：`isLocal()` 直接 `return true`（第 316~318 行），没有运行时条件。

## 三、存档问题：权威存档接管

### 3.1 Flash 侧（`gameAll/api/save/LocalSave.as`）

- 上报地址为**相对路径** `api/game-save`（第 24 行），天然指向本地服务，不含任何 4399 域名。
- 数据结构：8 槽容器 `{localSaveVersion:2, localSlots:[8]}`，每槽含 `index/title/datetime/status/data`。
- 序列化：AMF `writeObject` + `deflate` 压缩后以 `application/octet-stream` POST 上传（第 105~117 行）。
- 工程细节：
  - **写队列防并发**：`writeBusy` 期间新写入进入 `queuedWriteData` 排队，成功/失败回调按队列派发，避免丢档；
  - `IOErrorEvent` / `SecurityErrorEvent` 都接了失败回调，断服不会无响应；
  - 虚空档拦截：`isGeneratedBlankData()` 判定"等级<=1 且无主武器/副武器/车辆"的默认空白角色**不会被创建或保存**。
- 读档同理：`ReadList` / `Read` 走同一接口；`SaveAPI.readlist()` 的在线分支（`s4399.readlist`）为死代码。

### 3.2 Go 服务端（`server/http.go`、`server/store.go`、`server/amf.go`）

- `/api/game-save` GET/POST（http.go 第 200~222 行）：读取/接收权威存档。
- `savePrimary()`（store.go 第 66 行起）保存链：
  1. AMF 解码校验（`amf.go` 自研 AMF0/3 读取器，含条目数上限防炸）；
  2. `stripGeneratedBlankSave()` 剥离虚空档后写回（服务端兜底，与 Flash 侧双保险）；
  3. 原子替换写入 `build/saves/game_save.bin`（`writeFileDurable` 临时文件 + rename，`recoverPrimaryLocked` 提供损坏恢复）；
  4. 同步导出人类可读的 `saves/yagao.json`；
  5. `insertHistory()` 写入 SQLite（`saves/saves.db`）作为历史版本，修改器修改前也会自动备份。
- **明确禁用 Flash SharedObject（SOL）**作为存档源（`docs/gameplay/SEAL_RULES.md` §1.1）：避免同一台机器出现两个互相覆盖的存档源；旧版 `game_save.bin` 与 1.1 存档可导入。
- 服务端另提供 `/api/saves/export`、`/api/saves/list`、`/api/saves/latest.json`、`/api/game-save/backup` 等配套接口（修改器和存档脚本使用）。

## 四、商店与 M币：从"支付接口"变"存档余额"

**代码锚点**：`gameAll/api/Shop_API.as`、`gameAll/PayController.as`

- 购买入口 `Shop_API.buyPropNd()`（Shop_API.as 第 33~37 行）：

```actionscript
if(Game.save_api.isLocal())
{
   Game.payController.decMCoin(obj0.price * obj0.count,_yesFun,_noFun);
   return;   // 永远在这里返回，不往下走 4399 商店接口
}
```

- `PayController.decMCoin()`（PayController.as 第 54~84 行）的本地分支**直接操作存档字段** `Game.gameData.MCoin`：
  - 余额足够 → 扣款、`saveDataNoUI()` 触发保存、走成功回调；
  - 余额不足 → 提示"M币不足！"走失败回调；
  - 在线分支（`getStoreState` → `payCtrl("decMoney")`）为死代码。
- 效果：**M币不再依赖 4399 登录态，就是存档里的一个数字**。围绕它的发行侧配套（见 `docs/status/PROJECT_STATUS.md` 商城与货币章节）：
  - 累计充值奖励改为读取账户当前持有的 M币（`getTrueTotalRecharged()` / `backstageMCoin`）；
  - 成长礼包改为离线直接购买/激活；
  - 定制装备、往期装备入商城并按档位定价；购买上限扩大到 9,999,999；
  - "等级/G币一步到位"类纯充值入口隐藏，M币定位为材料、装备与可玩系统货币。

## 五、其他联网系统的处置

| 系统 | 原依赖 | 离线处置 | 锚点 |
|---|---|---|---|
| 服务器时间 | `serviceHold.getServerTime()` | `serviceHold` 为 null → 直接走本地时间处理器；`game_init` 也用 `getNowLocalTime()` | `SeverTimeAPI.as` `getTime()` |
| 公会 | `serviceHold.unionCreate/getUnionList` 等 | 公会状态写入 `Game.gameData.offlineUnion`（**随权威存档持久化**）；本地公会列表只返回自己的公会；创建/贡献/训练全本地计算 | `Union_API.as` 第 114~190 行 |
| 排行榜/成就 | `High_API` 提交分数、拉榜 | `serviceHold` 为 null 时全部本地降级（直接回调本地数据），不伪造全服榜单 | `High_API.as` |
| 网页服务根对象 | 4399 页面注入的 hold 对象 | **`Game.setHold()` 硬编码 `serviceHold = null`**，输出测试文本"离线版已忽略网页服务对象。" | `Game.as` 第 415~417 行 |
| Facebook 存档 | `fb_Save_api.as` | 死代码保留 | 同名文件 |

## 六、服务端 mock4399 兜底（最后一道防线）

**代码锚点**：`server/http.go` 第 241~242 行（路由）、第 303~326 行（实现）

```go
case strings.HasPrefix(path, "/api/4399/") || strings.Contains(path, "save.api"):
    a.mock4399(w, r, path)
```

兜底响应规则（按路径关键词匹配）：

| 请求含 | 响应 | 模拟意图 |
|---|---|---|
| `list` / `get` | 文本 `0` | 列表/查询类返回空结果 |
| `save` / `set` | 把请求体落盘 `saves/api_save_时间戳.bin` + `.meta.json`，返回 `1` | 保存类一律"成功"，且留证据可查 |
| `time` / `session` | 本地时间字符串 | 服务器时间/会话 |
| `token` | `offline-token` | 登录令牌 |
| 其他 | 文本 `1` | 通用成功 |

意义：即使某处遗漏改造的代码仍按原版相对路径发出 4399 式请求（全部打到本地域），也会拿到**格式合法的响应**，游戏流程不会卡死在等待弹窗或网络错误上。真正的 4399 域名根本不会被访问——因为资源与 API 同在 `127.0.0.1` 本地服务上，`/crossdomain.xml` 也由本地服务提供（http.go 第 175~176 行），Flash 安全沙箱直接放行。

## 七、启动链（把以上串起来）

```text
启动游戏-flashplayer_sa.bat / 超合金战记启动器.exe（同一终点）
  → build/server.exe 监听 127.0.0.1 随机端口（52000~63999）
  → /api/status 健康检查 + instance 令牌
  → Flash Player 打开 http://127.0.0.1:端口/game.swf
      ├─ 同域加载 build/swf/ 分包资源
      ├─ 存档 → api/game-save（权威存档 build/saves/game_save.bin）
      └─ 所有联网调用 → serviceHold=null 降级 或 mock4399 兜底
```

## 八、设计原则（引自 docs/runtime/OFFLINE_ARCHITECTURE.md"联网功能处理原则"）

1. 能转成本地状态的系统，使用主存档持久化（如公会 `offlineUnion`）。
2. 只需要静态返回值的接口，由本地服务或 ActionScript 适配层接管。
3. 依赖真实其他玩家的功能**明确标记不可用**，不伪造复杂在线生态。
4. M币不再依赖 4399 登录态，直接使用主存档余额。
