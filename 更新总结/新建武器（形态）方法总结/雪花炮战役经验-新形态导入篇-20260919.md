## S1｜位图编码必须验预乘不变量，"自身往返一致"是欠定证据

DefineBitsLossless2 fmt5 = **预乘 ARGB**（A=0⇒RGB=0，RGB≤A）。本任务首版按"非预乘"编码，用现役位图 862 做往返逐字节验证**通过了**——但 862 是二值 alpha（无半透明像素），预乘/非预乘两种编码在其上字节完全相同，结论欠定。实机表现为研究列表图标**白色不透明底**。
正确做法：编码后断言预乘不变量（A=0⇒RGB=0 零违反、RGB≤A 零违反），并与源 PNG 做"预乘可逆还原"逐像素比对。素材 alpha 全为 0/255 时，预乘=把 A=0 像素 RGB 置零。

## S2｜新增 Character ID 前做"三属性"全量普查

`characterID=`（位图）/`spriteId=`（精灵）/`shapeId=`（形）属性名不同，只扫其一必漏。本任务 1804~1809 已被近三期任务占用（只查 characterID 会误判 1803 为最大），被写盘前终检拦截。标准步骤（十步第 3 步）据此强化：三类属性 + soundId/fontId 一并取最大。

## S3｜"同深度替换"红线在武器本体时间轴上的适用边界

十步第 5 步红线：逐帧动画禁同深度替换型放置（运行时不渲染）。但武器本体的**状态切换帧**（f2 换发光形、f4 换回常态）用 MOVE+character 替换是**现役模板原生写法**（874 的 f3 换爆闪帧即如此），实机渲染正常。两者不矛盾：红线针对的是"同深度反复替换的逐帧动画链"；单次状态替换沿用模板即可。若新写逐帧链，仍必须 RO+add。

## S4｜发光/曝光机制二选一：ADD 叠加 vs 整幅替换

模板（2014）= 常态铺底 + 发光图 ADD 叠加（亮度相加，可能过曝糊白）。画师给的"高曝光贴图"适合**整幅替换**（f2 直接换装，亮度=画师给的曝光，无叠加风险）。本任务用户拍板替换式，实机通过。选型依据：叠加式适合"发光图比常态暗/局部"的素材；整幅提亮素材用替换式更稳。

## S5｜存量形态也能动，但编辑必须块内限定+基线唯一差异断言

微调轮 2 需要改**存量形态 2014**（sprite 874）的挂点。做法：在源 XML 上按 `spriteId="874">` 到 `</subTags>` 的块内限定替换，回读断言"874 块与基线往返的唯一差异=该矩阵"。存量形态的行为变更（子弹出生点移动）不是禁区，但断言口径要从"零变化"换成"预期差异唯一"。

## S6｜多轮挂点微调的沟通口径：每轮记"累计位移+终值"

本任务挂点调了三轮（+5 误解 → 澄清双枪同移 → +20 追加），终态=2014/2026 双枪 shootPoint 均 2957,480。经验：用户报"再移 N px"时先确认**基准是原值还是上轮值**、**单枪还是同系多枪**；文档每轮记"累计位移+终值坐标"，避免下一轮再对错基准（磁轨炮家族同款多轮微调先例）。

## S7｜本机 trace 通道失效时的探针替代法

SA 播放器（debug/release）在本机均不输出 trace（mm.cfg 两处位置都配置了也不行），但**错误报告通道有效**（未捕获异常落 flashlog）。探针验证改用负空间法：探针不写 try/catch，任何 1065/1107/VerifyError/沙箱错误必然落日志——**日志干净=加载干净**；成功路径（类存在、实例化、播帧、挂点坐标）画在舞台上供肉眼确认（双击 BAT+本地 HTTP）。另外 mxmlc 默认 `-use-network=true`，加载本地文件资源会 #2140，须显式 `-use-network=false`。

## S8｜收尾审计三件套

任务收口时：① grep 过时口径（"未导入/待定/当前生效"类，含错误记录文档的速查表——那表是给后续调研用的，过时即误导）；② 全库扫控制字符（历史 Python 转义事故残留，本任务修了一处上个会话的 `flyblade`→`\f`+lyblade）；③ 跨文档哈希/终值一致性（旧哈希只允许以"历史值"身份出现）。
