# 新建武器（形态）方法总结

> 定位：**3.0 前瞻开发期起新开的任务线**——不回迁旧素材，而是新建武器/新等级/新形态（画师新捏素材 + 星座系特效）。本文件夹沉淀这条线的**标准流程、平台红线与验证方法**；首例实践=黄金恶魔牙 LV3~LV6（20260916，见家族文件夹 `番外家族-黄金恶魔牙家族（黄金飞刃炮）\黄金四级形态任务过程总结-20260916.md`）。
> 与特效复古线的区别：复古线复用现役导出名与既有等级节点，素材来自 2.5/3.4 旧包；新建线**新增导出名（双注册）、新增配置等级节点、素材全为画师新捏**——风险与流程都由此而来。

## 新建武器（形态）标准流程（十步）

> 首例实践：黄金恶魔牙 lv3~lv6（sub1130）。每步的"断言"都是硬性关卡，失败即停。

1. **机制侦察**（动手前必做）
   - 等级解析：`getLabel() = id + "_lv" + (level+1)`——动态拼接，等级数=配置 armsLevel 数，无硬上限；
   - 符号注册：导出名 = **SymbolClass（名字↔角色 ID 平行数组）+ ABC 存根类** 双重注册，缺一加载即炸（见红线 R1）；
   - 本体/挂点结构：同家族现役级的 body/锚点/效果链深度排布，作为新级的模板与重锚基准。
2. **素材验收**：画师 PNG 逐张查尺寸/alpha/色彩；与现役组合素材对位（如挂点弹是否已画入本体——原版 lv1/lv2 本体形状内部含枪口顶弹，新捏图通常没有，需时间轴放置补齐）。
3. **ID 分配**：全库扫 characterID/shapeId/spriteId/soundId/fontId 取最大+1 顺延；定义插入必须"先于引用"（锚定在首个引用精灵之前）。
4. **素材导入**：PNG → DefineBitsLossless2（**预乘 ARGB、format=5、forceWriteAsLong**）→ 克隆 shape30 做 1:1 矩形包裹形状（fillStyleType=67）→ 单帧精灵（属性照抄现役单帧精灵）。全程单棵 ElementTree，禁止手搓标签。
5. **时间轴搭建**：⚠️ 逐帧换图**禁止同深度替换型放置**（运行时不渲染，只有第一帧可见）——必须「先移除、再添加」，位移用 MOVE 标签；详见 `时间轴动画替换失效修复与标准写法\`（20260918 引擎级发现）。**逐帧镜像同家族现役级的结构**（放置/清除/blend/音效），矩阵按"新本体 vs 基准本体"的枪口列/枪轴行差整体平移（20260912 重锚先例）；**深度规划三原则**：弹在下/枪在上/效果更高，锚点放镜像占用深度之上，且断言新用深度与镜像占用深度无冲突。
6. **新导出名双注册（核心红线 R1）**：SymbolClass 追加（tags/names 两数组同步追加保持配对）+ **ABC 存根类必须经 mxmlc 正经编译**（`-compress=false -swf-version=43`，类体=dynamic MovieClip+锚点 public var 声明），提取其 DoABC2 标签移植到 SymbolClass 之前（SWF 多 ABC 合法）。**禁止**两条邪路：只加 SymbolClass（FP 加载即 ReferenceError#1065）；手拼 ABC 结构（FFDec 能解析但 FP VerifyError#1107）。
7. **探针验证**（移植后必做）：本地 `python -m http.server` + FP34 debug 加载探针 SWF，断言 hasDefinition=真、可实例化、getChildByName("basePoint"/"shootPoint") 非空。注意：trace 有缓冲（mm.cfg 加 `TraceOutputBuffered=0`），探针结果优先用"实例上台+用户录屏"或 HTTP beacon 回传。
8. **配置追加**：armsLevel 节点照同级模板逐字段生成；断言：锚串回换可精确还原、字段逐项回读（**防参数顺序/转义类低级错误——首例实践实际拦截过一次畸形节点**）、兄弟块（本系）逐字段原样。
9. **构建与验证**：sub1130 三处同步（`swf\`＝`build\swf\`＝`runtime\swf\`）+ manifest 行更新（若该文件在册）→ `构建.bat`（若 server.exe 锁定先 taskkill）→ binaryData 回读（config 内嵌与 decompiled 字节级一致）→ `--check sa`/`sa_debug` 双自检 0。
10. **文档与提交**：家族执行总结（四段式：目标/实际修改/构建与验证/待实机确认）+ README 状态行/索引 + `各家族变更档案.md` 条目 + docs 登记；总结与代码同一次提交。

## 红线清单（每条都有事故背书）

- **R1** 新导出名必须双注册；只加 SymbolClass = 加载期 ReferenceError#1065。
- **R2** 手拼 ABC 结构会被 FP 校验器 VerifyError#1107 拒绝（FFDec 能解析≠FP 接受）；存根类一律 mxmlc 编译后移植。
- **R3** 时间轴新层级必须全帧排查冲突：同深度放置=替换（会顶掉既有对象）、RemoveObject 按深度删（会误删同深度其它对象）。首例事故=本体与挂点弹同置 d2 且 f2 清除标签误删换装体 → 实机"开火后整枪消失"。
- **R4** 共享角色只做放置引用，禁止改内容（金色链/小白圈被本体家族共用，引用断言进脚本）。
- **R5** 底稿哈希断言（==manifest）先行；全程单棵 ElementTree；产出可精确还原检查。
- **R6** 配置替换后必须逐字段回读（setf 参数顺序类错误产出畸形 XML 会砸烂整份武器配置——首例实践已拦截一次）。
- **R7** FFDec XML 常量池子项位置=AVM2 索引（无 +1）；trait 的 bytes 内嵌 u30 索引需同步改写。
- **R8** 不确定就先问（数值口径/等级范围/素材用法均由用户拍板后才动手）。
- **R9** 两套矩阵口径勿混：**PlaceObject 放置矩阵 scaleX/scaleY=原始因子（1.0=1.0）**；**位图填充 bitmapMatrix 20.0=1.0**（20 twips/px 口径）。黄金深渊五级事故＝子弹放置矩阵误用 20× 口径致 9.23× 巨型上台，FFDec 渲染器按 /20 解释使抽检失效——**矩阵类改动必须二进制解码或 1:1 实测验证**。
