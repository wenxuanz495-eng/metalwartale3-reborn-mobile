# 时间轴动画「替换型放置」运行时失效——根因、裁决方法与标准写法（重大）- 20260918

> **一句话结论：本引擎运行时里，PlaceObject2 的「同深度替换角色」静默失效——添加（add）与移除（remove）都正常渲染，唯独替换（replace）不生效。** 任何时间轴逐帧动画（武器蓄力特效、多帧火焰、过场动画、对话框动图、动态图）只要写成"同一深度换角色"，就**只有第一帧会显示，后面全是无效标签**。
> 首发现：星际雷神（zhongzifeidan）蓄力特效四帧 + 画师三帧火焰，实机只显示各自第一帧（2026-09-18，V24~V29 期）。耗时两个多小时定位，**属于引擎级重大发现，此后任何逐帧动画开发必须遵守第四节标准写法**。

## 一、事故经过

1. 用户实机反馈：蓄力光球不变形、火焰三帧只播第一帧（F2 慢速逐帧观察，排除了观感误判）。
2. 资源层三层验证**全部正确**：放置引用链（形状↔位图逐一对应）、位图像素与源图逐像素一致、二进制标签逐字节手工解析无误——**文件没有问题**。
3. 运行时三轮探针层层逼近（方法见第三节）：播放头在走 ✓ → 显示列表在变 ✓ → **渲染像素恒定 ✗**。
4. 游戏内渲染快照回传（最终裁决）：特效层单独画面在 f3/f6/f9/f12 **逐像素完全相同**——替换型放置从未生效。修复前证据：`证据-修复前fx机位四帧逐像素相同-20260918.png`。

## 二、根因与影响面

- **失效**：PlaceObject2（placeFlagMove=0、hasCharacter=1）落在**已有角色的深度**上——标签语义是"替换"，运行时不渲染新角色（旧角色保持显示）。
- **正常**：空深度放置（add）、RemoveObject2 移除（remove）、以及推定的 MOVE 重定位。
- **影响面**：所有时间轴重建用"替换型放置"表达逐帧动画的武器（当前已知：星际雷神两级——蓄力特效四帧、火焰三帧、装填滑动全部冻结在首帧/首状态）。**未来任何新建武器、过场、动图若按直觉写"同深度换图"，必然复现此问题。**
- 佐证怪象：FFDec 自带渲染器同样不渲染替换帧（内部帧分割错乱），但其导出/回读正确——即"文件正确、渲染器不渲染"，与游戏运行时行为互相印证。**不要用 FFDec 渲染结果当裁决依据，要用游戏内探针。**
- 替换失效的底层机制（播放器行为还是加载上下文所致）**尚未查明**，不影响标准写法的有效性；如未来查明请回填本文件。

## 三、裁决方法论（三探针 + 一通道，可复用）

按序部署，每层缩小一半可能：

1. **播放头探针**：imageTimer 每 tick 采样 `mc.currentFrame` → 区分"没在播"与"在播"。本次结论：播放头 2→15→1 正常循环。
2. **显示列表探针**：采样 `mc.numChildren` → 区分"标签未应用"与"已应用"。本次结论：添加/移除全部生效（7→8→6→8→7 精确匹配标签序列）。
3. **像素指纹/渲染快照**：`BitmapData.draw(mc)` 进小位图 → 采样哈希；升级版把位图 base64 后**经本地服务端回传**，直接还原游戏内实际渲染画面 → 最终裁决。注意 `reportClientError` 通道有 4000 字符截断（服务端 `sanitizeLogField` + 客户端 `Game.as escapeClientLog` 双层），大体积回传须直连 POST，服务端上限已提至 65536（20260918，见 `更新总结\开发商维护\`）。
4. **二进制手解**：FFDec 不可信时的最终手段——zlib 解 SWF 体，手工遍历 DefineSprite 子标签（tag code/length），逐字节核对 ShowFrame 边界与 PlaceObject2 标志位。

探针代码要点（临时插桩，随诊断结束还原；需要时按此重写）：
- `BitmapData.draw(mc, matrix0.4)` 进 64x32 位图 → `getPixels()` → 采样哈希或 base64；
- base64 手写编码器（AS3 无内置），`URLRequest POST api/client-log`，JSON 字段与 `Game.reportClientError` 相同；
- d10 特效层单独机位：`mc.getChildAt(mc.numChildren - 1)`（最高深度=最后子对象）。

## 四、标准写法（红线，逐帧动画必读）

1. **禁止同深度替换**。每一帧的"换图"= 上一帧角色 `RemoveObject2` + 本帧角色 `PlaceObject2`（**RO 在前、放置在后，同一帧内完成**）。添加/移除语义已被运行时数据与用户观察双重证明可靠。
2. 逐帧链示例（四帧特效 @d10，帧 2/5/8/11 起、每帧 3 tick）：
   `f2 Place特效1 → f5 RO d10 + Place特效2 → f8 RO d10 + Place特效3 → f11 RO d10 + Place特效4 → f14 RO d10`
3. **位移/滑动用 MOVE 标签**（placeFlagMove=1、无 characterId、仅矩阵）——重定位语义，不涉及替换。
4. **删除冗余重放批次**：待机帧的"原样重放"（同角色同矩阵）是 no-op，直接删。
5. **验证清单**（缺一不可）：F2 慢速逐帧肉眼确认每帧形态不同；游戏内渲染快照差分确认像素逐帧变化；`numChildren`/播放头探针确认标签应用正常。
6. 多帧美术素材（如三帧火焰）帧间差异可能较小，**必须**用逐帧差分或快照对比确认轮播，不能凭肉眼 GIF 判断（GIF 去重编码会骗人）。

## 五、修复实例（星际雷神 V27~V29，20260918）

- V27：蓄力特效节奏拉开（每帧 3 tick，f2/f5/f8/f11 起各 3 帧）。
- V28：删除 sprite 内复制残留的 SoundStreamHead2×2（流同步嫌疑排除项，保留清理成果）。
- **V29（本修复）**：两级（MK1/MK2）时间轴零替换改写——焰2/焰3、特效2/3/4 全部改为 RO+add，装填滑动改 MOVE，删 f15/f16 冗余批次；火焰三帧、蓄力四帧、装填滑动同时复活。
- 修复后 fx 机位证据：`证据-修复后fx机位四帧轮播-20260918.png`（f3 暗球 → f6 亮核横线 → f9 红花 → f12 渐隐）。
