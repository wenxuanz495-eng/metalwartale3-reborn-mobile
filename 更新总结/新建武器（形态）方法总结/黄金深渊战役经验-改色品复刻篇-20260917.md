# 黄金深渊战役经验·改色品复刻篇 - 20260917

> 来源：黄金深渊（cutter_gold）20260917 五级形态战役（4 个提交，任务台账见 `..\武器家族内容\副武器家族\高周波切割炮家族\番外-黄金深渊\黄金深渊五级形态导入执行总结-20260917.md`，全程总账见同文件夹《黄金深渊五级战役任务流程总结-20260917.md》）。
> 定位：与《黄金飞刃炮战役经验-特效挂点调优篇》（E1~E10，导入后调优期）互补——本篇沉淀**"改色品复刻"型新建任务**（画师按原件画布重绘＋时间轴逐标签镜像本家）的导入期经验，以及本战役唯一重大事故（R9 矩阵口径）的完整教训。每条有本战役实证背书。

## G1 改色品的第一原则：逐标签镜像本家同级，而不是重新设计（零调优的根据）

黄金深渊五级导入**全程零次对位调优**（对照：黄金飞刃炮同类任务打了 22 个提交的挂点调优仗）。差异只在方法论——本战役把"改色品"落到结构层：

- 时间轴＝本家同级精灵的**深拷贝**，仅替换本体/特效件引用（锚点矩阵、RemoveObject 时机、StartSound、帧数逐标签原样，含 lv1 f8"本体 RO→件7 合成帧接管→f9 回归"这类隐蔽语义）；
- 特效件＝本家同级件的**同画布替换**（画师按交接说明的原件画布重绘）；
- 挂点/特效坐标照抄本家（用户口径），不做任何"按新枪体重锚"。

**口径**：动手前先问"这是新形还是改色"——改色品的模板就是本家同级时间轴本身，任何重新设计都是引入偏差的来源。

## G2 画布同位检验：IoU 比对必须"裁剪内容"与"画布内位置"分开做

素材验收用了两层互不替代的比对：

1. **内容裁剪比对**（内容 bbox 裁剪后 IoU＋最佳位移）——判定"画的是不是同一个东西"；
2. **画布内位置比对**（内容 bbox 左上角在各自画布中的 tl 偏差）——判定"能不能零位移替换"。

两层全过才是"纯改色"（本战役 52/57 件全过）；任一层不过即产生补偿项（本战役 3 件：件7 双填充合成、件11 fill＋1px、lv1 本体几何平移 −4,−2px）。只做第 1 层会漏掉"内容相同但画内挪位"的件——落地即偏。

## G3 画师交付的解读必须落到填充结构，不能只看张数

件数对得上≠结构对得上。本战役 13 件黑绳链中，件7 实为**双填充合成形状**（底层白热枪体＋顶层月牙球），画师交付的只是顶层重绘稿——直接单填充导入会在 f8 丢失枪体层。判定方法：对原链逐件查 fillStyles 数量与位图引用，双填充件的"缺层"要还原成合成结构（克隆原形状→底层换金体位图＋内容对位平移→顶层换画师稿）。焰切七件的"双位图"同理——但画师交付的是渲染合成稿，故反向简化为单填充。

## G4 枪体画布不一致时，用内容 bbox 对位换算几何，禁止目测

画师黑绳/叫唤枪体画布大于本家原件（51×29 vs 43×25/49×29，留白加大）。换算公式：**新矩形原点＝原矩形原点＋(原件内容 tl − 画师件内容 tl)×20**（twips/px）。lv1 补偿 (−4,−2)px 即由此算出，落地后枪身像素与本家完全重合（75 帧渲染内容框 ±0~2px 全对齐背书）。

## G5 R9 矩阵口径事故：FFDec 渲染器会"将错就错"，二进制解码才是矩阵验证的唯一可信手段（本战役最大事故）

- **事故**：五颗子弹以 9.23×（lv4 20×）巨型上台，实机满屏金月牙。
- **根因**：PlaceObject 放置矩阵 scaleX/scaleY=**原始因子**（1.0=1.0），位图填充 bitmapMatrix 的 20.0=1.0（20 twips/px）——两口径混用，按 20× 写入 9.2308。
- **抽检为何失效**：FFDec 渲染器与 XML 导出同口径（把 9.2308 再 /20 解释），渲染图看起来完全正常——**渲染验证对矩阵口径错误系统性失明**。
- **破案手段**：手工解码 SWF 二进制的 PlaceObject 矩阵比特（NScaleBits=21，原始值≈605032=9.2308×65536），与 XML 值互证。
- **口径**：凡手写矩阵，验证顺序必须是"二进制解码 ＞ 1:1 实测尺寸 ＞ FFDec 渲染"；渲染通过不构成矩阵正确性证据。已沉淀为方法总结红线 R9。

## G6 子弹缩放的"倍率"必须指明基准：可见内容，不是画布

用户口径"参照本家子弹大小倍率"的落地基准＝**alpha≥10 可见内容尺寸比**（本家同级内容 / 黄金弹内容 77×50），而非画布比（画布含透明留白与光晕，比例失真）。实测黄金弹内容≈本家 lv4 弹（实心 1883 vs 1873 px），故各级倍率即本家 lv4→lvN 的自身倍率。透明光晕占比不同的两套美术，画布比会系统性偏差。

## G7 遗留系统兼容盘点：改 id 语义前先全域 grep

单级武器五级化不是纯增量——旧 id 在代码层有兼容设施，动语义前必须全域盘点（本战役 `cutter_gold` 命中 7 个 .as 文件）：

- 发放侧：DropBox×3 掉落表、WeekExtraDefine 周常池早已按 `cutter_gold_lv1` 书写；GameData 有 cutter_gold→cutter_gold_lv1 旧存档迁移；
- 展示侧：`getBuySite()` 活动特判含 cutter_gold 子句→升级界面显示"通过活动获得"（实机反馈后移除该子句）；
- 兜底侧：ItemsController.isGoldenAbyssReward 的 id/名称双重识别（保留作重复转化判定）。

**口径**：导出名/等级语义变更＝先 grep 全部引用点，逐个判定"保留（兼容层）/修改（过时判定）"，漏一个就是实机意外。

## G8 成长型数值照搬的"近亲先例"选择：升级路径同构者优先

数值口径"照抄本家"遇到成长型专属字段（升级条件/材料/price）时会出现无本家先例的空洞——此时选**升级路径同构的近亲**（恶魔牙：同为成长型、mustLevel 全 1、四材料组＋price 空）整组照搬，而不是拿非成长型的本家字段硬凑（Y_num 单材料组实机无法升级的教训）。先例选择标准：升级/获得路径的同构度，不是武器外观的相似度。

## G9 画师交接文档的闭环价值：当初写清画布规格，交付就能逐像素对上

本战役 55/57 件 IoU=1.000 的前提，是 09-12 交接说明把"每件特效的画布尺寸/递进关系/透明 PNG/同尺寸交付"写到了位——画师完全按规格重绘。对比：规格不明的交付（如黄金飞刃炮挂点弹）引发两轮返工加溯源立项。**交接说明里的画布尺寸表不是参考资料，是验收标准的合同**；写作时的十分钟省掉验收时的一整天。
