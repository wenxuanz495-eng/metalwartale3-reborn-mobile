# 感应炮"激光探伤 / 金属撕裂 / 集群爆炸"平衡系统（雏形方案，暂缓实施）

整理日期：2026-09-06
状态：**雏形 / 暂缓**——用户明确"太复杂了，目前不做，后续优化时再做"；当前优先实施《感应炮追踪目标优先级改进》锁敌优化（见同目录潜在项目 MD），实施后再详细讨论**简化计算**版本。
性质：**完全自定义的新系统**，偏离 2.5 原版最远，需独立平衡验证。
前置依赖：逻辑1 锁敌优化（目标优先级 + 死亡转火）先行落地——本系统的索敌改进收益（省过杀、精准转火）与集群爆炸（0.5 秒齐射触发）都建立在它之上。

## 一、设计背景与设定

- **平衡动机**：锁敌优化（智能索敌 + 堆积弹齐射）会显著提高实际命中质量（省掉过杀浪费、永远打优先目标），因此感应炮基础伤害需要下调作为平衡代价。
- **设定**：感应炮炮弹是智能炮弹；激光负责**引导/探伤**（帮助炮弹识别机器人金属的裂痕处）；炮弹打在激光探伤标出的薄弱部位会造成**金属撕裂**（结构性损伤，永久）。
- **受益方划分**：激光探伤 debuff **只对感应炮炮弹有用**（感应炮专属增益）；金属撕裂 debuff **对所有武器有用**（怪物整体防御下降，全队受益）。

## 二、核心数值：基准 80% + 削弱后基数（推荐定稿方向）

- **基准下调**：感应炮（爆能弹 + 激光段）伤害从 100% DPS 基准 → **80%**。
- **基数规则（推荐采纳）**：**削弱后基数**——每个增益按"当前累计值"的百分比叠加（数学上等价于连乘）。用户原话的算法（80+10=90）实为"当前值+原基准的10%"，与连乘在第一层数值相同（80×1.1=88），后续层每层按当前值重算。
- **选择理由**：用户平衡目标为"**堆叠 buff 后的子弹伤害只能略高于原本（100%）**"。削弱后基数下，探伤1层 → 撕裂 → 探伤2层 三步叠完约 **101%～105%**，精确命中目标；削弱前基数（百分点直接加）满叠 125%+，超标。用户也已认可削弱后基数"更方便计算"，接受"为平衡需叠更多层（约 3 层）"。

### 推荐数值链（削弱后基数）

```text
基础                 80%
探伤 1 层（激光施加）  ×1.10 → 88%      （仅感应炮炮弹）
撕裂触发（炮弹概率）   全队武器对该怪伤害 ×1.10 → 96.8%
                     炮弹专属再 ×1.05 → 101.6%
探伤 2 层（撕裂状态下激光才可叠）
                     普通武器对该怪 ×1.10 → 111.8%
                     感应炮对该怪 ×1.15（推荐档）→ 116.9%（×1.20 → 121.9%）
集群爆炸（0.5s 窗口）  ×1.05/层，最高 4 层（×1.20）→ 爆发窗口 140%~146%
```

不含集群的常态满叠 ≈ 105%~117%，符合"略高于原本+有感提升"；集群爆炸定位为**堆积弹齐射的爆发窗口奖励**（0.5 秒内密集命中才触发），不计入常态 DPS 预期。

## 三、两个 debuff 的规格

### 3.1 激光探伤（激光施加，感应炮专属增益）

| 项 | 内容 |
|---|---|
| 施加 | 激光段命中怪物时施加（感应炮每攻击周期首发的瞬时射线） |
| 持续 | **5 秒**，激光周期照射可无缝续 |
| 叠层 | 常态 1 层；**金属撕裂状态下可叠 2 层**（第 2 层 = 防御再下降，见 3.2） |
| 效果 | 感应炮炮弹对该怪伤害 ×1.10（探伤 1 层） |
| 受益方 | **仅感应炮炮弹**；其他武器不受探伤影响 |

### 3.2 金属撕裂（炮弹触发，全队受益，永久）

| 项 | 内容 |
|---|---|
| 触发 | 感应炮炮弹命中时**低概率**触发（候选 10% 或 5%，**待定，建议 10%**） |
| 维持 | 触发后，后续炮弹命中 **100%** 刷新/维持；**永久**（怪活多久持续多久，设定=结构性损伤） |
| 效果 1 | 该怪受到**所有武器**的伤害 ×1.10（"整体防御下降10%"的最简等价实现，用户已确认此落地方式） |
| 效果 2 | 激光对该怪伤害额外 ×1.10 |
| 效果 3 | 感应炮炮弹对该怪额外 ×1.05 |
| 解锁 | 撕裂存在期间，激光探伤可叠第 2 层（普通武器 ×1.10 / 感应炮 ×1.15~1.20，**档位待定，建议 15%**） |

## 四、集群爆炸（短窗口命中奖励）

| 项 | 内容 |
|---|---|
| 触发 | **0.5 秒内**多枚感应炮炮弹命中**同一**怪物（窗口已定 0.5s） |
| 生效 | 命中数 **> 5** 起，每多 1 发 +5%，**最多 4 层（+20%）**：6 发+5% / 7 发+10% / 8 发+15% / ≥9 发+20% |
| 定位 | 堆积弹齐射（8 秒寿命堆积 → 追踪齐射）的**爆发窗口奖励**，与锁敌优化的"Boss 齐射"玩法联动 |
| 计数实现 | 每怪一个滚动窗口计数器（命中时间戳队列或 0.5s 帧窗口计数） |

## 五、实现锚点（未来实施时）

- **debuff 槽**：挂在敌人 `define` 实例上（每敌人独立 EnemyDefine 实例，lifeBar 先例）；需新增字段：探伤层数 + 探伤到期时间戳、撕裂标志（永久布尔）、集群命中窗口计数。
- **施加点**：激光段——`BodyGroupHit` 的 laser 分支（命中即施加/刷新探伤）；炮弹——`bulletHited`（概率撕裂 + 集群计数）。
- **结算点**：`EventGroup.hurt` 敌人分支，在装甲克制之后、扣血之前插入 debuff 乘区（顺序：基础 → 克制 → 撕裂全队 ×1.10 → 探伤/撕裂感应炮专属区 → 暴击 → 技能减伤 → 集群加成；**最终乘区顺序实施时再定，先跑数值表**）。
- **到期处理**：探伤 5 秒倒计时（`live_t` 或帧计数），过期层数回落；撕裂无到期。
- **范围**：仅感应炮（爆能弹 + 激光段）；其他武器只享受撕裂的全队增伤。

## 六、待定决策点（立项时拍板）

1. 基准 80% 与探伤/撕裂各增益档位是否按第二节数值表执行（含探伤 2 层推荐 15% 档）；
2. 撕裂触发概率 10% / 5%（建议 10%）；
3. "整体防御下降"的展示（怪物名/血条是否加状态图标——当前 UI 无 debuff 图标系统，可纯数值实现）；
4. 集群爆炸计数是否包含激光段命中（建议只计炮弹，避免激光瞬发干扰窗口统计）；
