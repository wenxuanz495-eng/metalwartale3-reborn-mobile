# BGM 曲库二级扫描补齐与装包路径修复 · 总结

> 记录日期：2026-09-19
> 分类：底层系统维护（服务端 / 构建构装链），非游戏内容改动

## 一、目标

修复 2026-09-15 工作区七分类整理（歌单移入 `相关素材\` 二级目录）后的遗留：全库共三处 `.playlist-root` 曲库发现逻辑，当日只升级了根目录《【开发者工具】打开BGM曲库源目录.bat》为二级扫描，其余两处（服务端运行时扫描、构建期曲库复制）仍停留在一级扫描，导致曲库发现静默失效。同步处理装包脚本的静音版模板冷备指路与 `构建.bat` 过时提示语。

## 二、实际修改

1. `server\bgm_player.go` — `scanRecommendedCatalog()`：一级扫描未命中时，对每个一级子目录再下扫一层寻找 `.playlist-root`（现标记位于 `相关素材\歌单\.playlist-root`），找到即选中；一级优先级保持不变。
2. `scripts\prepare_build_runtime.bat` — `RECOMMENDED_BGM_SOURCE` 发现同步升级二级扫描（`if not defined` 保证一级优先、首个命中生效）；后续 robocopy 复制逻辑不变（`*.mp3 *.flac *.wav *.json` → `build\bgm\recommended\`）。
3. `scripts\build_player_packages.bat` — `:missing_silent` 报错补充冷备位置与恢复说明（`F:\超合金冷数据备份\2.0版本归档\静音版本归档\静音版` → 临时拷回 `D:\superalloy\静音版`，封装后可删）。`SILENT_SOURCE` 路径本身不动，遵循"冷备仅在封装窗口临时回 D 盘"的使用方式。
4. `构建.bat` — 末尾提示语 `启动游戏.bat` → `启动游戏-flashplayer_sa.bat`（跟随 2026-09-15 根目录整理后的现行入口名）。

三个 BAT 均保持 CRLF；`scripts\build_player_packages.bat` 含中文路径属既有状态（UTF-8 + chcp 65001）。

## 三、构建与验证

- `go build` / `go vet` / `go test ./...` 全部通过（flashoffline 包，含 bgm_command_test 等既有测试）；
- `构建.bat` 全量构建退出码 0（期间一次 `server.exe` 残留进程锁文件导致 code 4，taskkill 后重跑通过——与本轮多个提交记录过的现象一致）；
- **game.swf SHA-256 = `3C96640B…1614B1` 与当前记录值精确复现**（本修复不触碰游戏内容，可复现构建零漂移）；
- **修复生效实证**：`build\bgm\recommended\` 修复前仅剩空目录，构建后填充 `曲库\`（含 `developer-playlists.json`）＋ 49 个音频文件；
- `scripts\launch_game.bat --check sa` / `--check sa_debug` 双自检退出码均 0。
