> **定位**：给每个对外版本打一条"版本标签"，一条版本一行，串起 **版本号 → 日期 → 类型 → GitHub tag/Release → 封装包（三件套位置 + SHA-256）→ 关联更新总结文档**。

> **包体落点**：热层 = `D:\superalloy\临时封装目录\端游端\<大版本>\`（封装输出层，成品归档后清空）；冷备 = `F:\超合金冷数据备份\端游端\{1.0,2.0,3.0}\`。

## 三、字段口径与红线

1. **哈希口径**：取封装目录内 `.sha256.txt`（certutil 格式）的 SHA-256 前 16 位；完整值见冷备 `F:\超合金冷数据备份\端游端\3.0\<版本>\*.sha256.txt`，GitHub Release 说明中同步维护完整值。
2. **GitHub 附件命名**：附件名不支持中文，Release 用英文名（`3.0-Alpha-full.7z` / `3.0-Alpha-mini.7z`…），本地中文版本名与英文附件名以 **SHA-256 一一对应**。
3. **迷你包口径**：永远不含开发者推荐曲库（`build\bgm\recommended`），保留原版默认 BGM 与外置播放器；完整包与迷你包的 `game.swf` 哈希一致。
4. **公告口径**：`runtime\游戏更新公告.txt` 只保留现行周期栏目，**顺序为"小版本在前、大版本在后"**（2026-09-21 用户裁定：玩家先看到最新小版本改了什么，大版本内容最后列出）；现行顺序：**3.0.4 → 3.0.3 → 3.0.1 → 3.0"抢劫版"Alpha（大版本）**；历史版本公告不驻留；版权/群号两行只保留文末一处；致谢单列 `runtime\感谢公告.txt`，**致谢名单只许追加、严禁删减**。
5. **发布流程**：先改公告 → 封装（`scripts\build_player_packages.bat <完整版本名>`）→ 上传 Release（英文名 + `--clobber`）→ Release 说明更新 SHA-256；装包产物经 `PKG_OUT_DIR` 重定向落 `临时封装目录\端游端\<大版本>\`，归档后冷备到 `端游端\`。
6. **归档联动**：新增版本行后，同步更新本文件所在目录的 `README.md`（索引），并确保该版本在 `版本更新总结\` 下有**版本夹**（导航索引：版本标签 / git tag / 包哈希 / 关联总结 / 备注），以及该版本的总结文档已归入对应分类目录。
